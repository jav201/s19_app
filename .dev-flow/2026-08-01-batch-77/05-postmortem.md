**④ Three requirements were amended because the requirement was FALSE, not because the wording was loose.**

- **Amendment D (`HLR-111` Statement + `LLR-111.7`) — the strictness clause was unsatisfiable by any allocator.** Two runs of different but similar mapped size legitimately round to the same integer column count; a size difference smaller than one column's worth of bytes cannot be represented in integer columns. The derived precondition is `surplus × (max_bytes − min_bytes) > total_bytes`. ⚠️ **The `≥` form has counterexamples at ratio exactly 1.0 that random sampling cannot find** — 285 of them under exhaustive enumeration (`runs=[1,4,4], n_gaps=0, bar=6 → widths=[2,2,2]`), a measure-zero boundary a 140 808-case random sweep never hit. **The threshold must be strict, and only exhaustive enumeration can establish that.** Consolidated: 859 276 cases, 0 counterexamples (independently re-run at 6.5 M). `_allocate_band_widths` was **not** modified — chasing an unsatisfiable clause in the allocator would have been chasing a target that cannot be hit.

### Process / workflow findings

**① A monitor does not outlive the task that armed it. Three agents hit this.**
The OS process survives and completes; nothing remains to observe it. Only two mechanisms work: **block in the foreground**, or **hand the run to the orchestrator**. C-25 exists for exactly this and **was violated once by the orchestrator itself** — the Inc-2 implementer reported *"clean full suite is running in the background … I'll report when it lands"* and ended its turn; that run never survived and could never have reported, and the orchestrator relayed the claim onward as though it were in flight. Caught only because the operator asked *"working or stuck"* — a liveness question there was no signal for. **A report that work is in flight is exactly as unverified as any other plausible claim.** → *suggested change: C-25 gains an explicit clause that a delegated background run is not a run; the gate figure must come from a foreground-blocked or orchestrator-owned invocation.*

**② A single green run on a timing-sensitive suite is weak evidence.**
`test_tc041_6` and `test_tc062_1` (both batch-45) reported clean at Inc-7 and Inc-8, on a tree byte-identical to the one that later failed **3 of 4 runs**. Measured, not argued: 0 of 4 failed at `f8747b8`; 3 of 4 failed on this branch. Latent since batch-45 — the tests post an `OpenInHexRequested` and return immediately, leaving the message in flight; teardown dispatches it into a screen that is already gone. batch-77's per-render deferred work lengthened the message queue enough to convert a dormant fault into a live one, **so the batch fixed it**. Neither Inc-7's nor Inc-8's report was dishonest; **the evidence standard was.** Verified by 4 consecutive clean runs against an experiment that failed 3 of 4. → *suggested change: for timing-sensitive nodes, the gate figure is N consecutive runs, not one.*

**③ Source-reading tests are corrupted by concurrent edits, and the corruption is indistinguishable from a real failure.**
Two Inc-4 full-suite failures (`test_tc078_4`, `test_tc080_5`) were artifacts of docstring edits landing **while the run was in flight**: `inspect.getsource` on an already-imported module returns the **wrong region** after a line-number shift, so the AST walk finds zero calls. Demonstrated rather than asserted — `BEFORE ok=True, calls=['SENTINEL_CALL']` → `AFTER ok=False, calls=[]`. **The agent invalidated its own run and discarded it rather than reconciling to it**, which is the correct behaviour. → *standing rule: never edit a file while a suite that reads its source is running.* Affected nodes in this repo include `test_tc031`, `test_tc032`, `tc_042` and the re-scoped `TC-519`.

**④ Probe defects were self-caught repeatedly. Counted honestly: eleven.**
`F-1(a)` cp1252 `UnicodeEncodeError` · `(b)` temp-cleanup `PermissionError` · `(c)` an unsettled 23/50 geometry read reported as fact · `(d)` `address_in_sorted_ranges` arg order inverted · `(e)` a `pilot.click` that did not land, making the R-6 arms RED for the wrong reason · **`(f)` the C-13 starvation detector compared the glance box's TITLE (11 cols) against candidates instead of its widest CONTENT row (29), reporting "STARVED: none" for every candidate — the exact starvation it existed to detect, committed inside the detector** · `(g)` a runs-vs-ranges fixture seeding `random.Random(3)` **per byte**, making the "random" half constant and briefly appearing to refute the finding · **`(h)` a liveness signal measuring unrelated processes** — the `python.exe` count was `taskboard.exe`, `desk.exe` and five `python -m http.server` instances; there was never a `pytest` process in any of the six samples, and the 8↔10 drift was narrated as *"a test run starting."* · `(i)` a cross-producer epoch mismatch — Git Bash `stat -c %Y` against PowerShell `Get-Date -UFormat %s`, giving `mtime_age = −352 min`, one step from a fabricated alarm (**C-42 in its purest form**) · `(j)` the first monitor watched the **deliverable file**, written once at the end — a completion detector wearing a liveness detector's label · **`(k)` a shell-quoting false positive on a byte count, on the batch's most sensitive artifact.**

  **`(k)` in full, because it is the closest this batch came to a fabricated integrity finding.** Inc-3's first CR check on the byte-exact golden — `git show :$P | grep -c $'\r'` — printed **4**, one per line. **Mechanism:** `$'\r'` did not expand to a carriage return in that shell context, so `grep -c` counted lines matching a **literal string** rather than lines containing CR — one hit per line, which is why the number looked like a plausible per-line corruption count. The implementer **did not report it**, re-ran the check authoritatively in Python, and measured the true CR count as **0** in both the worktree and the stored blob. Had `4` been reported, it would have been a fabricated integrity finding against a **byte-exact golden** — the one artifact in this batch whose whole value is that its bytes are trustworthy. **Caught by re-running the check in a different tool, not by re-reading it** — which is the transferable part: a quoting defect is invisible to inspection of the command that contains it, because the command reads correct.
