## 🔺 MAJOR / HIGH — `report_service` producer bounding + report integrity

  - **▸ (MAJOR/HIGH, new — batch-63 D1, RETURNED at the Phase-2 re-gate) `_addendum_lines` is a memory-exhaustion path, and no output cap can reach it.** `report_service.py:1467` builds `hits: List[str] = []` (`:1513`) and appends one **fully formatted string per (region × variant × entry)** at `:1518`/`:1524`/`:1532`, extending only at `:1537` — so the whole cost is paid **before any output exists** and every byte-budget or row-cap design is structurally blind to it. **Measured** (bounded grid, ≤200 000 hits; the declared-domain fixture was never built because building it is what exhausts host RAM): one line per (R × V × E), **87–94 B resident per hit**, product law confirmed independently on all three axes (×2.00/×1.98 per doubling). This is the most likely cause of the host RAM exhaustion that killed the operator's machine mid-batch. **Two HIGH findings that must be designed for, not discovered again:** (a) a per-**region** cap re-introduces **attacker-selectable truncation, class-selectively** — the producer order emits modification hits (100 % attacker-supplied via the change file) before validation-issue hits, so 200 crafted entries evict **0 of 5** validation issues; measured. A per-**hit-class** cap fixes the cross-class case (**5/5** survive) but **not** intra-class or cross-variant eviction: 200 attacker-authored `CHG-ADDRESS-SYNTAX` warnings still evict the ERROR-severity `CHG-COLLISION` (0/1), and one flooded variant suppresses two other variants' collisions (0/2). **All three hit classes are document-derived** (`ChangeSummary.issues` and `CheckRunResult.issues` are both `list(document.issues)` — `changes/apply.py:363`, `changes/check.py:399`), so the attacker controls every class's cardinality. The real control is the **notice naming the cut classes**, not a predicate asserting each class is merely represented. (b) **bounding output does not bound traversal** — a cap-and-continue implementation is indistinguishable from cap-and-break by peak memory (identical 19019/19019, ratio 1.00) or wall time (1.00 vs 1.04); the only falsifiable form is an **injected counting iterable** (measured: 201 consumed vs 2000). **Named residual (arch B-3(b), carried explicitly rather than left inside a pointer):** even a capped producer still traverses `O(V×E)` for a region with FEW or ZERO matches, because a cap can only fire after `CAP` *matches* have been found — so a low-match region pays full traversal. Closing that needs membership to be decided without walking every entry, i.e. `s19_app/range_index.py`'s binary-search primitives (`build_sorted_range_index` / `address_in_sorted_ranges`), which is the module the codebase already designates for "many addresses against many ranges" and which `_addendum_lines` does not use today. **All `report_service.py` line numbers in this bullet are as of `031ca8d`**; batch-63 added +47 lines to that module (49 insertions, 2 deletions), so re-derive them.
