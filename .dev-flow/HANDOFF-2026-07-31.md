# PLAN — batch-73 · `_first_intersecting_symbol` soundness

**Flow:** `/fast-dev-flow` · **Lane:** A · **Est.** 2 increments, ≤3 files

## 1. The defect

`_first_intersecting_symbol` resolves an address to a linkage **symbol name** using a one-candidate
bisect. Over **overlapping** ranges it can miss an enclosing range that starts earlier, returning
"no linkage" — or the wrong symbol — for an address that plainly sits inside a named region.
**The linkage is displayed to the operator**, which is why this is MAJOR rather than cosmetic.

**`[EXECUTED 6524afd]` — the backlog's counterexample reproduces exactly.**
Ranges `[(4096, 36864, 'BIG_ARRAY'), (8192, 8208, 'INNER')]`, address `0x5000` (20480):

```
starts = [4096, 8192]; ends = [36864, 8208]
bisect_right(starts, 20480) - 1 = 1        -> candidate = INNER
ends[1] = 8208 > 20480 ?  NO
successor = 2                              -> out of range
=> returns (False, None).   Ground truth: BIG_ARRAY  (4096 <= 20480 < 36864)
```

## 2. Two premise corrections the backlog gets wrong — do not inherit its wording

- **`[EXECUTED 6524afd]` The backlog names the wrong function.** It says *"`_linkage_index` carries its
  OWN copy of the one-candidate bisect shape (`:511-518`)"*. `_linkage_index` (**`apply.py:438` @6524afd**)
  only sorts and builds the index — **it contains no bisect**. The unsound probe is
  **`_first_intersecting_symbol` (`:470` @6524afd)**, bisect at **`:513-518` @6524afd**.
- **`[EXECUTED 6524afd]` The fix the backlog points at LOSES THE SYMBOL.** It cites
  `report_filter.py:737` — `build_sorted_range_index(_merge_ranges(ranges))`. That is correct for
  **membership** and wrong here: `_merge_ranges` coalesces, destroying which symbol owned which span,
  and this probe **returns a name**. The correct in-repo precedent is the *other* one the same bullet
  cites: **batch-65's `_addendum_lines`** — a caller-local `bisect` plus a **prefix-max array**.
  *An implementer who copies the `report_filter` pattern silently breaks attribution.*
- **`[EXECUTED 6524afd]` The limitation is already CONFESSED in the docstring** (`:491-496`):
  *"overlapping declared ranges may resolve to the nearest-start match only — acceptable for an
  informative-only annotation."* So this is a **declared contract the backlog decided is no longer
  adequate**, not an unknown bug. That makes D-1 an operator decision, not an implementer's.

## 3. D-1 — OPERATOR DECISION REQUIRED BEFORE INC-1

| Option | Expected result | Consequences |
|---|---|---|
| **(a) Fix the probe** — prefix-max, correct attribution over overlaps | Displayed linkage stops being silently wrong | ⚠️ Observable behaviour change; may move report goldens containing `Linkage` |
| **(b) Keep the contract, harden the disclosure** | Zero regression risk | ❌ The operator keeps seeing a wrong symbol, now with a note |

**Recommended: (a).** Wrong data presented confidently in an evidentiary document is worse than absent data.
**If the operator picks (b), Inc-1 and Inc-2 below are void** — rewrite the batch as a docstring +
requirement amendment.

## 3. D2 — three traps already paid for by other batches

Do not re-derive these the hard way:

1. **The boundary literal is NOT stable.** `int → str` raises past ~3572 hex digits by default, but the
   threshold moves to **831** under `-X int_max_str_digits=1000`. **An acceptance must derive the width
   from `sys.get_int_max_str_digits()`**, never hard-code 3572.
2. **A bare-hex fallback is forgeable as a decimal numeral.** `int('9'*3572, 16)` renders as `'9'×3572`,
   `.isdigit()` is `True`, understating the true length by ~10^730× *in an evidentiary document*. The
   alternative form needs a `0x` prefix, and the predicate must be `^-?0x[0-9A-F]+$` — because a
   **negative** length is constructible (`ChangeSummaryEntry(0x2000, 0x1000)` → −4096), so a naive
   "starts with `0x`" rewards the malformed `0x-9999…` and false-fails the correct `-0x9999…`.
3. **The two sites take DISJOINT inputs** (`change_summaries[].entries` vs `check_results[].entries`),
   so **a change-only fixture never reaches the second site.** Each AT must bind its site independently.

**Already eliminated by measurement — do not re-argue:** "cap the rendered width" *still raises* (the
int→str conversion precedes the slice), and "render the column in hex" changes **9/9** in-domain
renderings.

**Preserve the fail-closed behaviour.** Today `app.py` catches the `ValueError` and no partial file is
written. The defect is that it surfaces in the **operator-input-rejection** branch, so an internal
failure is presented as though the operator's input were invalid. **Fix the misattribution; keep the
fail-closed guarantee.**
