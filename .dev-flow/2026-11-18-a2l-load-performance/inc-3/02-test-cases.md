## Product-route and oracle rules

- Instantiate the shipping `S19TuiApp` under Textual `run_test()` and drive the existing image load, project load and direct-attach routes. Read visible widgets and installed state after real workers settle; no renderer-only call or direct private-state assignment counts as a full route.
- `F` is a spy on the existing common A2L-dependent-view publication. `OUTCOME` is the existing successful or failed route outcome. `UI` is the Textual app thread. `STATE` includes current artifacts, both generations, enrichment/definition keys, MAC/Issues state, project-file hashes, mounted visible content and active worker identities.
- `OLD` and `NEW` are independent, valid, equal-size fixture pairs with distinct pinned marker names, addresses, formats and image bytes. Expected markers are fixture data, not values read back from the implementation under test. Every case asserts both the required NEW value and the absence of its OLD counterpart.
- `P-PAIR` contains image+MAC+A2L, `P-PAIR-NOMAC` contains image+A2L without MAC, and `P-ONLY` contains A2L only. Same-path cases overwrite bytes at one lexical path, keep a normal changed-write timestamp, perform no clear, and use equal-size OLD/NEW content so a path-only or size-only cache cannot pass.
- Every .039 arm also paints the fixture's current declared-length/format sentinels in Check and Patch and asserts 0 UI enrichment, summary or definition constructions; a snapshot that exists but is not consumed therefore fails rather than passing on presence alone.
- The large timing routes use committed case_06 (`37,742,888` bytes; fixture probe `220,040` tags and `0` parse errors in `evidence-e1/case06-probe.txt`). The probe's count and first/last sentinels are fixture guards, not a measured load-time result.
- Each timing alternative runs 3 serial-timing repetitions in a fresh app on the E1 host and records platform/Python/host load without personal paths. Total duration is measured independently from product-route request before admission/copy to final outcome, parse included: median ≤80 s and every run <100 s (D-14, executed E4 budget). Admission/copy, parse, post-parse preparation and install/publication are reported as separate named phases; A2L-only reports admission without a copy phase. The timer remains a 50 ms UI timer using `timing_bound`, with actual lateness, ≥3 callbacks during a 0.20 s producer-worker gate and zero observations failing. Moving the producer and gate onto UI tests the timer; a separate responsive 105 s worker hold tests total duration even when every tick passes.
- Stale cases construct an independent snapshot with the wrong expected generation and deliver it through the real worker-to-UI completion route; they do not mutate a frozen snapshot. Project-pair cases include MAC so image-then-MAC stage expectations are exercised. A valid positive arm must install before the stale arms are trusted.
- The derived STAGE_RACE inputs are removed as unreachable: `evidence-e3/stage-invariant.txt` proves P5's preflight/reset/L1 calls are one synchronous UI sequence without await/yield, with runtime generation writes confined to UI writers. New live-change arms /9-/10 occur before P5 entry, not between P5 and L1. There is no rollback: every adverse project arm rejects before reset, and introducing a yield into the invariant must return to design rather than claiming rollback coverage.
- All files and environment state are isolated under test temporary directories. No test reads secrets, touches a real clipboard or writes a real project outside its temporary workarea.
