## Oracle and fixture rules

1. The small-fixture semantic oracle is an independent, deliberately exhaustive iteration over explicitly constructed entry tuples in declaration order. It does not call the product index, candidate iterator or overlap predicate. For full case_06, an independent lexical scanner reads the pinned source bytes, skips comments and quoted strings, and records each live MEASUREMENT, CHARACTERISTIC, BLOB, INSTANCE or AXIS_PTS `/begin` declaration by source line, byte offset and cross-kind declaration ordinal; that textual order is the expected order. It never reads the product walk, product `position` or `shared_with`. Final address/length fields are inputs to the ordered-interval reference and retain their own existing regression pins. The reference must first pass hand-computed controls with interleaved kinds, comments, quoted fake declarations, cross-page spans, homonyms, masks and over-cap spans. Both oracles compare exact names, not the implementation's ordering metadata.
2. The disjoint fixtures use non-uniform names and positions so reversal, name-only identity and palindrome-like symmetry cannot hide defects. The 1,000-definition and 4,000-definition populations are generated from a fixed arithmetic rule and their counts are asserted before timing. Each population runs once as 1-byte scalars and once as valid 4-byte VAL_BLKs under the same case id; every threshold and counter applies separately to each parametrization.
3. Candidate checks are counted at the existing final overlap predicate, index constructions at the central index builder, and final definition builds at the existing per-name builder. Actual entries into final-span `materialize` are counted independently with a call tracer or an E2-equivalent seam, including scalar entries that do not invoke the per-name builder. A private generator wrapper around `_occupancy_candidates` appends to `consumed_positions` only when the downstream consumer requests another yield. E2 must keep all five measurements observable at the real integration seam; an instrument that resolves zero targets on a known-present case is a hard failure. Construction and population counts are asserted for every warm-up and every measured run, not inferred from the median.
4. The no-gather/no-sort source arm independently parses the candidate selector and rejects collection as well as sorting of the query-wide alias population. The runtime arm separately asserts exact selected names, consumed-yield counts and materialization counts. Consumption instrumentation alone cannot see an internal gather, so gather-without-sort is explicitly a source-arm RED even when its sort count is 0. This applies to every R-A2L-DEF.159 arm, including the exempt-first arm. The source arm is not a semantic oracle.
5. Timing uses the E1 reference host, warm-up and repetition protocol in `01-requirements.md`. The full-case source-order oracle and all 220,040 expected outcomes are computed once per test invocation before the warm-up and reused; `oracle_seconds` is measured once and `comparison_seconds` is measured per run, both outside the timed region and product limit. A 120 s watchdog on that preparation reports `ORACLE INVALID` on expiry. Product temporal watchdogs are 2× their time bounds and a timeout is RED. Memory uses `tracemalloc`; the separate 96 MiB watchdog applies only to the known-bad allocation mutant and is not a temporal or two-times-memory rule.
6. No test accesses the real clipboard, user secrets or user state. Temporary files stay under pytest's isolated temporary directory or this increment's evidence directory.
