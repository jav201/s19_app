## Product-route and discriminating-oracle rules

- Instantiate the shipping `S19TuiApp` and drive typed-path, Workarea Files, start-up or confirmed-replacement routes through Textual `run_test()`/Pilot. Read visible widget content at the outcome as well as the generation/key/snapshot state being tested. Never substitute a direct call to `_install_attached_a2l`, `_replace_current_a2l` or a renderer for an acceptance route.
- Use small, non-palindromic OLD/NEW A2L fixtures with different names, declared lengths and formats. Pin their expected visible cells independently of the attach snapshot. A same-path replacement must change both content and expected cells so a stale snapshot cannot pass by coincidence.
- Thread spies record the real `enrich_tags_and_render` and bulk `describe_definitions` calls, picker panel calls, common refresh and outcome. They establish count, order and thread only; expected rows, summaries, lengths and formats come from the independent fixture contract.
- A held worker phase uses a `threading.Event` only after proving the phase is off the UI thread. Key latency is measured from scheduled product input to the existing action/focus acknowledgement with `time.monotonic()`. No key task is awaited before releasing its hold. Record host, load and every individual latency; a median cannot hide a slow key. A negative control that moves a held phase onto main runs under an outer timeout, and that timeout is RED rather than an unexecuted arm.
- Build the 1,000,000-byte image through the existing deterministic generator in `tests/conftest.py`, never a new ad-hoc large-file builder.
- The real `case_06` arm starts keys/progress sampling before the direct attach and stops only at the terminal outcome, not when `current_a2l_path` changes. It includes enrichment, both picker describes, installation and common refresh. The existing slow `test_tc_b100_53_case06_a2l_attach...` node was read for census but was not run in E1.
- The common-refresh phase is measured on the real large attach, never by blocking the UI thread in a fixture. The held-phase controls therefore discriminate worker placement without manufacturing a blocked-UI failure on correct code.
- Stale-generation arms alter only the result's recorded generation after the real worker finishes and before its real install callback; the oracle is the complete previous state plus explicit zero-call sets. Preparation-failure arms inject one exception into each real worker preparation stage and assert the existing failure outcome and no partial state.
- Use isolated temporary homes/workareas and test clipboard seams only. No case reads or writes the real clipboard, real home or real recent-files store.
