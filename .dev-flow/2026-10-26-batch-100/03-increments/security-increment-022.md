## Seam rulings — security view

- **SR12b-2.** Guard both calls (SE5-12b-2). The integrator frames this as a race in microseconds. For `validate_project_files` it is not a race: the call reads the open project's folder, which can be gone for any length of time, and the probe shows the app exits. For `stat()` it is a race, but the guard is free. Neither belongs in residual risk when the fix is one `try` each in a function 12b already owns. The two sync helpers have the same root but sit outside 12b's edits, so they go to BACKLOG-CODE.
- **SR12b-6.** **Declared residual risk, no guard.** By reading, the C5 tail after the rollback `try` (`app.py:12064`–`:12133`) is pure arithmetic over paths that are already absolute: `base_dir` defaults to `Path.cwd()`, and `workarea` / `project_dir` derive from it. Its only filesystem call, `project_dir.resolve()`, sits in its own `except (ValueError, OSError)`, and `relative_to` has its `ValueError` arm. No input I found can make it raise. If it ever did, the error would point in the **safe** direction. The outcome is a false `Project NOT saved`, with no session commit, and the failure arm clears `_quit_pending` (`:12160`), so the app stays open. The pasted entries stay in the Patch Editor, the session stays unsaved, and the files on disk are complete. Nothing is lost, and the user can save again. A guard would add a branch no test can reach (Q6's rule against dead branches). Record it in BACKLOG-CODE as residual risk.
