## Checked and fine

- **S11-01 / SR-11-1 (the open project by file identity, the deferred rebind).** G10 decides "open project" with `os.path.samefile(item, current_project_dir)`, with `OSError` read as "not the same" (`:10484`–`:10494`). `_plan_project_save`'s kind uses the same test (`:12026`–`:12037`). The rebind to the on-disk spelling happens after the loop, and only when no folder holds the exact typed name (`:10461`, `:10468`, `:10504`). Typed `strasse` with `strasse` open and a `straße` project present → refused as a disguised clash; the single node passed (probe 3). Typed `straße` → `straße`, merge. A casefold twin that is a junction is skipped in the clash loop, but if it is typed exactly, `exact_folder` keeps the typed name and G13 refuses it as `link or junction`. An exact-named plain folder that holds no project is painted `new project in an existing folder` through the link-safe `_folder_holds_project`. On a case-sensitive directory, the exact folder wins over the open project's case variant, which is correct. No other casefold decision on the Save path chooses the target.
- **Links, junctions and reparse points.** Target: `_project_folder_refusal` checks with `lstat` (link → refused, any other `OSError` → `unreadable`, fail closed), and its parent must be textually the work area (`:13476`–`:13488`). Save-as source: the same check before the lazy inventory and before the plan (`:10539`–`:10543`, `:10605`). The commit keeps `mkdir(exist_ok=False)` ownership, the guarded placements (`place_into_workarea(..., workarea_root=)`), `_copy_project_subfolders` with `_path_traverses_reparse_point` / `_guarded_destination`, and `_keep_previous_manifest` guarded and claimed with `O_EXCL`. The Q10 document arm hashes only the inventory's listed files, through `_match_identical`, which skips links and non-regular files with `lstat`.
- **Time of check vs time of use (preview → confirm → commit).** `confirm` re-prepares at the Save press and compares the plan and the painted text (`:10968`–`:10981`). A Save before the first refresh passes `painted = None` and can never return go (`:10969`). The router reuses the prepared save only on plan-object identity and the same typed name (`:10322`–`:10329`), and clears the per-open state on every route. The gap to the commit is one `call_next` hop. Disk changes in that gap still meet `mkdir` ownership, `_plan_row_mismatch` (path and reuse) and the rollback. Stale per-open digests of image, MAC and A2L files are safe: a changed source lands at a different name or reuse and `_plan_row_mismatch` aborts. The exception is SE5-11-1, where the stale input is in memory and no check compares it.
- **Lazy-inventory fill (S11-10 / R3-01).** `live = session is self._save_session` is captured before `replace(...)`, and the app attribute is written only when `live` is true (`:10607`–`:10611`). After router step 0 the attribute is `None`, so a direct or non-matching payload cannot leave a session behind.
- **SR-11-3 sentinel key.** `_DOCUMENT_UNREADABLE_KEY` (`Path("<unreadable-change-document>")`) cannot equal a loaded path (`<` and `>` are not allowed in a Windows file name). It is read only through `_digest(path)` lookups and the memo test (`:12067`, `:12143`), never iterated, compared or written to disk, and it lives one dialog open. No concrete failure found.
- **Path length, name length and free space.** G7–G9 run before any read of the target (except SE5-11-2). The free-space check covers `new` targets (`:10653`–`:10667`) and returns `plan=None` (A11-02). Open-project and merge targets have no free-space check; a full disk there is an `OSError` that the commit rolls back. That is the base behaviour.
- **Partial writes and the manifest backup.** The commit body is base code with its four `except` arms. Placed files, created folders, the manifest restore and `kept_copies` are rolled back. The A11-05 row (`a copy is kept as project.json.previous-<UTC>`) is painted from the same `manifest_keep_reason(existing)` that the commit uses (`:10914`–`:10923` vs `:11447`–`:11470`), and a failed copy aborts the save.
- **Names painted from disk.** Every disk-derived name in the where line and the rows goes through `painted_names`: target, row sources and landings, folders, skipped links, active variant, the vanished source, the carried-document line, `_unreadable_text`, the missing source, the disguised clash, the device name. Constant texts: `validate_project_files` errors, kind words, actions, the blocked-entries refusal (addresses only). The dialog paints with `Static(..., markup=False)` and `Text(...)` (`screens.py` `_paint`, compose), assignment labels with `Text(name)`, and the router's `notify` with `markup=False`. `painted_names` strips Cc / Zl / Zp, so a where line cannot be split.
- **Emitted record.** `emitted_record` is computed once per open from the base file (`_derived_record`, `:13946`). It is used only for the emitted row's `derived_from`, and is not painted. Its staleness is part of SE5-11-1.
- **Worker vs main thread.** Preview, confirm and commit all run on the main thread (timer, key handler, dismiss callback). The commit is synchronous, so no write runs at the same time as a preview. The only cross-thread effect is the load worker's main-thread install described in SE5-11-1.
- **Data flow and secrets.** Nothing leaves the local system. There are no credentials, tokens or keys in the slice, and none appear in this report.
