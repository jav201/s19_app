- **Progress labels and the one scrub.** `begin_busy` has one caller, `_busy_begin_action` (`:20089`), which makes the one `painted_names` call (`:20085`). `str.format` never re-reads a `{…}` that sits inside the value: the probe's name `…{name}{0}` paints literally (`label_line`). `_busy_fail`'s `<label> failed` reuses the scrubbed label, and the step names are constants. `_paint_status_text` (`:19908`) and `end_busy`'s outcome (`:20020`) apply `safe_text(...).plain`. The exception is SE5-12a-1.
- **Other outcome texts.** The before/after refusal diagnostics, the diff-report texts (the new status-log line from the E2 ruling), `Cannot load file: {exc}` / `Cannot load A2L: {exc}`, and every Save abort line now pass through `end_busy`'s scrub. On base they were raw `set_status` calls, so this is a net improvement. `Load failed: {exc}` (`:17736`, base) stays raw. An `OSError`'s `str()` shows the file name with `%r` (escaped), and `S19File` collects record errors instead of raising them: arm A of the probe, with a file whose content holds ESC, produced no control character in any log line. I found no reachable control-byte path through that line.
- **Cross-thread writes.** Each of the 4 workers touches the UI only through `call_from_thread`: `step_busy`, `end_busy`, `_busy_fail`, `_apply_prepared_load`, `_sync_loaded_file_to_project`, `_finish_generate_report`, `_handle_load_error`, `panel.set_status`. `_log_report_event` runs off-thread but writes only to the logger. The guard is `except BaseException: post _busy_fail; raise`, so a successful run posts nothing extra (S12a-06). After an effective end, `_busy_fail` is a no-op, because it checks the generation before calling `end_busy`. Main-thread actions (`a2l_load`, `project_load`, `save_project`) use `try/finally: _busy_fail`, and `load_from_path` uses `except BaseException` + re-raise, which hands the run to the worker on a normal return.
- **Worker cancellation.** Each `exclusive=True` group serves one key: `load` → `file_load` (the only `group="load"`, `:17608`), `generate_report`, `diff_report`, `before_after_report`. A restart pops and re-inserts the key before the new worker starts, so a cancelled worker that never ran leaves no open run. A replaced worker that keeps running in its thread posts with a stale generation: its outcome is logged (A12a-04) and the indicator ignores it.
- **The timer after unmount (SR-12a-2).** `_busy_tick` returns when `runs` is empty or when `query_one_optional("#status_text")` is `None`. `App.query_one*` searches the default screen (`textual/app.py:941`–`:943`), so a tick under a modal still paints. In `_shutdown`, `_close_all` prunes the screens and clears the stack with no await point before `_close_messages` stops the App's timers, so a tick cannot reach the `ScreenStackError` window. The last end stops the timer and sets it to `None`. Runs and timer stay paired: only `begin_busy` creates the timer, only the last-end arm stops it, and `_busy` is excluded from the session reset. A late worker end during quit can still raise `NoMatches` from `end_busy`'s widget calls. That is the same as base's late `set_progress`, and the quit-after-end check belongs to 12b (A12a-07).
- **Dot/space-ending folders.** `list_projects` skips them on every OS (`:13644`). On POSIX this only narrows the list. On Windows, `os.path.abspath` strips the trailing dot or space of a typed path, so the typed route matches the folder Win32 would open. Stream / 8.3 / `::$INDEX_ALLOCATION` spellings never equal a listed name. On macOS a case- or NFD-variant spelling fails closed (`not a project`), because `normcase` is the identity there.
- **The loadable-suffix predicate.** `refresh_files` keeps `recent_kind(p) is not None`, the expression 9b's dialog uses. It is pure (`PureWindowsPath` suffix, case-folded), and it only hides entries; the rows still paint through `safe_text(painted_names(...))` with the on-disk name in `item.data`. A POSIX name that ends in a backslash can be listed and then refused by the loader's native suffix check as `Unsupported`. That outcome is harmless.
- **OS-refused typed paths.** `_typed_load_route` catches `(OSError, ValueError, RuntimeError)` around its one `resolve_input_path` call (`:14518`) and never narrows the catch. The rest of the classifier uses `os.path.isdir` (which swallows the errors) and `os.lstat` with `FileNotFoundError` / `OSError` arms. Its refusal line paints the typed text through `painted_names` + `safe_text`, so a NUL is removed. The warning log uses `%r`. The use-time calls are SE5-12a-4.
- **The single project-match function.** Both callers (`_handle_load_project` `:13189`, `_typed_load_route` `:14605`) call `_listed_project_name` inside `except OSError` → the `unreadable` sentence. The list is the only gate, and the matched on-disk spelling is the one opened. The exception is SE5-12a-3.
