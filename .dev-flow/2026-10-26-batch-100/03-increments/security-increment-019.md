## Checked and fine

- **No load runs before the question (route census).** Every caller of `load_from_path`, `load_selected_file`, `load_a2l_from_path` and `_handle_load_project` sits inside a `go` passed to `_confirm_then_load`, or inside `_handle_load_project` / `load_from_path` themselves (`app.py:7760`, `:8222`, `:12576`, `:13774`, `:13780`, `:13945`, `:14259`, `:14261`; grep of `s19_app/`, no caller outside `app.py`). The Load dialog's `project` / `workarea` / `path` / `recent` kinds, the Workarea list, `v` and the Load-result panel's `v` all reach the seam. Unload (`U`, `[u]`) is out of scope by ruling Q7.
- **Type-ahead.** A request followed at once by `enter`, with no pause, cancels: the stack is `['Screen']`, `fw.s19` stays and D stays true (probe (a)). `y`, `y` gives exactly one load, and the second `y` reaches the main screen, which binds no `y` (probe (c)).
- **Stacked questions.** Two requests made before any answer stack two questions (probe (b), by direct calls). `y` on the top one loads `other.s19`. The lower question then still names the old patch, though nothing is unsaved any more: stale text, but harmless. `n` keeps `other.s19`, and `y` would load over a clean image. No order loses work without a `y`.
- **Double answer.** `_close` checks `_dismissed` on its first line (`screens.py:1382-1386`), and `dismiss` calls `answer` once, so `go` runs once. The test `a_second_answer_is_ignored` passes.
- **Priority keys.** `check_action` makes `load_file`, `save_project`, `focus_palette` and `cycle_density` inert while a `ConfirmQuestionScreen` is anywhere on the stack (`app.py:8672-8675`). These are the app's only `priority=True` bindings (`:2167-2170`). LoadDialog's `alt+l` applies only on that dialog. Non-priority app keys (`l`, `p`, …) do not walk past the modal. Textual's `ctrl+p` opens its palette over the question (probe (d)), but its only commands are `Theme`, `Quit`, `Keys`, `Maximize` and `Screenshot`, and none loads. Quit belongs to Inc 12.
- **Patch Editor dropdown (S10-02).** The guard reads `panel.is_dirty` → `LoadGuardScreen` (`app.py:6211-6223`). Cancel keeps the entries and sets the `Select` to `NULL`. The select is built with `allow_blank=True` (`screens_directionb.py:5181`), so this cannot raise, and the panel ignores a `NULL` change (`:5951`). `_patch_editor_load` has exactly 3 callers: the clean branch of the button, the clean or accepted dropdown pick, and the guard's accept arm. `load_doc` is posted only from the clean branch of the button (`screens_directionb.py:5795-5798`). The test passes.
- **Reads before the reset (S10-01, S10-05).** `build_variant_set`, `read_project_manifest`, `check_project_files` (so `problems` exists before the A2L arm appends to it), `recorded`, the A2L read with its unreadable arm, and `choose_install_set` with the all-`None` refusal now run before `_reset_project_session()` (`app.py:12475-12522`). The tests `refused_project_after_yes` and `unreadable_a2l_project_after_yes` pass: the session, the entries, W and D are kept, with 0 resets.
- **Refusals after `y` on the image routes keep the work.** In `load_from_path`, not found, unsupported type and containment all return before `current_file` changes, and `_pending_variant_id` is cleared. In `load_selected_file` a parse failure returns, and `_handle_load_error` returns before install. `load_a2l_from_path` never replaces `current_file`.
