## Checked and fine

- **Label scrub.** `_busy_begin_action` is the one formatter. `painted_names` removes Cc (ESC included), Cf, Zl and Zp, and clips to 120 characters (`project_gather_service.py:965`). `row.label.format(name=…)` uses a constant template, so a `{…}` in a file name is not re-interpreted. `_busy_fail`'s `<label> failed` reuses the scrubbed label. `final_line` is `safe_text(...).plain`. `restore` is `str(T.render())`, which is plain text. `#status_text` and `#log_line_1..4` are `markup=False` (`inc9b app.py:2857, 2872-2875`), so no markup span is possible. 12b's `busy: <run.label> …` reuses the scrubbed label.
- **Timer lifecycle.**
  - Exactly one timer exists. It is created only when `timer is None` and stopped only in the last-end arm.
  - Only `end_busy` removes runs, and a restart pops and re-inserts, so "runs empty" and "timer stopped" stay paired.
  - `_busy_tick` returns at once when no run exists.
  - `App.query_one` searches the default screen (`textual/app.py:941-943`), so a tick under the Load dialog, the question or the palette cannot raise `NoMatches`.
  - An end from a replaced generation is ignored.
  - Main-thread actions use `try/finally`. `load_from_path` uses `except BaseException` plus re-raise, so a normal return hands the run to the worker.
  - The 3 report kickoffs compute their arguments before the begin (F-10).
  - I found no exit that leaves a run open at 12a; S12a-05 covers the 12b condition.
- **Pick re-check mechanics.** These are fine, apart from where the check sits (S12a-03).
  - `os.lstat` does not follow links. `S_ISREG` is false for a symbolic link (S_IFLNK) and for a junction (directory); probe G3 checked both.
  - Any other `OSError` fails closed, and `FileNotFoundError` stays silent.
  - The cap is read from the module at call time.
  - `name` always comes from row data (on-disk basenames, `inc9b app.py:7599`), never from typed text, so no traversal input reaches it.
  - `_load_dialog_verdict` stays free of filesystem calls.
  - Hard links give an attacker no gain: NTFS needs write-attribute access to the target, and Linux `protected_hardlinks` applies.
- **Windows inputs to the typed route.** `C:\System Volume Information\fw.s19`, a UNC path to a host that does not exist, and a `\\?\` path all return `('refuse', 'not found')` on 9b (`probe_resolve.out.txt`). On this host only NUL and a symlink loop raise, and 9b already catches both.
- **Removing the `os.name` gate (LLR-172.4e).** On Windows the condition was already true, so behaviour there is identical. Win32 strips only trailing dots and spaces, and the skip covers both. On POSIX the change only narrows the list. 8.3 short names and `::$INDEX_ALLOCATION` aliases do not match a listed name in `_listed_project_name`, so the list stays the single gate.
- **Workarea Files filter (LLR-172.4f).** `recent_kind` only hides files: `.json` sidecars, `.txt` and files with no suffix. It shows nothing new; upper-case `.S19` was already listed. The rows still paint through `safe_text(painted_names(...))`, and a pick still passes the on-disk name. A hidden file can still be reached only by typing it, through the typed route's own checks.
- **Labels (LLR-173.2m).** These are text-only changes, with no security effect.
- **Secrets.** No secret value appears in the design or in this report. The probes wrote only under `work/e3-security/`. The symlink-loop fixture was removed afterwards, and no process is left running.
