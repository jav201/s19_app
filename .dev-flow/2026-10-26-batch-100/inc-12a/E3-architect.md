# Inc 12a — E3 PDR, architect review

**Verdict: PASS-WITH-NOTES** — 0 HIGH · 0 MAJOR · 7 MINOR · 2 NIT.

The seam works as designed. A begin always gets an end: each of the 7 actions holds a `finally` (or the kickoff's `except BaseException`), and a second end is a no-op. Generations increase for the whole app, so a stale `step_busy` / `end_busy` can never paint over a newer run. Inc 12b can use the seam with its signatures unchanged. The findings below are text errors that would mislead an implementer (A12a-01 … -03), two gaps in what gets logged and in the busy window, which the seam's own rules cause (A12a-04, -05), one simplification that removes a defect class (A12a-06), and one note for 12b (A12a-07).

## Checked and fine

- **Begin/end pairing, all 7 actions, on `inc10` bodies.**
  - File load: containment end, kickoff `except`, the parse-error and unsupported posts to `_handle_load_error`, the success post, and the worker's `finally`.
  - A2L load: containment end, success end, `finally`.
  - Project load: the all-`None` refusal and success are the only returns after `build_variant_set` (`inc10` :12475-12603); the rest is `finally`.
  - Save project: from the 11 graph — 10 aborts, the tail, `finally`.
  - The three reports: their 3, 2 and 4 exits, plus `finally`.
  - F-10 holds for the before/after and report kickoffs, apart from A12a-08.
  - A cancelled-before-start worker cannot leave a run open: every exclusive replacement starts with a begin of the same key, and app code makes no `cancel_group` / `cancel_all` call on these groups (grep).
- **Stale paint.** Generations increase across the whole app, and `_busy_fail` checks the generation before ending. No stale step or end touches the line, bar or timer.
- **Timer ticks under modals.** `App.query_one` searches the default screen (textual `app.py:941-943`), so `_busy_tick` / `_paint_status_text` find `#status_text` while the Save, Load, question or report screens are open.

The instance-level `set_progress` / `set_status` lambdas stay compatible, because the seam calls `set_progress(v)` with one argument and logs through `self.set_status`.
