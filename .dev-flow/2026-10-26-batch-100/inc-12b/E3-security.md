## Checked and fine

- **Worker reads (LLR-177.1e).** The `self_reads.py` AST over the base helpers the workers reach: `_abort_save` (`current_*`, `_report_filter_path`, `workarea`), `_restore_manifest` / `_keep_previous_manifest` / `_copy_project_subfolders` (`workarea`), `_write_editor_document` (`_change_service`, `base_dir`, `workarea`), `_load_mac_file` (`current_a2l_*`, cache), and the two merges (`current_file`). Every one is parameterised or moved to main in P-1. `_flush_logger`, `_log_loaded_file_summary` and `_unrecorded_document_lines` read only `logger` or nothing. `emit_and_verify` is replaced by direct calls (Q-b2). `SaveImageInput.derived` is a copy (`rederive_for_save` returns `copy`).
- **No concurrent session writer.** `e3-sec-writers.py`: the only methods that assign `current_file`, `current_a2l_*`, `current_project(_dir)` or `_variant_set`, or that mutate the change service, are the install / commit handlers, the reset, `_apply_unload` (behind 2 refused entries), `_activate_project_file` (save-back and file-load sync), and the 6 `service = self._change_service` aliases (all under refused handlers or read-only). Nothing outside `app.py` writes the session (grep). So the file-load worker's off-main reads (P-1 F-6, P-2 D-6) and the cache-pair read cannot tear.
- **The refusal cannot be bypassed into two writers.** The begin and the worker start run in one main callback. Each worker's last post is its end, so no gap exists between a worker finishing and its run ending. Stale ends are no-ops by generation. Q-a1 covers the 4 action starts. The deferred `go_if_idle` (P2-6) covers the palette over the load question. The 4 modal continuations (P2-5) are covered too. `load_selected_file` stays an unguarded product-callable writer with no caller; that is ruled backlog (PR-6) and not re-opened.
- **Failure containment.** Every worker step catches `Exception` and reports. Handler defects stay loud (`exit_on_error=True`, Q-d1). The deferred installs are guarded with `except BaseException` + `_busy_fail` + re-raise, and a callback raise exits the app (P2-c), so no half-installed session survives. Base `app.py` has no `on_unmount` and no `self.exit(` call, so nothing persists session state on exit.
- **Quit.** The exit happens only inside `end_busy` after the hand-back, and the end is each handler's last statement. There is no main-thread wait (no `future.result()` deadlock). `ctrl+q` under the question is ignored. Textual's system "Quit" command calls the bound `self.action_quit`, so the palette reaches the override. `ctrl+c` is `help_quit` and only notifies.
- **Painted labels.** The busy line and the quit body use the label `_busy_begin_action` scrubbed with `painted_names` (Cc / Cf / Zl / Zp removed, clip 120). `str.format` takes the label as an argument, so braces inside it are not re-read. `#status_text` and `#log_line_1..4` are `markup=False` (`app.py:2857`, `:2872-2875`). The project-load and A2L failure lines go through `safe_text` / `end_busy`.
- **a2l.py progress.** The callback runs inside a `try` whose handlers catch only `FileNotFoundError` / `OSError`, so a `RuntimeError` from the forwarder propagates and cannot become a "File not found." soft result. Rates: at most one forwarder call per 4 096 lines, and at most about 101 cross-thread posts per step, plus posts at or past the total. `total == 0` is handled. The result is identical with and without the callback (D12b-04, executed by P-2).
- **Concurrent staging.** `_private_stage_dir` is one `mkdtemp` per writer with an `exist_ok` home and post-creation re-checks (`workspace.py:567-610`), so a Save worker, an A2L copy and a report never share a staging path.
- **Not regressions.** The gap between the project request frame's no-follow / cap checks (`_a2l_admission`, `_list_project_files`) and the parses already held `check_project_files` on base; 12b adds only the thread start. `record_save_entries` before the worker matches base (base never undid it on failure). The Inc 11 preparation is read-only.
