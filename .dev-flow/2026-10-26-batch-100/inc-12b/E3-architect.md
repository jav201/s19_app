## Checked and fine

- **Project-load equivalence (LLR-177.1f).** The worker parses the image with explicit A2L inputs and `existing=None`, which is the identity merge the base gets after its reset. It merges the MAC onto its own `image`, never onto the live `current_file` (U2 hazard closed). `_apply_prepared_load` changes only `variant_id` and `bases_set` on the object it installs (`app.py:15968-15976`, `:16110`). F-1's stamp therefore closes the only field the merge copied from the installed image. The merge does not copy `bases_set` on the base either. `mac.mem_map is image.mem_map` keeps the `mark_saved` identity rule (`app.py:16019-16023`) firing once, as on the base. The install order (reset → regions → cache → A2L-only → document → `current_project` / `_variant_set` → image → MAC → announcement) matches the base body (`app.py:12260-12376`). Q-g1 keeps TC-B100-08's two installs.
- **Save equivalence.** An emit implies an image row (`app.py:11208-11220`), so `request.image is not None` equals the base `image_step.emit` for adopt and `mark_saved`. `_report_filter_path`, `_variant_set` and `current_file.variant_id` are worker locals and are written only by the commit arm, so the failure arm needs no restore. `_abort_save` keeps only the file rollback. Moving `record_save_entries` to the kickoff is unobservable: its value is a pure function of the document (`change_service.py:2203-2206`), the refusal freezes the document, and its only reader re-records before it reads. A failed save leaves `_last_manifest_verify_result` at its earlier value where the base wrote `None` (`app.py:11636`). Both readers read immediately after a write (`:10968`, `:13084`), so this is unobservable too. Base `emit_and_verify` stamped `saved_path` and `source_image_path` on the summary in place (`change_service.py:2456-2458`). P-1 stamps them on main before `adopt_rederived`, and `VerifyResult.written_path` exists (`changes/verify.py:50`).
- **Immutable requests.** `_PreparedSave` and `_SaveSession` are frozen (Inc 11 interfaces :45-71). The mutable payloads (the derived map, `ChangeSummary`, the parsed A2L dict) have no main-thread writer while the run exists. `rederive_for_save` writes no service state (`change_service.py:2208-2272`), so a busy refusal after the Inc 11 preparation changes nothing.
- **Refused set.** Every app-side writer of `current_file`, `current_project(_dir)`, `_variant_set`, `current_a2l_*` and the change document was found by grep. Each sits in a session-action handler, in `_apply_unload` (2 callers, both refused), in `_activate_project_file` (save-back, refused; syncs inside session ends), or in the reset. Of the modal continuations (`push_screen` census), only `LoadGuardScreen` and the two JSON editors write the document (P2-5). Flows, operations, the report viewer and the Check Editor (which writes under `base_dir`, `app.py:6414-6416`) do not write the image, the document or the project. The s19 palette dispatches through `run_action`, which applies `check_action` (`textual/app.py:4243-4247`).
- **Ends.** Every begin has exactly one end on every path. Kickoff guards end only when the dispatch itself raises (A12a-08). Inner `except Exception` → failure handler, end last. Outer `except BaseException` → posted `_busy_fail` (a no-op after an effective end, 12a A12-72). The deferred installs (`call_after_refresh`) carry their own guard (P1-34, C12b-52). With non-exclusive groups nothing is cancelled before its body runs.
- **Quit.** The check inside `end_busy`'s effective branch reaches every exit (`end_busy`, `_busy_fail`, `_handle_load_error`). In the question-open-at-end state, `y` later exits at once and `n` stays. `ctrl+q` again while busy is ignored (Q-c2). After the end, `ctrl+q` is an idle quit. A second question answered Stay cancels a pending quit. `q` does not pass a modal (`textual/screen.py:449`). `ctrl+q` is priority (`textual/app.py:454-462`). The palette's system "Quit" calls `self.action_quit` (`textual/app.py:1344-1348`), so the override catches it.
- **Textual 8.2.8 semantics the design relies on.** `call_from_thread` blocks on `future.result()` and raises on the main thread (`app.py:1818-1838`). A thread worker runs through `run_in_executor` (`worker.py:326`). `Worker._run` catches `Exception` and, with `exit_on_error`, calls `_handle_exception(WorkerFailed)`, which exits with return code 1 (`worker.py:376-385`, `app.py:3263-3283`). `cancel()` cancels only the task (`worker.py:416-421`). `exclusive` defaults to `False` in `@work` (`_work_decorator.py:45`) and cancels only when it is set (`worker_manager.py:75-76`). `call_after_refresh` posts `InvokeLater` (`message_pump.py:466-467`).
- **The `a2l.py` crossing.** It adds one optional argument and changes no result (D12b-04). The 4 one-argument callers outside `app.py` are unchanged.
- **Simplicity of the rest.** The two installs, the `routed` flag, `_QuitQuestionScreen` and the per-key groups are each the smallest form that meets a requirement or a test pin.
