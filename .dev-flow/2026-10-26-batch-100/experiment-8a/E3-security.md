## 1 · Executed evidence

**P1 — the cost the reopen adds to every Load** (`probe_reopen_cost.py`, sha256 `952a3b59…6f98bb6`). The probe builds a valid v2 change document with N distinct address entries through `ChangeService.add_entry` and `serialize_change_document`, then times `ChangeService().load(path, base_dir)`. That is the call `_reopen_active_document` makes.

| entries | bytes | `ChangeService.load` |
|---|---|---|
| 100 | 6 322 | 0.01 s |
| 1 000 | 62 122 | 0.09 s |
| 5 000 | 310 122 | 2.07 s |
| 10 000 | 620 122 | 8.28 s |
| 20 000 | 1 240 122 | **33.33 s** |

The read cap is `READ_SIZE_CAP_BYTES = 268 435 456` (`changes/io.py:257`, = `DEFAULT_COPY_SIZE_CAP_BYTES`). The entry ceiling is `MF_ENTRY_COUNT_CEILING = 100 000` (`io.py:261`). The cost grows roughly as N², so a document at the 100 000 ceiling (~6 MB) would take on the order of 14 min (extrapolated, not run).

**Read-only source checks** (cited where they are used below):
- `resolve_input_path` (`workspace.py:1990`) returns the path as given when it exists. A missing relative path falls back to `base_dir`, then to the repo root.
- `read_change_document` puts `type(exc).__name__` in its finding messages (`io.py:467`, `:573`, `:1617`).
- `_restore_manifest` (`app.py:8935`) stages and runs `os.replace` with no destination guard.
- `_abort_save` (`app.py:8832`) restores `manifest_restores` first, then unlinks every `placed_files` entry.
- `place_into_workarea` bases its reuse race-freeness on "no in-app writer replaces or deletes a placed file" (`workspace.py:1080-1083`, LLR-155.3).
- `validate_project_files` (`workspace.py:1842`) selects images with `is_file()`, which follows file symlinks; images get no link check at Load.
- `set_status` (`app.py`, `_append_log_line`) does not scrub control characters. The Load panel does (`screens.py:1156`, `safe_text`).
- `_manifest_key_refusal` / `_component_refusal` (`variant_execution_service.py`) refuse drive, root, `:`, device names and a trailing dot or space. They do not refuse C0/C1 control characters.
- `manifest_keep_reason` is consulted by Save project (`app.py:9574`). Skipped entries are not a keep reason.

### R3.2 · New classifier nodes

**`recorded_document_state`**: no bypass found.
- Caps: the size cap is read from the file's own `lstat` before any open; the read is bounded to 1 048 577 bytes and "more read than the cap (the file grew) → `too_large`"; the count runs before the parse; the parse runs on the same bytes. No path reaches `parse_change_document` over either cap, and `ChangeService.load` / `read_change_document` are never called (examples pin 0 calls).
- Link check: `lstat` of the home, then the file, both before the open; a link on either → `link`, 0 bytes read. A device name, a FIFO or a folder is "not a regular file" → `unreadable` before any open, so no device read and no hang. The `lstat` → open window stays the accepted pre-ruling 11 class.
- Exception set: steps (4) and (5) both catch `JSONDecodeError`, `RecursionError`, `UnicodeDecodeError`, `ValueError`, `TypeError`; any `OSError` on `lstat` / open / read → `io_error`; the form predicate (NUL and C0/C1 refused) rules out the `ValueError` that `lstat` raises for an embedded NUL. Probe: a 5 000-digit integer makes `json.loads` raise `ValueError` (Python's int-digit limit), and **`parse_change_document` also raises `ValueError`** despite its "Raises: None" contract (it catches only the three decode errors). Step (4) catches it first, so the classifier as designed does not raise; no example pins it (S3R3-2).
- Save project on a hostile manifest: a drop removes only the key (no file deleted); `too_large` / `io_error` keep a key that names a regular file the reader already walked; a kept file is hashed by `project_file_records`, the same uncapped hashing every top-level data file already gets (pre-existing class, not new in 8a).
- Painted text: four user-term reasons, detail to the log only (entity `RecordedDocumentState.detail`); example "(E3 R6 …) failed-write, held-file, unreadable and drop arms → 0 issue codes, 0 class names". Wording drift for `io_error`: S3R3-3.

**`classify_active_document`**: one bypass of the link check (S3R3-1).
- "Inside" is decided on `normcase(abspath(...))` text; a textually-inside source goes through `document_in_home`, which `lstat`s the home and the file, so a junctioned home inside the target is `inside_elsewhere` (example "`P/patches` is a junction … → inside_elsewhere, never outside"; mutant on the resolved path → RED).
- A textually-OUTSIDE source gets one `lstat` of its final component only, and the gather then copies it "as today", i.e. after `active_document.resolve()` (`project_gather_service.py:498`). `place_into_workarea` rejects a reparse source "directly", but it receives the resolved path, which is never a reparse point.
- Painted text: the gather's findings go to the log only (`app.py:9548-9549`); the app's one status line for `inside_elsewhere` / `missing` is a fixed phrase through `safe_text`.
