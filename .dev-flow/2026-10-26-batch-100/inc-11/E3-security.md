# Inc 11 — E3 security review (code-free PDR)

**Verdict: PASS-WITH-NOTES** — 0 HIGH · 1 MAJOR · 5 MINOR · 3 NIT.

S11-01 needs a ruling before E4. It is a base defect, but Inc 11 changes two things about it. The prefill sends the default keystrokes (`ctrl+s`, `alt+s`) into it, and the dialog now paints the wrong target as `updates the open project`. That is the exact case the operator's P-C note warns about. The fix stays inside the moved G10 block and `_plan_project_save` (app.py, within the cap). It removes a name-folding path; it adds no guard.

Scope reviewed: E1-scope, E1-rulings, E2-rulings, E1-requirements-draft, codewire/interfaces-11 (fixed), baseline-11 / baseline-notes, proto-11-app (G-B) and proto-11-dialog (G-A). I read the code at main `8947666` (`app.py` G4–G18 `:9476`–`:9855`, the commit tail `:10150`–`:10232` and `:10490`–`:10556`, `_plan_project_save` `:10806`–`:10956`, `_file_digest` `:1680`), plus `workspace.py` (`sanitize_project_name`, `is_windows_device_name`, `validate_project_files`, `_match_identical`), `project_gather_service.py` (`SavePlan`, `_walk_refusal`, `plan_project_save` refusals, the ceilings), `variant_execution_service.read_project_manifest`, the 9b worktree's `check_action`, and Textual 8.2.8 (`Screen.dismiss`, `ResultCallback`, `App.get_system_commands`, the palette binding).

Probes (executed; scripts and outputs in `work/e3-security/`; nothing outside that folder was written; `LOCALAPPDATA` pointed into it):
- `fold_probe.py` → `fold_probe.out.txt`: NTFS treats `abs`/`abſ`, `abk`/`abK` (Kelvin) and `abss`/`abß` as **distinct** folders. Python `casefold()` treats each pair as **equal**.
- `fold_save_probe.py` → `fold_save_probe.out.txt`: the shipped Save handler on base, with the open project `strasse` and an imported project `straße`. The save under the open project's own name lands in `straße` (S11-01).
- `acl_probe.out.txt`: on 3.11, `Path.exists()` raises `PermissionError` when a file's attributes are denied. `Path.iterdir()` is lazy, so its error is raised by `sorted(...)` (S11-02, S11-03).

## Checked and fine

- **Traversal and the target.** The sanitiser keeps only letters, digits, `-` and `_`, so `.`, `/`, `\` and `:` (ADS) never reach `cleaned`. G12 builds `project_dir = self.workarea / cleaned`, unresolved (SEC-1). The commit uses `prepared.project_dir` only, and `payload.parent_folder` (`painted.target.parent`, which is the work area because `SavePlan.target` is the unresolved app spelling) reaches only the G2/G3 refusals. This answers the E2-rulings "Parent folder" check: confirmed.
- **Device names.** Checked on the raw name, on each component and on `cleaned`, all case-folded. `COM0`–`COM9`, `LPT0`–`LPT9`, `¹²³`, `CONIN$` and `CONOUT$` are covered (`workspace.py:62`, `:1855`–`:1865`).
- **Reserved homes.** Python `casefold` is wider than NTFS folding (probe), so reserved names and the disguised-clash rule against a project that is not open can only over-refuse, never under-refuse. Length 64 and the full-path limit are checked before the clash loop, as on base.
- **Link or junction at the target.** G13 refuses it before any read. The commit keeps `mkdir(exist_ok=False)` ownership and the placement guard that sees reparse points.
- **Time of check vs time of use.** `confirm` re-prepares at the Save press, and the router does not re-prepare on the dialog path. The gap is one `call_next` hop (`ResultCallback.__call__`). On base, the window between G13 and `mkdir` already spanned the planning (hashing, the inventory walk), so the window is no wider. Disk changes in the gap still meet `mkdir` ownership, `_plan_row_mismatch` and the rollback.
- **The confirmed save's match.** It requires both `payload.plan is confirmed.plan` and the same typed name. Both attributes are cleared on every route out and reset at open. `SavePlan` equality covers every field the commit reads (target, kind, rows, copies, totals, refusal).
- **Painted text.** Every name G-B composes goes through `painted_names`: device and clash texts (new), the unreadable target (base `safe_text` + `painted_names`), the missing source (new), `_unreadable_text` (new), and plan refusals (`_second_file_refusal`, `_walk_refusal` and the cap texts already scrub). So do the image description (changed), rows, folders, links and the active-variant row. G7 and G13-link embed only `cleaned`. G-A paints with `markup=False` and `Text`, so there is no second scrub. The status log is markup-off. The router logs only the scrubbed refusal. No `\n` survives (`painted_names` removes Cc / Zl / Zp), so a where line cannot be split.
- **Per-keystroke cost** (except S11-06). The 150 ms debounce holds. One `iterdir` of the work area (name compare first). `read_project_manifest` is capped at 1 MiB (`MANIFEST_SIZE_CAP_BYTES`). The exempt digest runs only for a same-name, same-size target item, and the open project's own file is exempt by path, so F-case06 typed `P` adds 0 digests. Identical-match hashing is bounded by the session files' sizes. `differs_from_last_saved` iterates only the journal.
- **Write failure partway through the commit.** The commit is moved verbatim, with its four `except` arms, including `except Exception` → `_abort_save` (`app.py:10350`–`:10412`), the manifest restore and `kept_copies`. The Q10 edits (b), (c) and (d) keep the base substitution to `landed_document`, so the Patch Editor binding and `active_document` follow the real landing. A source deleted after the open meets the commit's `OSError` arm and is rolled back.
- **The guard.** The whole-stack tuple `(LoadDialog, ConfirmQuestionScreen, SaveProjectScreen)` matches 9b's form (`s19_app-b100-inc9b` `app.py:8417`). Textual's `ctrl+p` palette over the dialog offers only system commands (Theme, Quit, Keys, Maximize, Screenshot; the app defines no `COMMANDS`), and none of them reaches the save state. `ctrl+q` quits with nothing half written, because the commit is synchronous. `alt+s` is a screen binding, so it is not in the chain while another screen is on top.
- **Data flow.** Nothing leaves the local system. There are no secrets, tokens or credentials in the slice.
