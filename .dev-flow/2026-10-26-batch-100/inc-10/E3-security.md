## Checked and fine

- **Question text scrub.** The title, the 3 item forms and the target all pass through `painted_names` exactly once, in `_load_question_text` (C17–C26). `painted_names` removes Cc/Cf/Zl/Zp characters (bidi, zero-width, ESC, newlines) and clips each name to 120 characters (`project_gather_service.py:965-1013`). The title `Label`, the body `Static` and both button labels paint with markup off (K6; I1-2 shows `rich.text.Text` labels are literal, per ruling P-GA10-1). The labels are literals, so a hostile name cannot relabel `Replace (y)` / `Cancel (n)`. The answer log line carries `kind` and `replace` only, never a name.
- **Priority keys.** The app's `priority=True` bindings are `ctrl+k/d/l/s` (`app.py:2155-2158`), which S-f's whole-stack test makes inert under the question; LoadDialog's `alt+l`, which applies only on its own screen; and Textual's own `ctrl+p` / `ctrl+q`. The app defines no `COMMANDS` and does not override `get_system_commands`, so the Textual palette offers only Theme, Quit, Keys, Maximize and Screenshot, and none of them loads. Quit with unsaved work belongs to Inc 12 and is out of HLR-174.
- **Non-priority keys and mouse under the question.** They do not reach the main screen (K4). `Button` binds only `enter`.
- **Type-ahead.** A repeated `enter` that lands on the question presses `#confirm_no` (AUTO_FOCUS), so it cancels. A stray second request, such as `enter` on `#files_list`, can stack a second question. Each stacked question still asks before its own `go`, and no stacked order loses work without a `y`.
- **Double-click click-through.** I measured a double-click on SelectVariantScreen's `#variant_ok`, where the first click dismisses, `_handle_select_variant` pushes the question, and the second click lands on the question. The button column is shared, but the rows differ by 4–5 at 118×54, 99×54, 220×60, 80×24 and 120×30, with 2 or 3 variants. The second click hit no button: stack stays `['Screen','Q']` and `answers=[]` in all 10 arms (`probe_sec_click.out.txt`). The same probe confirms that the dismiss-callback push lands over the main screen and not over the closing modal.
- **Double answer.** The `_dismissed` guard runs as the first line of `_close` (K7, Q5-1), and `answer` runs `go` once per dismiss.
- **Stale `go`.** While the question is open nothing can change the variant set, the project or the target path: input is modal, the palette cannot load, and the only background installs are S10-03's. `_pending_variant_id` is set only inside `go` (C42).
- **State before `y`.** The 9b router (log and defer), `_typed_load_route` (metadata only, 0 writes, grep), the leaves' `exists()` / descriptor checks and `_load_would_lose` write nothing. `record_recent_source` has exactly 2 callers, both inside the loaders, so inside `go` (C36 holds). `copy_into_workarea`, the session reset and `_last_load_announcement` all run inside `go`. Cancel calls only `_rehome_focus_after_load`.
- **Kind classification.** A typed path uses the stripped `typed.suffix.lower()`, the work area uses `candidate.suffix.lower()`, and the loaders read the same suffix. Windows `abspath` can only drop a trailing dot. That turns `x.mac.` into `x.mac`, which asks once for nothing; it never turns an image into a question-free attach. A MAC over a MAC-only session replaces the map, but a MAC-only session cannot hold a patch: its `ranges` are `[]`, so apply writes nothing (`changes/apply.py` containment). `MAC_EXTENSIONS` and `A2L_EXTENSIONS` are sets, so `|` is valid. An A2L attach keeps the image map.
- **Refused image loads after `y`.** The `load_from_path` refusals (not found, unsupported, containment), a `load_selected_file` parse failure and a worker parse failure (`_handle_load_error`) all return before `current_file` changes, so the work is kept. A project refusal before the reset keeps the work; after the reset, see S10-01.
- **Exception in `go`.** `go` runs in the same `call_after_refresh` frame the 9b router uses on base, so the exposure is unchanged. The new guard and composer code cannot raise on mounted or unmounted trees: `App.query_one` searches `default_screen` (Textual `app.py:941-943`), and `Flow` has no validation (`flow_model.py:536-559`).
- **Flow Builder.** `set_blocks` has one caller, and it goes through `ConfirmDiscardScreen` (`app.py:3482-3486`). A project load keeps the builder (Q1).
- **Bypass census.** No module outside `app.py` calls the loaders (grep of `s19_app/`). The only image installers are `load_selected_file`, `_start_load_worker` and `_install_project_image`, the last inside `_handle_load_project`. The document loader is outside the census; see S10-02.
