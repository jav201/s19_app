## 1 · Executed evidence

**P1 — cost of the save-as copy on the current placement** (`p1.py`, sha256[:16] `01cfa0b45aeca5d5`). Builds P under a scratch work area, runs the inventory the design describes (`walk_tree_no_links` + `os.lstat` per entry), then copies every regular file with `place_into_workarea(P/rel, Q/rel.parent, workarea_root=W)`, exactly what `_copy_project_subfolders` step (3) calls, without the extra per-file re-check of step (1).

| files | files per folder | inventory | copy | per file |
|---|---|---|---|---|
| 1 000 | 1 000 | 0.05 s | 5.99 s | 6.0 ms |
| 3 000 | 3 000 | 0.13 s | **26.43 s** | 8.8 ms |
| 3 000 | 100 | 0.14 s | 14.19 s | 4.7 ms |

The per-file cost grows with the size of the destination folder, because each placement lists that folder once (`find_identical`), so a single folder is quadratic. Extrapolated, not run: 20 000 files in one folder take about 6 min; 100 000 files spread out take about 8 min. Save project runs on the main thread (a dialog callback), so the app is frozen for that time, with no progress and no cancel.

**P1 — parent spellings against the G1 rule** `normcase(realpath(parent)) == normcase(realpath(W))`: trailing separator, upper case, `W/temp/..`, the 8.3 short name, forward slashes and a junction `alias` → W are all **equal**; the `\\?\` prefixed spelling is **refused**. UNC (`\\localhost\C$\…`) and `subst` were not executed (UNC realpath keeps the UNC form, so it is refused; fail-safe either way, see S3-10).

**P1 — the shared folder check on a two-part name:** `W/sub` a junction to `W/R`, name `sub/P` → `_is_reparse_point(W/sub/P)` False, `contained_in_workarea` True: accepted (S3-7).

**P2 — names inside P's tree** (`p2.py`, sha256[:16] `210bfb26a9da2ef0`). Files created through `\\?\`: `CON` and `con.json` → `os.lstat` on the normal path reads a regular file (this Windows 11 build does not map them to the device). `x.json.` and `y.json ` → `os.lstat` on the normal path raises ENOENT, so the G2 inventory rule "an entry whose `lstat` raises is left out" drops them with no line (S3-2).

**Read-only source checks** (cited below):
- `place_into_workarea` (`workspace.py:1000`) checks only the final source component for a link, then `source.resolve()` follows any junction above it; the size is read once, before the copy.
- `_is_reparse_point` (`workspace.py:207`) returns False on an `OSError`; it never reports "link" for an error (the G1 node text says it maps errors to link).
- `_abort_save` (`app.py:9125`) unlinks only `placed_files` and removes folders only while empty: the rollback cannot delete a file this save did not claim.
- `_handle_load_project` (`app.py:11316`) parses the project A2L in place with `_load_a2l_data_with_cache` → `parse_a2l_file`: no link check, no size cap. `validate_project_files` selects with `is_file()`, which follows a file symlink. The base A2L-only route went through `load_a2l_from_path` → `copy_into_workarea` (`app.py:12138`), which refuses a link and caps at 256 MiB.
- The save handler's existing excepts (`app.py:10123–10180`) paint `str(exc)`: `Cannot save project: Refusing to copy: …` and `could not save — [WinError 5] …`.
- `_manifest_carry` (`app.py:11570`) makes every reader-accepted entry relative to `project_dir.resolve()`; entries the reader skipped are not carried.

### R2.1 · Executed evidence

- **Walk cost of entries that are not regular files.** 20 000 empty folders under one folder: `walk_tree_no_links` + `os.lstat` + `_is_reparse_point` per entry took **4.70 s** and counted 0 regular files, so the R1 file ceiling never fires. - **Scrub set of R6 against Unicode.** 151 code points of category Cf / Zl / Zp are outside the scrub set LLR-171.7 names, for example U+00AD, U+061C (ARABIC LETTER MARK, a bidi mark), U+180E, U+2028 / U+2029 (line and paragraph separators), U+2060–U+2064, U+FEFF, U+FFF9–U+FFFB and the tag characters U+E0001–U+E007F.
- **Unpaired surrogate in a name.** A file named `x` + U+DC80 + `y.json` was created in P with a normal Python `open`; the walker yields it; `safe_text(...).plain.encode("utf-8")` raises `UnicodeEncodeError` ("surrogates not allowed"). Not run: the effect of painting it in the TUI.
- **Device names at the top level (R3, R10, R11).** Not run: this Windows 11 build refused to create `CON`, `CONIN$`, `NUL.txt`, `con.json`, `AUX` and `COM1.s19` even through `\\?\` (EINVAL). Round 1's P2 created two of them on its run. The design already turns an entry that `lstat` reports as a device into `unreadable`; see S3R2-6.
- **Read-only source checks.** `find_identical` (`workspace.py:921`) matches only `<name>` and `<stem>_<digits><suffix>` of the copied file's own name. Placing the top-level copies after the rows (R11) therefore cannot reuse the image row's landing, and F-8 is gone. `_handle_load_project` (`app.py:11330–11343`) clears the local `a2l_files = []` when the parse fails, and that local also feeds `_install_project_image(install.variant, a2l_files)` (`:11369`) and `load_selected_file(install.mac, a2l_files)` (`:11386`), which reaches `_load_mac_file` → `_load_a2l_data_with_cache(a2l_files[0])` (`:13221`, `:13228`), a second parse site of the project A2L (S3R2-3).

### R2.4 · Attacks on the pass that found nothing

- **Long names and deep paths under the ceilings:** 2 000 names of 255 characters are small in memory. A path past the Windows length limit makes `scandir` raise → `unreadable` → refusal before `mkdir` (fail-safe).
- **The `unreadable` walker change:** additive. Its other callers pass nothing, and an unlistable folder is still skipped for them, as at `ebe6d0c`. A folder that cannot be listed is a refusal, never a partial copy.
- **Top-level copy, links:** a top-level file link is listed in `skipped_links`, never copied (pre-ruling 10). `place_into_workarea` refuses a link at the source. The plan leaves out the row names (`normcase`) and, with a MAC / A2L row, every other MAC / A2L of P (F-7), so Q never holds two.
- **A P file swapped mid-save:** a file link or junction above it → steps (1) and (5) → row 11 → rollback. A file that grows past the cap → the placement raises → row 11. A file that vanishes → `WorkareaPlacementError` → row 11. A hard link to an outside file is a regular file and is copied, but its bytes were already readable through P, so no boundary is crossed (same-user, not counted).
- **A2L guard:** both branches are guarded before the reset or the parse. The window between the `lstat` and the parse is the accepted TOCTOU class (8a pre-ruling 11). An A2L at or under the cap is still parsed on the main thread (R5 accepts this).
- **`painted_names` with very long names:** each name is clipped after the scrub, with at most 10 names per line. Combining-mark floods inside the 120 characters are cosmetic.
- **Session rebind to Q:** `_publish_flow_session_dir()` publishes `current_project_dir` = `self.workarea / cleaned`, which is inside W by construction (steps 1–2). The only path outside Q is S3R2-5.
- **Ceiling refusal text:** it names the limit and P's name, which is a work-area child name the operator chose. No file name from the tree is painted without `painted_names`.

### R2.5 · Inc 1–8a rules

Hold in the corrected design. Every copy goes through `place_into_workarea`, with the destination unresolved (LED .50), private staging, an `O_EXCL` claim and the `lstat` re-check. A save as never replaces a `project.json` (Q is new), so the `.previous` logic is untouched. No new `os.replace` of an existing file. The planner computes no payload digests: the only hash is G1's same-name, same-size `exempt` check, and that runs in the app. The rollback unlinks only claimed files and removes only empty folders. Refusals carry no issue codes and no exception text (R6). The A2L-only attach never uses `load_a2l_from_path` (C4), and the R5 guard replaces the link and cap guards that `copy_into_workarea` gave that route. R9 writes only under W.
