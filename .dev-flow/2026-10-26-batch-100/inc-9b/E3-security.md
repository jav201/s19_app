# E3 — Inc 9b PDR, security review (S9b-)

**Verdict: PASS-WITH-NOTES** — 0 HIGH, 2 MAJOR, 6 MINOR, 1 NIT.

No finding leaks a secret or crosses a trust boundary the requirements allow. Two MAJOR findings must be folded into the design before E4, because each defeats a control the design claims to have:
- **S9b-1:** the LLR-173.2e guard can be bypassed through `ctrl+p` (executed probe).
- **S9b-2:** the synchronous project preview follows links inside untrusted project folders on the event loop. Merely pressing `p` triggers it.

This clearance is not ship authority. S9b-1 and S9b-2 are `planned` mitigations, and I re-verify them at the increment gate.

## Checked and fine

**Painted text**
- Every dialog label from disk goes through `pn`: project rows, work-area rows, recent rows (`PureWindowsPath(e.path).name`), the `_file_preview_marks` names, the project preview names (variant, MAC, A2L, sub-folders).
- The recent `kind` is safe, because `_recent_entry_ok` requires it to equal `recent_kind(path)`.
- `pn_full` is unclipped (`painted_names(..., clip=len(v))` exists, `project_gather_service.py:965`). Entries already refuse U+0000-001F, U+007F-009F, Cf, Zl, Zp and Cs (`workspace.py:2190-2220`).
- `OptionList(markup=False)` passes the flag to `visualize` (`_option_list.py:763`).
- The preview `Text` in `Static(markup=False)` and the constant `#load_reason` tokens are safe.
- `cannot load: {error}` uses only the 2 constant `validate_project_files` sentences.

**Path handling**
- `workarea` values are the on-disk names from `list_workarea_files`, which skips links (two gates), names ending in a dot or space, and non-files. `.`/`..` cannot occur.
- `project` values pass `_project_folder_refusal` (lstat link check) and the `normcase` listing match.
- Recent entries are drive-rooted only, so UNC, `\\?\` and `\\.\` are refused. So are streams, device components and control characters. A recorded path never reaches the relative fallback (LLR-172.2e + LLR-173.1f).
- The typed-path preview is suffix-only, with 0 filesystem calls per keystroke.
- Recents make 0 filesystem calls before Enter (rows and preview).
- LLR-172.1n `via_fallback` is pure.

**Failure paths**
- `read_recent_sources` never raises (catch-all), and its problem lines paint no store path.
- `list_workarea_files` never raises, so rows step 2 is safe.
- `list_projects` `OSError` is caught in the rows (LLR-173.4m) and in `_handle_load_project` / `_typed_load_route`.
- F-12's catch at `:11743` sits before any reset.
- The preview catches `OSError`. Its non-`OSError` sources (`build_variant_set` with no `active_id`, `choose_install_set`) cannot raise. `read_project_manifest` maps JSON, `ValueError`, `RecursionError` and `OSError` itself.
- A missing recent gives `not found` in the dialog, with the store unchanged.
- An unassigned drive `Q:` returns `False` with no hang. A mapped offline drive at Enter is the declared §6 "Known gap".

**Preview cost**
- No image read and no hashing on a highlight: `check_project_files` is removed, and `_file_preview_marks` is pure.
- The manifest read is capped at 1 MiB.
- The A2L metadata test uses `lstat`. The limits are S9b-2 and S9b-3.

**Modal guard**
- The four keys are inert while `LoadDialog` is the top screen (G-A probe K6 mechanism).
- Non-priority app bindings are stopped by the modal.
- Within the dialog the palette offers only Theme / Quit / Keys / Maximize / Screenshot; no app action is exposed. Only the stack-top test is wrong (S9b-1).
- Opening Load over another modal (Save, Load-result) is the Q6 backlog (Inc 11).

**Logging**
- `_handle_load_dialog` and LLR-172.1n log values with `%r`, so control characters are escaped.

**Out of scope, noted for the backlog**
- A data load worker can still be running when Load is reopened (no in-flight guard; Inc 12a).
- `read_project_manifest` follows a linked `project.json` at load time as well (pre-existing; S9b-2 fixes it on the 9b route).
