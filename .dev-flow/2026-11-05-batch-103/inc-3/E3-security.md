## Answers to the questions routed to E3

- **E2‑7 (fail‑closed choices, the 1 MiB record cap — "the security reviewer for the size cap"):** the *byte* caps hold and fail closed. Over 203 files the model raised 0 times and reached no open branch ([C1], [C3]); a curve/map whose record walk passes `MAX_A2L_DECODE_BYTES` returns `None`→`A2L-DEF-ADDRESS` (`.7.1`), and an array's computed byte length `>` 1,048,576 → `.7.2` ([C2]: real refusals `A2L-DEF-ADDRESS`, `-ALIGNMENT`, `-LAYOUT`, `-AXIS-KIND`, `-AXIS-PARTIAL`, `-AXIS-REF`). The gaps are the two caps that are **not** byte caps: the FIX point count cap (E3S3‑02 — `.142` bounds a *count*, materialised eagerly at describe) and the absence of a datatype restriction on the count component (E3S3‑01 — a raise). A huge MATRIX_DIM product (3 whole numbers, ≤ 10^9 each) is a bignum that `.7.2` refuses in O(1); the layout walk bails at the first component once the offset exceeds the cap — no hang (R).
- **E2‑3 / E2‑10 (two extra nodes `_conversion_fields`, `_module_common`; changed signatures):** no security objection. `_module_common` is an identity lookup in the one walk's map (not a per‑object tree walk), so it adds no DoS surface; E2‑8's unclosed‑`/begin` nesting does not defeat it (the walk finds the one MODULE by identity). These are the architect's to accept on design grounds.
- **E2‑5 (decode/encode on a scalar definition):** the one‑element reading is safe; no new raise path.
- **E2‑9 / E3A‑32 (describe‑all cost):** the ≈ 0.995 s figure holds for software_a (model 0.40 s here [C8]; the cited cost prototype is the figure of record). It does **not** hold for a hostile file — see E3S3‑02. Determinism: the model's output digest over V171 + software_a is identical under three `PYTHONHASHSEED` values [B6].

## Checked and clear
- **No raise over the corpus.** 561 objects over the 35 fixtures and 7,331 over the 168 public‑corpus files built with **0 exceptions** and **0 open branches** [C1]/[C3]; the public corpus (`design/a2l-corpus/`, runner `~/a2l-corpus/files`, 98 MB) is untrusted, read‑only, never copied in.
- **`.58.2` whole‑number reads.** MATRIX_DIM, NUMBER, positions, FIX_NO, ALIGNMENT and max‑axis‑points words go through the CTX *whole number* read (1–9 ASCII digits, no `int()` on a longer word); the COM axis object address uses `int(word,0)` only for ≤ 20 characters; `_fixed_points` uses `_to_float` then a finiteness gate, and computes `2^s` only for `s < 1024` ([B2] confirms `2.0**1024` raises and `2.0**1023` is finite). No decimal `int()` on a > 4300‑digit word is reachable.
- **`2^s` / absurd FIX counts / non‑finite words.** Covered by R-A2L-DEF.141/.142; one finite float tuple at most, bounded by the cap (the eager *build* is E3S3‑02, not a raise).
- **COM_AXIS self/dangling/cycle.** Self‑reference and a missing object both → `A2L-DEF-AXIS-REF` in O(1); CURVE_AXIS/RES_AXIS → `A2L-DEF-AXIS-KIND` before any resolution (50 in the corpus [C2]); the axis object is read for points only and never re‑described, so no cycle [H].
- **COM axis object record span.** `.143` bounds it (placement `None`/negative/last‑byte); a `>` 1 MiB axis‑object record is refused.
- **Record components overflowing the span.** The reused `_walk_record_layout_components` caps at `MAX_A2L_DECODE_BYTES` and bails (`.7.1`).
- **MOD_COMMON alignment arithmetic.** `align_up` short‑circuits `a ≤ 1` (no `ZeroDivisionError`); `_collect_declared_alignments` fails closed on non‑positive/non‑int; ALIGNMENT words are whole numbers ≥ 1. Real corpus alignments are small [C7].
- **Determinism, no writes, no secrets.** `R-A2L-DEF.58.1` deep‑copy covers the payload and image; the module has no file/clipboard/network I/O; no secret anywhere; PKI out of scope (public repo).
- **Real shapes exercised.** CUBE_5, FIX_AXIS_PAR, COM→AXIS_PTS, many‑component layouts all present; largest real element count 524,280, largest FIX count 1,000, NO_AXIS_PTS datatypes only UBYTE/UWORD [C4]/[D1]/[D2]/[D3] — so E3S3‑01's float count and E3S3‑02's cap‑sized FIX axis are hostile‑only, which is the point.
