## Why token strings and the float list are no longer all retained

- **No second float list.** The old code built `numbers = [_finite_number(word) for word in list_numbers]`, holding a whole list of `float`s alongside the token strings. The new loop parses each word via `_finite_number(word)` and immediately converts it with `_to_int_or_float` before the loop variable is reused, so the float list never exists.
- **Token strings are replaced in place, not kept alongside.** `list_numbers` *is* the `tokens` list returned by `_flatten_body_tokens` — a freshly built list with no other owners. Writing `list_numbers[i] = _to_int_or_float(number)` overwrites each `str` slot; once a slot is overwritten, the old string has no remaining reference and is collectable immediately (there is no alias to the original token list inside `_read_fixed_rule`). So the strings are released progressively during the loop instead of surviving until the branch ends.
- **`tuple(list_numbers)` shares the numeric objects.** The final tuple holds references to the same `int`/`float` objects already stored in the mutated list — no second copy of the values is materialised. After `return rule`, the local list is dropped and only the tuple (and its `int`/`float` objects) survives.

Peak simultaneous retention drops from three collections (token strings + float list + int/float tuple) to two (the single in-place list + the shared tuple), and the list no longer holds any strings by the time the tuple is built.
