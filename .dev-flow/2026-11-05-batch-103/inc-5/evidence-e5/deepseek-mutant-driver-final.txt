### Point 3 — PASS
Classification (`run_5_mutants.py` result line): `"killed" if failures else "SURVIVED" if returncode==0 else "TIMEOUT" if returncode==124 else "ERROR"`. With `-q`, pytest emits `FAILED …` lines only in the final summary, so a genuine timeout (returncode 124, summary never printed) lands on `TIMEOUT`, not `killed`; a test-only ERROR lands on `ERROR`. The collected `errors` list is dead but harmless. Classification is conservative (it can under-report kills — e.g. ERROR counted as "survived" — but cannot misreport a timeout/error as a kill). Baseline timeout (2400s) is uncaught and fails loud, which is acceptable.
