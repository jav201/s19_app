## User stories

### US-103-06 — the commission story
From the Patch Editor alone, the operator applies the document's changes to the loaded image, sees that they were applied, and exports the changed image as S19 (16 or 32 data bytes per line) or Intel HEX. (Operator, 2026-11-06: "I saw the Apply button, but I did not see the change applied. When I saved the file with the button, only the JSON was saved.")

### US-I10-1 — I see the apply and its export where I pressed Apply (US-103-06)
As the operator, I want the result of Apply and the prompt that writes the changed image to appear where I pressed Apply, in whichever tab of the Patch Editor I am, so that I see the change was applied and can write it without hunting for a tab.

### US-I10-2 — I choose the file format of the export (US-103-06)
As the operator, I want to write the changed image as S19, with 32 or 16 data bytes per line, or as Intel HEX, whatever format I loaded, with a file name whose extension follows my choice, so that I get the file my flashing tool takes without a trip through the Flow Builder.

## Definitions (changes to CTX-SAVEBACK, CTX-PE and CTX-SHELL; terms only)

- **Output format** (CTX-SAVEBACK, new). The file format a save-back writes: S19 or Intel HEX.
- **Format control** (CTX-SAVEBACK, new). The control of the save-back prompt that shows the output format and changes it.
- **Format suffix** (CTX-SAVEBACK, replaces *kind suffix*). `.s19` when the output format is S19; `.hex` when it is Intel HEX.
- **Suggested name** (CTX-SAVEBACK, changed). `<stem of the loaded file>-patched` followed by the format suffix of the output format.
- **Save-back prompt** (CTX-SAVEBACK, changed). The row "Save patched image as:" with a name box, the apply line, the Format control, the Width control `Width: <w> bytes/line`, `Write file` and `Don't save` (layout: S10, R-PE-EXPORT.1).
- **Apply line** (CTX-SAVEBACK, new). The line of the save-back prompt that states the result of the apply that showed it (text: R-PE-EXPORT.4).
- **Width** (CTX-SAVEBACK, unchanged). Data bytes per S19 record: 32 or 16.
- **Inspector tabs** (CTX-PE, informative fact, not a change): at `e07fb00` the inspector has four tab chips, Inspector, JSON, Checks and A2L (`screens_directionb.py:4453-4458`; the A2L tab is batch-102 Inc 5's and is not yet in the canon's CTX-PE or R-TUI-063.3, `E1-rulings.md` §6). "Whichever inspector tab is shown" counts all four.
- **CTX-PE `save-back prompt`** (changed, PROPOSED — awaits G2): "S8 CTX-SAVEBACK. It sits in the JSON tab, hidden until an apply reveals it." becomes "S8 CTX-SAVEBACK. Hidden until an apply reveals it; it sits under the document row (R-PE-EXPORT.1)." The JSON tab's content list drops "the save-back prompt and the before/after control"; the *before/after control* sits with the save-back prompt (D-5).
- **Shown widget** (CTX-SHELL). As batch-101 Inc 12 defines it (`b101-inc12:.dev-flow/2026-11-01-batch-101/inc-12/01-requirements.md`): a widget that is displayed, together with every widget that holds it, up to its window. Inc 10 uses that term unchanged; whichever increment merges first folds it into the canon.
- **Census sources** (test data, for the thresholds): *case01* = `examples/case_01_basic_valid/firmware.s19` (S0 data `CASE01_BASIC`, S3 records, S7 at 0x80000000, highest address 0x8000007F); *case00* = `examples/case_00_public/s19_sample.s19` (S0 data `Debug\stm8s003.sm8`, S1 records, S9 at 0xFFFF, highest 0x80F1); *s2src* = a 57-byte S19 image at 0x012340 and 0x020000 (S2, S0 data `S2SRC`); *x64* = 36 bytes at 0x0000FFF0 … 0x00010013 (crosses a 64 KiB boundary); each also as Intel HEX, emitted by the system's own HEX writer from its image (as the probe made `firmware.hex`).
