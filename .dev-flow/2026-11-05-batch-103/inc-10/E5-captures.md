Taken by X10 (claude-opus-5-5) on the PC, tree `b103-inc10` at `190121c0` (product code = `28a5c82f`; the only later change is a test). **Provisional, awaiting the operator's confirmation on the final page (P-059).**

Method: `evidence/e5/captures/capture_i10.ps1` (a copy of CAP8's `inc-8/evidence/captures/capture_i8.ps1`; only the title prefix and the driver name differ) + `capture_i10_driver.py` (CAP8's method: one NEW Windows Terminal window per capture, `--size`, unique GUID title, truecolor with `NO_COLOR` removed, `python -I -B`, isolated HOME / XDG / LOCALAPPDATA, OS clipboard and OSC 52 stubbed; the window closes itself through a release flag, else by the launcher's PID, never by title) + `run_i10.ps1` (the matrix). The scratch root was a neutral temp folder so no account path could be painted; case01 is copied into the scratch base before loading. Every state is reached through the app's own key handling: the widget is focused and Enter pressed (Inspector chip, `Add`, `Apply loaded changes`, `Format`, `Write file`); the entry boxes are typed key by key (`0x8000007C`, `DE AD BE EF`). Each PNG has a `.png.txt` sidecar with the state actually reached (statuses, prompt class, labels, name box, painted region and hit test of every dock control, the painted rows from the document row down). All 10 sidecars end `surface=ready`; 0 notifications; 0 clipboard writes. Capture lock `wt-capture.lock` held from the first window to the last and deleted.
