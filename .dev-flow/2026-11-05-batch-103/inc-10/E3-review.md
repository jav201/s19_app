## Verdict: **FAIL** — 0 BLOCKER, 2 MAJOR, 8 MINOR

The design is sound on the write path's security: the output format is allow-listed twice (handler E2-14, engine `_SAVE_BACK_EMITTERS`), the name passes the unchanged F-S-01 sanitizer, placement never overwrites (`O_EXCL` claim + `_N` dedup), staging is private and the write lands by `os.replace` (no partial file under the final name), and the verify reads with the same kind as the write. Two MAJOR design gaps stay open: a stale apply line that the dock now shows beside the edits, and Intel HEX records that cross a 64 KiB boundary — a defect the verify cannot see and the fixture meant to cover it cannot reach. Both have targeted fixes (below). E4 should not start until both have rulings that show in the requirements and the graph.

## Rulings on the E2 open items

- **Q1** — Partly settled by reading: R-PE-EXPORT.2 holds structurally for the dock's own controls (`#patch_main` absorbs the rows). The open risk is the other tabs' controls → **E3-3** (E4's G-T1 measures first). A runner probe before E4 is not needed: the result changes thresholds, not the graph.
- **Q2** — Yes, add the row → **E3-4**. Its id must not collide with E3-1's `.17` or E3-2's row.
- **Q3** — Acceptable, no row. Save project writes under the loaded image's name and in its format (`_decide_project_image`, `app.py:13968-13985`), so no S19 bytes are written under a `.hex` name. The before/after report reads each side by its suffix (E2-6 b). Not checked: whether variant execution (`_execute_one_variant`, S19 only) refuses an active `.hex` variant cleanly. That is out of scope; it goes to the backlog as a question.
- **Q4** — The allow-list holds in two places (the handler, E2-14, and the engine, `apply.py:103-106` → `render_patched_image` returns `None` → `CHG-HEX-SAVE-UNSUPPORTED`). Separators, `..` and drive prefixes are stripped (`PureWindowsPath(...).name`). A trailing dot or space and the listed reserved names are refused. No overwrite (`O_EXCL` + `_N`, the `lstat` before the claim, `os.replace` from private staging). No write outside the destination (`_guarded_destination` on the unresolved path). The apply line and the notice hold only integers (the notice's default markup is harmless: no `[`). Gaps → **E3-5**, **E3-6**, **E3-7**, **E3-8**.
- **Q5** — Confirmed by reading textual 8.2.8 (R, not a run): `Compositor.get_widget_at` returns a widget only if `widget.visible` (`_compositor.py:846`), so a click at the hidden chip's place goes to `#patch_saveback_buttons`, which has no click handler (the only `on_click` in `screens_directionb.py` is on unrelated classes, `:1446`, `:1566`). `Widget.focusable` requires `visible` (`widget.py:2373`), and `visible` reads the chip's own `visibility` rule first (`dom.py:951-953`). R-PE-EXPORT.10/1–/2 must still prove it at E4.
- **Q6** — Confirmed: the four `conflict` cases have no test. AT-I10-2 and R-S19-EMIT.3/.4/.5 assert only the terminator's **type** (`S7`, `S9`, `S8`). R-S19-S0HEADER-001.3/1–/4 assert `S0030000FC` only for sources **without** S0 data (the row's own text, not D8-27). **E4 addendum:** testers check the terminator by its two-character tag only, never a full line such as `S70500000000FA`, and never assert an empty S0 for a source that has S0 data.
- **Q7** — Confirmed: the Format control is selector state (no message, no write). `Write file` is refused by `_refuse_if_busy()` (`app.py:5393`) before `hide_save_prompt`, so the prompt and the chosen format survive the refusal. The apply arm is refused too (`:5163`).
