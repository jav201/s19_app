## User stories

### US-103-05 — the Patch Editor edits a parameter by its A2L definition (this increment: the scalar model)
As the operator, I want the Patch Editor to edit a parameter through what its A2L declares — its enum texts, its bit mask, its text length, its display format and unit, its limits and extended limits — so that I type the value I mean and the bytes the change writes are the ones the ECU reads back as that value. (PLAN, story 5, pe verdict `mix`.) This increment builds only the pure model behind it: what one scalar A2L object is, how its stored bytes read as a value and a display text, and how an operator's text becomes bytes, with the round trip as a requirement. The editors (Inc 8, Inc 9) and the picker (Inc 6) consume it through interface I-2; arrays and axes are Inc 3.

## Definitions (CTX-A2L-DEF, new context note of S2; terms, formats and lists only)

```text
defined object  A VALUE CHARACTERISTIC, an ASCII CHARACTERISTIC, or a MEASUREMENT whose
                MATRIX_DIM is 1 or absent. (Inc 3 adds its kinds to this list.)
definition      What the system knows about how one defined object stores, converts and
                shows its value: kind, address, byte length, datatype, byte order, bit mask,
                conversion method, display format, unit, limits, extended limits, enum entries,
                default text. A definition that cannot be edited carries a refusal and every
                field the system could read.
kind            number (a VALUE or a MEASUREMENT whose conversion type is not TAB_VERB) ·
                enum (conversion type TAB_VERB) · text (an ASCII CHARACTERISTIC).
refusal         A code and a message the system gives in place of a definition's edit, a
                decoded value or the bytes of an encoded value.
notice          A message the system gives with an accepted value.
conversion method record   A COMPU_METHOD as the definition reads it, comments left out:
                <name> <long identifier> <conversion type> <format> <unit>, then optional
                keyword groups: COEFFS a b c d e f · COEFFS_LINEAR a b · COMPU_TAB_REF <table> ·
                FORMULA … · REF_UNIT <unit> · STATUS_STRING_REF <table>.
enum table      A COMPU_VTAB: <name> <long identifier> TAB_VERB <n>, then n pairs <raw> <text>,
                then optionally DEFAULT_VALUE <text>.
                A COMPU_VTAB_RANGE: <name> <long identifier> <n>, then n triples
                <min> <max> <text>, then optionally DEFAULT_VALUE <text>.
                The words are read comments left out, the /begin line's words first. Entries
                are read in file order, at most n; an entry whose raw, min or max is not a
                number is skipped; a count that is not a number gives no entries.
enum entry      One pair (raw → text) or one triple (min..max → text). Its raw value is the
                pair's raw, or the triple's min.
range bounds    Both bounds of a COMPU_VTAB_RANGE entry, min and max, are included for every
                datatype, as the system's rule.
default text    The text of an enum table's DEFAULT_VALUE line.
bit mask        The number on a BIT_MASK line: 0x and hexadecimal digits, or decimal digits.
mask shift      The number of 0 bits below the lowest 1 bit of the bit mask.
object record   The words of the object's /begin line and its own lines, comments left out,
                in file order (the header words first).
the text of the object  The /begin line after the name and long identifier, its own lines, and every section below the object, at any depth, that is not an object and does not stand inside an object (an object: MEASUREMENT, CHARACTERISTIC, AXIS_PTS, INSTANCE, BLOB, TYPEDEF_…): that section's /begin line after its keyword, and its lines; comments and quoted strings included. Its sections, each on its own: the object (its /begin line and its own lines), and each of those sections (its /begin line and its lines).
span            The bytes of an object from its address through address + byte length − 1, the byte
                length being the tag's, else the size of its datatype × its MATRIX_DIM (R-A2L-014);
                an object with no address or no length has no span.
bits an object selects  For each byte of its span, the bits of that byte its bit mask selects
                (the mask's lowest 8 bits lie in the span's least significant byte: its first byte
                when little-endian, its last when big-endian); every bit of every byte when the
                system read no bit mask for it (no BIT_MASK, or a refusal of R-A2L-DEF.19). Two bit
                masks overlap when the two objects select a common bit.
stored value    The raw value (CTX-A2L-VALUE); for a definition with a bit mask, the bits of
                the raw value that the mask selects, shifted right by the mask shift.
extended limits The two numbers of an EXTENDED_LIMITS line: the extended lower and upper limit.
display format  A quoted text of the form %[<length>][.<decimals>], optionally ended by f;
                <length> and <decimals> are runs of decimal digits. Any other text gives no
                decimals.
decimals        The <decimals> of the display format.
15-significant-digit text  The number written as C's %.15g writes it: 15 significant digits,
                no trailing zeros, no trailing point, exponent form below 1e-4 and from 1e15
                (examples: 0.3, 12.5, 1234567, 1e-07).
display text    The text the system gives for a decoded value. It holds no unit.
operator text   The text an operator gives as the new value of a defined object. For a number
                or an enum, the spaces (U+0020) at both ends are left out.
number text     [+|-] then ASCII digits with an optional point and ASCII digits, or a point and
                ASCII digits, then optionally e or E, an optional sign and ASCII digits.
                Nothing else: no thousands separator, no comma, no underscore, no hexadecimal,
                no nan or inf, no other digit script.
limit value     For a number: the value of the operator text. For an enum: the raw value of
                the chosen entry.
printable ASCII The characters U+0020 … U+007E.
agree at the display precision   A decoded value p agrees with an accepted value x when
                |p − x| ≤ 0.5 × 10^(−d) in IEEE double, where the display format gives d decimals (d capped at 17), or their
                15-significant-digit texts are equal (every datatype), or, for a FLOAT32_IEEE
                datatype only, their 6-significant-digit texts are equal. FLOAT64 never at 6
                digits.
encode direction  How a conversion method turns a value x into a stored value r:
                none (NO_COMPU_METHOD) and IDENTICAL r = x · LINEAR r = (x − b) / a (a missing: 1,
                b missing: 0) · RAT_FUNC r = (a·x² + b·x + c) / (d·x² + e·x + f) (a missing
                coefficient: 0) · TAB_NOINTP the raw of the table pair whose value equals x
                (within 1e-9) · TAB_INTP x interpolated back between the two table pairs around
                it, rounded to the nearest integer. An integer datatype then takes the integer
                within 1e-6 of r; a float datatype takes r.
encode reasons  The reasons the encode direction gives when it yields no stored value:
                `LINEAR conversion coefficient a is zero` · `RAT_FUNC denominator is zero` ·
                `lookup table missing or empty` · `lookup table has no numeric entries` ·
                `the value <x> is not a table value - the nearest table values are <a> and <b>`
                (or `… are <a>` when one) · `the value <x> is outside the table range [<lo>, <hi>]` ·
                `the converted raw value is not finite` ·
                `the converted raw value <r> is not integral` ·
                `the converted raw value <r> is outside the <datatype> range` ·
                `datatype FLOAT16_IEEE is not supported` ·
                `the raw value does not pack as <datatype>: <detail>`.
refusal order   name, kind, address and length, datatype, length against datatype, conversion
                method, conversion type, enum table, entries, bit mask.
encode order    the definition's refusal, number text, enum text, text length, text characters,
                limits, extended limits, encode direction, image bytes, bit mask, precision,
                shared bytes.
case 08 pin     The SHA-256 digest of each of the 11 files the release case writes with seed
                20260001 at 10 MiB and at 1 MiB, taken on the base e07fb00 over the file's bytes
                with every CR LF read as LF: the 22 values of the increment's evidence
                (evidence-e1/i2e1-case08-hashes-transcript.txt, the rows `<size> | <file> | …`).
definitions case  The synthetic case the generator writes when asked for it (--case definitions),
                beside the release case 08, from the same seed option.
placeholders    <name> the object's name · <kind> the CHARACTERISTIC kind as the file writes
                it, MATRIX_DIM <n> MEASUREMENT, or (none) when the header gives no kind · <address> the address as 0x and upper-case hexadecimal digits, -0x… when negative · <length> the length as a decimal integer · <method> the conversion method the object
                names · <type> the record's conversion type, or (none) · <table> the
                COMPU_TAB_REF word, or (none) · <mask> the BIT_MASK word as the file writes it ·
                <other> the name of the other object ·
                <lower> <upper> <elower> <eupper> the limits and extended limits as the file
                writes them; a side whose word is not a number, or is a number that is not finite, declares no limit and is empty · <text> the operator text · <stored> the
                display text of the decoded value · <raw> the stored value as an integer text
                when it is integral (finite and float.is_integer() is true), else its 15-significant-digit text.
```

Terms reused from S2 without change: CTX-A2L-TAG (address, length, datatype, record layout, byte order, conversion method, unit, limits), CTX-A2L-VALUE (tag span, raw bytes, raw value, physical value, conversion error, the conversion methods), CTX-A2L-FILE (CHARACTERISTIC kinds, quoted string, comment). Context-note change proposed for the fold-in (`E1-rulings.md` §2): CTX-A2L-VALUE's TAB_VERB line gains "or a COMPU_VTAB_RANGE of raw ranges → text" (D-4 A).
