## Issues

1. **Unsupported RED citations (6 rows) — the four encode-arm cases are also vacuous on the stub.** `.58.1/1`, `.58.1/2` (rows at `02-test-cases.md:220-221`), `.19/7` (:78), `.58.2/12` (:233), `.58.2/14` (:235), `.58.2/15` (:236) all claim "RED on cb083d07 (`int2b-red-stub-final4-main.txt`)", but none of these test names appears in that transcript's failure list; the run collected the same 308 tests as the GREEN run, so **all six passed on the RED stub**.
   - *Why they pass on the stub:* `.58.1/1`/`.58.1/2` (`tests/test_b103_a2l_definition.py:3518,3526`) and `.58.2/12`/`.58.2/14`/`.58.2/15` (`:3471,3485,3492`) accept any non-mutating `Refusal` outcome (`isinstance(res, (Encoded, Refusal))`, plus a no-mutation compare) — a stub that refuses every encode satisfies them. They cannot produce a discriminating RED, contradicting both the cited transcript and the handoff's "no vacuous assertions" rule (`E4-handoff-tests-2b.md:9`).
   - `.19/7` (`:2473`) makes no `encode_definition` call at all; its check is describe-time (`BO: its byte order cannot be read`), i.e. 2a logic that already passed on the stub. As a "2b residual guard" it tests no write-side behavior.
   - *Fix:* correct the six Result cells (these arms' first honest execution is the GREEN run; the `.58.1` encode arms need a discriminating assertion, e.g. that at least one defined object encodes to the expected bytes, before any RED claim), or produce a per-arm RED transcript that actually shows them failing.

2. **`.55/1` claims inputs the test never builds (coverage overstatement).** The ledger's Inputs describe the masked grid — "the integer datatypes also with a multi-bit and a one-bit mask: 0x0FF0 and 0x0001, UBYTE 0x0F and 0x01" — and "≥ 2 typed decimals" per object, with expected clauses "0 refused for precision among those taken from decoded stored values; 0 refused among typed decimals". `test_r_a2l_definition.py:2975` has **no BIT_MASK anywhere in the grid and no typed decimals**: it round-trips only the decoded display text over 3 methods × 5 datatypes × 2 orders × 4 formats × 5 samples (600 accepted, ≥ 300 asserted — the count itself is non-vacuous). Masked writes are covered elsewhere (`.46/1`–`/4`, `.47`, `.138`), but this row's own ledger text does not describe its test. *Fix:* either add the masked objects and typed-decimal arm to the test, or trim the row's Inputs/Expected to what the test asserts and adjust `full`.

3. **`AT-B103-I2-2` write arm is narrower than its `full` mark.** The row's Expected says "each object of the case: build, decode, encode its planned value's text and a second value"; `test_at_b103_i2_2_write_arm_encodes_planned_then_a_second_value` (`tests/test_b103_synth_definitions.py:340`) encodes only the four `_SCALAR_DEFC` objects. The DEFC case also holds AXIS_PTS/curve/array objects (its `_defc_decode` branches on them), whose write arm is not exercised. *Fix:* mark the 2b arm `partial` (or extend the test if the intent is whole-case coverage) and say "each scalar object".

4. **Stale/incorrect ledger details (test is authoritative and passes; column edits only).**
   - `.26/4` (`:113`): Inputs/Expected name the ASCII object "`UNKNOWN`" and message "`UNKNOWN: 42 of its 42 bytes…`"; the test uses the re-derived parser name `ASAM.C.ASCII.UBYTE.NUMBER_42` (constant at `tests/test_b103_a2l_definition.py:247`). Stale pre-re-derivation text.
   - `.44/1`, `.44/2` (`:180-181`): Preconditions say "image 00 at 0x810004"; the SBYTE object is at 0x810001 and the tests image 0x810001 (`:2726,2736`). The stated precondition would trigger `A2L-DEF-BYTES`, not the notice.
   - `.44/2` and `.43/4` (:2713, :2733): the ledger says the case "first asserts the overlap" (an `A2L-DEF-OVERLAP` refusal at encode); the tests assert only `d.shared_with == …` (describe state) and never encode on the uncleared definition (.44/1 does assert the refusal; .43/4/.44/2 do not). Wording overstatement.
   - `.56/1` (:214): "every V171 entry-text encode before the clearing refused `A2L-DEF-OVERLAP`" — the test checks the first entry per table only (3 overlap assertions), then encodes the rest on the cleared definition directly. Minor.
