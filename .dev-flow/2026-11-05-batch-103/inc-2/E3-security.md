## Answers to the questions routed to E3

- **E2-10 (describe cost):** rule **A**. The module keeps no state and no cache, so it cannot hand out a stale definition. The availability risk moves to Inc 6, whose E1 must state that it never describes every row of a large A2L on the UI thread (≈ 14 000 × 20 ms).
- **E2-11 (how a masked encode avoids the whole-word write):** the reading is **confirmed**. Calling the reused encode on a mask-free tag view gives only the stored value; `_merge_bit_mask` writes `(word & ~mask) | (field << shift)` after the fit check; step 5's bytes are never the result. Keep R-A2L-DEF.46/1 neg and AT-B103-I2-1's "every bit outside each write's mask unchanged". On its own it does not close BL-I2-1; with E3S-01 it does.
- **E2-12 (a BIT_MASK word that is not a number):** **fail closed** (E3S-01, fix 1). "Drop it" leaves the whole-word write reachable.
- **E2-13 (`<kind>` with no header kind):** `(none)` is accepted, and has no security impact.
- **E2-14 (slice deviations):** accepted. Add `MAX_A2L_DECODE_BYTES` to the import list (E3S-02); it is public, so the rename guard does not need it.
- **D-4 (the COMPU_VTAB_RANGE upper end):** no write-path impact. The encode writes the entry's min, which lies inside the range whichever way the max is read. Every tracked range table is integer, and the ASAM demo (`examples/case_00_public/ASAP2_Demo_V161.a2l:2555`) carries no note on the max. Have the row state the rule the system applies (both ends included).
- **D-12 (texts):** the texts echo file words, which is E3S-04. The em dash and the `'<text>'` quoting are fine.
- **Synth:** confined to test data. `git grep "make_release_case\|tools.synth" -- s19_app` is empty. Case 08 is untouched: `release` runs the old body, `build_definition_objects` draws from its own `Random(seed)`, and R-A2L-DEF.59 pins the 22 digests. One collision remains (E3S-12).
