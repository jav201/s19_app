## I-1 — one copy, one write, one notice

Owners: `app.py` (group A) and `os_clipboard_input.py` (group B).

- `S19TuiApp.copy_to_clipboard(text: str) -> None` stays synchronous like Textual's method. Bind the real exception with `from textual.actions import SkipAction`. If `text == ""`, it executes `raise SkipAction` before constructing a coroutine or worker; a missing import or `NameError` is a RED implementation defect. Otherwise it schedules `_mirror_and_write_os_clipboard(self, text)` exactly once with the original, untruncated text. It does not call `super()`, call `write_os_clipboard`, truncate, sanitize or notify.
- For a representable payload, the existing async tail remains the only owner of the OS write and result notification. It preserves the original text length, caps at 65,536 characters, calls the toolkit base `App.copy_to_clipboard` exactly once and runs `write_os_clipboard` exactly once in the executor. Success produces one information notice; truncation substitutes the cut notice; failure keeps only the existing warning. Text-box copy/cut continues to enter this tail directly, never through the override.
- **R-COPY.25, consumed tail contract:** if the already capped payload contains U+0000, the tail fails closed before the base mirror or writer. Base call/writer/OSC 52/process/success-notice counts are all zero, both clipboard seeds remain unchanged, and no success or cut notice is emitted. The only notice is one 6-second warning with exactly `Clipboard copy refused — NUL cannot be represented in the Windows text clipboard.`; the fixed WARNING is exactly `OS clipboard copy refused; payload contains NUL`, with no payload or payload prefix in logs. If NUL occurs only after character 65,536, the capped prefix contains no NUL and follows the ordinary capped-copy route: one base call, one writer call, one OSC 52 request and one cut notice retaining the original total. Group B owns the tail internals; group A only passes the original text through.
- NUL is the narrow representability exception, not a general sanitizer. Other C0 controls, ESC, LF and markup-like text remain unchanged in the copied payload; no replacement with U+FFFD or markup stripping is permitted.
- `_copy_notice_text(text: str) -> str` is a pure helper **in `os_clipboard_input.py`**, avoiding an import cycle with `app.py`. It returns `Copied 1 line to the clipboard.`, `Copied <n> lines to the clipboard.`, or `Copied the first 65,536 characters to the clipboard (<N> in all).`. Line feeds plus one determine `<n>`, except that a final line feed is not counted; `<N>` is the original, grouped character count.
- No import from `app.py` into `os_clipboard_input.py` is permitted. Existing public names and clipboard constants keep their contracts.

## Copy gestures and quit

Owner: `app.py` (group A).

- N3 owns exactly one new private transient attribute, `S19TuiApp._right_gesture`, containing `text`, `screen_offset`, `screen`, `widget` and a `valid` flag. It is gesture state, not session-action state and not another function node.
- Every not-forwarded `MouseDown`, regardless of button, first replaces or clears any prior candidate. On button 3 only, before toolkit dispatch, N3 captures the N2 text snapshot plus the press's `screen_offset`, current screen and widget; it never calls N1 on the press. N2's existing upfront `OsClipboardInput`/`CappedTextArea` type-or-ancestor exclusion remains the first selection/name read, preserving the text boxes' own direct route.
- Any `MouseMove` whose `screen_offset` differs from the captured offset sets `valid=False`, permanently for that candidate even if the pointer later returns. Every not-forwarded `MouseUp` consumes and clears the candidate before any possible N1 call. N1 is called once only for button 3 with a valid, non-empty candidate and identity/equality of the press/release `screen_offset`, screen and widget; a replayed or forwarded release cannot copy again. Every mouse event, including invalid, cancelled, forwarded and non-button-3 events, finishes with exactly one `await super().on_event(event)`. Back-to-back press/release therefore copies the pre-dispatch snapshot once on release before toolkit forwarding clears the selection.
- An empty Ctrl+C copy raises `SkipAction` from N1 rather than returning normally. While idle it continues to `action_help_quit` and opens exactly one body-B dialog, with zero clipboard/worker/notice effects and both seeds unchanged while open and after `n`. Beneath a modal screen the same exception produces no app fallback: the original modal remains, no N9 or second dialog opens, and both seeds remain unchanged.
- `S19TuiApp.BINDINGS` pins `('q', 'help_quit', 'Quit')` in `app.py`, replacing `('q', 'quit', 'Quit')`. Ctrl+Q and command-palette Quit continue to invoke `action_quit`, so either quits immediately while idle; their busy behavior remains governed by R-QUIT.1.
- `S19TuiApp.action_help_quit` is shared by `q` and the toolkit Ctrl+C fallback: with a running session action it opens the existing busy quit question under R-QUIT.1; otherwise it opens `_CopyQuitScreen`. Thus idle `q` opens the quit dialog with a selection present or absent, while the Ctrl+C fallback opens it only with nothing selected. Both questions use `_answer_quit`. A modal screen's binding chain keeps `q` and Ctrl+C from opening another dialog.
- `_CopyQuitScreen(_QuitQuestionScreen)` lives beside `_QuitQuestionScreen` and inherits its bindings, focus, plain-text labels and answer guard. Current G2 r2 and these interfaces both fix body B: `Quit the app? Nothing is selected to copy.` Title/buttons remain `Quit?`, `Quit (y)`, `Stay (n)`. They also fix q=B / O-1=B: idle `q` opens the quit dialog, idle Ctrl+Q and palette Quit quit immediately, and busy behavior remains R-QUIT.1. No interface supersession is needed for these aligned choices.
