## P-002 — teardown race `NoMatches '#a2l_tags_list'`

Failing nodes (WinCI only, intermittent):
- `test_b103_clipboard_windows.py::test_r_paste_17_no_powershell_starts_nothing[read]`;
- `::test_r_paste_5_win_no_selection_keeps_os_clipboard`;
- `::test_r_tui_043_10_1_5_6_no_text_no_powershell[single]`.

**Cause.**
- Each test pastes or copies in `#a2l_tags_filter_input`. The input change schedules the 0.15 s filter debounce (`_schedule_a2l_filter_refresh`).
- The test then leaves `run_test`. `App._shutdown` sets `_running = False` and prunes the default screen. A debounce that comes due in that window runs from `_flush_next_callbacks`.
- `_apply_filter` → `_refresh_a2l_filtered_tags` → `update_a2l_tags_view` then calls `query_one('#a2l_tags_list')` on the pruned `Screen(id='_default')` and raises `NoMatches`. `run_test` re-raises it as the test's failure.
- On a slow 2 vCPU runner the teardown takes long enough for the timer to come due; on Linux it rarely does. This is a product robustness defect: the callback has no guard for a closed app.

**Requirement and case** (trace US-103-01 → R-COPY.26 → R-COPY.26/1):
- `01-requirements.md` **R-COPY.26** (If form): "If a pending A2L filter refresh comes due after the app has stopped running, then the system shall drop that refresh without an error."
- `02-test-cases.md` **R-COPY.26/1** → `tests/test_b103_a2l_filter_teardown.py::test_r_copy_26_1_filter_refresh_due_after_teardown_is_dropped`.
- Code → R: `S19TuiApp._schedule_a2l_filter_refresh` docstring, Data Flow, cites R-COPY.26.

**Regression (deterministic, no timing).**
- A spy on `app.set_timer` captures the `_apply_filter` callback that the real input change schedules, and does not schedule it.
- The test runs the callback while the app runs. This is the positive arm: the summary must read `No A2L tags match 'KEEP'.`.
- After `run_test` exits, the test checks the WinCI state: `is_running` is False and `query_one('#a2l_tags_list')` raises `NoMatches`. It then runs the callback again, which must raise nothing.

**Fix.** In `_apply_filter`, after the token check: `if not self.is_running: return`.
- `is_running` is the message pump's public flag. `_shutdown` clears it before it prunes any screen, so every teardown that can remove the table is covered.
- No exception is caught; `update_a2l_tags_view` is unchanged.

**Main-loop stall sampler** (`tests/test_b103_clipboard_tail.py`, `_StallSampler`), on /101 … /103, C1 and C2:
- A daemon thread. The marked writer starts it right after it stamps `t_start`, and stops it when it stamps `t_end`. Nothing runs outside the write window.
- Every 20 ms it reads the last tick of the existing tick trace. When no tick has run for more than 150 ms, it captures the loop thread's stack: `sys._current_frames()[loop_ident]` → `traceback.extract_stack`. That is once per stall, at most 3 captures, each trimmed to the innermost 12 frames.
- Frames are written as `module:function:line` only. The module is dotted and relative to the repo, site-packages or the stdlib, or else the file's base name. No path, payload or source line appears.
- It also records its own largest wake gap (`sampler_max_wake_gap`). If that gap is well above 20 ms, this thread could not run either: the GIL was held in C code, or the process was not scheduled.
- Cost: one GIL acquisition every 20 ms, plus about 1 ms per capture, and a capture happens only once a stall already exceeds 150 ms. `lateness`, the window and the ticks are computed exactly as before.

**GC timeline.** A `gc.callbacks` hook records start/stop, the generation and whether the collecting thread is the loop thread. It is installed before the gesture and removed after the window. The report lists collections that start inside `[t_start, t_end]`: the count and seconds per generation, and the 5 longest as start/duration.

**Asyncio slow-callback info: skipped.** `loop.slow_callback_duration` reports only in debug mode, and debug mode changes the loop's cost.

**Pilot `Callback` per 100 ms:** kept as it was (`callbacks_per_100ms`).

All of this is appended to the existing failure message: ` | gc_in_write … | sampler_max_wake_gap=… | loop_stalls>0.15s=[…]`.
