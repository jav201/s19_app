## Reglas de ejecución y baselines

Cada fila es **un único mutante**: aplicar sólo el cambio indicado sobre una copia limpia de `287b9dc3c5e18614ea50a053ef183d80dac59dfc`, nunca combinar dos filas y nunca mutar el árbol de integración. Los grupos delimitan baseline y copias; cada `<grupo>/<id>` requiere su propia copia del árbol.

- **L — baseline Linux, para GA/GT/GQ/GC/GN.** Host Linux headless con `DISPLAY` y `WAYLAND_DISPLAY` sin definir, HOME/tmp aislados y los recorders de clipboard de los propios tests. El runner ejecuta la batería completa **una sola vez por grupo**, en su copia pristine del hash y entorno fijados; no la repite por mutante. La batería `tests/test_b103_copy_views.py tests/test_b103_clipboard_tail.py tests/test_b103_copy_quit_dialog.py tests/test_b103_copy_paste_matrix.py` debe dar **123 passed + 19 skipped** (de **142 nodos**): 14 P2 WinCI + AT-I1b-8 manual + R-PASTE.13/101 + R-PASTE.14/101–103. Es un criterio de admisión, no un resultado declarado aquí. Un skip adicional o distinto, un fallo o una colección distinta invalida el baseline. En cada copia independiente, todos los node IDs objetivo también deben pasar inmediatamente antes de aplicar el mutante.
- **W — baseline WinCI, sólo para GW.** `windows-latest` GitHub-hosted, probe de clipboard aislado superado, seed y lectura mediante procesos separados. El test objetivo y su holder/reader deben pasar sin skip antes de mutar. L no sustituye W; un skip en W no es un mutante muerto. El runner Linux rechaza estas cuatro filas.
- Después de mutar, ejecutar únicamente los node IDs nombrados con el mismo entorno y timeout externo. Veredictos: **KILLED** = uno o más tests fallan por assert, sin errores ni skips; **SURVIVED** = todos pasan; **CRASH** = error, fallo de colección del mutante, señal o timeout, sin convertirlo en kill; **BAD** = parche no aplicado exactamente una vez, selección inválida, skip, baseline inválido, restore incorrecto o fallo del harness. Un fallo ya presente en baseline nunca cuenta como kill. No reclamar equivalencia de un SURVIVED sin análisis.
- El runner debe restaurar los bytes originales y comprobar SHA-256 después de cada intento, incluso tras CRASH/BAD. Ejecuta Python con `-B`, `PYTHONDONTWRITEBYTECODE=1`, caché de pytest deshabilitada y stdin cerrado; cualquier bytecode nuevo invalida el intento. El objetivo vuelve a pasar tras el restore o el resultado es BAD.
- Para **GC-C14** (reentrada), son obligatorios una cota externa concreta de tiempo **y workers/iteraciones**, captura de cardinalidad `override/tail` al alcanzarla y cancelación del árbol aislado. Un timeout desnudo es CRASH/inconcluso, no kill. **Queda pendiente y no ejecutable** hasta disponer de esa instrumentación; el runner lo rechaza como BAD sin aplicar el parche.

Estas exclusiones **no cuentan entre los 73 mutantes**. No se les asigna un test que deba morir porque el oráculo actual no lo garantiza.

1. **MouseMove reenviado: sólo exit-return discrimina GA-A10.** `_right_drag` marca reenviados los moves, no el release (`tests/test_b103_copy_views.py:308-332`). En R-COPY.11/5 y R-COPY.13/7 el release ocurre en otro offset (`tests/test_b103_copy_views.py:626-640`, `:781-795`), por lo que el mismatch de offset ya impide copiar incluso con el guard reintroducido. El brazo que realmente mata GA-A10 es R-COPY.13/8, A→B reenviado→A→release. No presentar los demás brazos como prueba independiente.
2. **Forwarded MouseUp no tiene brazo.** El único `_set_forwarded()` se aplica a MouseMove; MouseUp se publica sin marcar (`tests/test_b103_copy_views.py:317-330`). Quitar `not event.is_forwarded` del bloque MouseUp de `app.py:23351` no tiene muerte garantizada, pese al control de `codewire/graph-inc1b.md:222`.
3. **Mismo offset con screen/widget distinto falta.** El grafo lo exige en `codewire/graph-inc1b.md:221`; el test de reentry sólo cambia A/B por offset y luego repite release en el mismo contexto (`tests/test_b103_copy_views.py:666-690`).
