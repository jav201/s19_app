## F-2 — `1F F6` vs `1F F7` (hand arithmetic)

- current: field = (0x1AE7 & 0x0FF0) >> 4 = 0x0AE0 >> 4 = 0xAE = 174; bit = 0x1AE7 & 0x0001 = 1 (the capture's Current `174 (0xAE)`, `1 (0x01)`).

CAP8's state has both staged in one ledger entry, so the strip's `word 1A E7 → 1F F6` (sidecar: `bit 15…0 0001111111110110   word 1A E7 → 1F F6`) is right; the code is right; the requirement rows and their examples are right. ## F-5 — cells run into the next column (as designed; proposal)
The bound is CTX-PE-DEF `column widths` with R-PE-DEF.6 (start of each cell = sum of the widths before it), R-PE-DEF.7 (no painted line wider than the sheet) and R-PE-DEF.15 (the name clipped to the Parameter column). The clip rule is "a cell wider than its column shows the longest start that fits in the column's width − 1 cells, then one `…`", so a clipped cell, and an unclipped cell exactly as wide as its column, fill the column to its last cell and abut the next one. The approved examples pin this: R-PE-DEF.15 `ASAM.C.ASCII.UBYT…` (18 cells, Parameter 18 at W = 118) and R-PE-DEF.7 `温度温度温度温度…` (17 cells of 18) and `温度温…` (7 of Unit 7). The code (`_fit`: cut with `…` or pad to exactly `width`) follows. Capture cases: `longmsg` New 13 = 12 × `x` + `…` then Unit `deg C`; `text` Parameter `ASAM.C.ASCII.UBYT…` then Kind `ASCII`; `narrow-edit` W < 100, Parameter 16 holds `VAL_BLK_DEF_0001` (16 cells, not clipped) then Current `6 values`. Changing it changes the approved layout (DF-09), so it goes to the operator with the capture verdicts. **Proposal:** one gutter cell per column — a cell takes at most width − 1 cells (clip to width − 2 + `…`) and the last cell is always a space; examples change to `ASAM.C.ASCII.UBY…` (17 + gap) and the CTX widths stay.
