# Inc 8 E5 captures (CAP8): real Windows Terminal, full colour

Branch `b103-inc8` (base tip 7ac47dc5). Method: `evidence/captures/capture_i8.ps1` + `capture_i8_driver.py` (adapted from Inc 1b's `capture_i1b.*`); `run_all.ps1` runs the matrix. Each PNG is one real Windows Terminal window (new window, unique title, `--size`), truecolor (`NO_COLOR` removed), `python -I -B`, isolated HOME/XDG/LOCALAPPDATA, OS clipboard and OSC 52 stubbed. The driver reaches each state through the app's own key handling (`App._press_keys`, the path Textual's pilot uses) and writes a `.png.txt` sidecar with the state actually reached (status lines, painted sheet text, focus).

## Operations notes
- Windows: each capture window exits by itself (the driver exits 0 when the launcher releases it; fallback is stopping the launcher PID tree). One leftover window from my first run (the first script version stopped the shell with a nonzero exit, which left the tab open) was closed once with WM_CLOSE, found by its unique GUID title; this deviates from "by PID" because the operator's window shares the same WindowsTerminal process, so a process kill was not possible. No other window was touched. Final check: no window of mine remains.
- Early runs of `text/curve/array/refused/bigtext` failed on selectors; the re-runs overwrote those PNGs.
- No test run, no `__pycache__` (python -I -B), LF only.

Rulings on V-2, V-7, V-9, V-11 `status-overlap` and the column run-in: `E5-capture-facts.md` (D8: 0 defects, no capture re-taken).
