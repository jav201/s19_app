## Common fixtures

**Platforms.**
- **WinCI** — the Windows job (`E1-rulings.md` D-6) on a GitHub-hosted runner. Every WinCI case first passes the isolation guard (R-PASTE.21) and is skipped by the probe rule when the probe fails (R-PASTE.22). **Blocked until** a branch is pushed (operator approval) and the probe passes.
- **LinuxH** — <runner> headless or the `ubuntu-latest` CI job: `DISPLAY` and `WAYLAND_DISPLAY` unset (the test asserts it), no OS clipboard reachable. Runs now.
- **LinuxX** — <runner> with a private Xvfb display started by the test session (`-nolisten tcp`, a private auth file) and `xclip`. **Blocked until** the operator installs `xorg-server-xvfb` and `xclip`.

**Apps and boxes.**
- **Real app** — `S19TuiApp(base_dir=<tmp>)` under `run_test(size=(160, 48))`; `LOCALAPPDATA` isolated by `tests/conftest.py`.
- **Box A** (single-line) — A2L Explorer `#a2l_tags_filter_input` (rail key `2`). **Box M** (multi-line) — Patch Editor `#patch_paste_text` (rail key `6`, its JSON tab chip). **Box A'** — A↔B diff `#diff_path_a` (key `7`). **Box M'** — Split / Join / Export `#sje_manual` (its opener, `S19TuiApp.action_open_split_join_export`). A box gets the focus by a click on it (`pilot.click`), not by `.focus()` (tui-design NAVIGATION: `.focus()` is not evidence that a box can be reached).
- **Select** — single-line: `end`, then `shift+home`; multi-line: `f7` (select all) or `shift` + arrows for a part.
- **Clear** — select, then `delete`.
- **Box 1 / Box 2** (addendum) — a one-box app (the shape of `evidence-e1/i1a-pilot4.py`): a Button `#other` and one `OsClipboardInput` (Box 1) or `CappedTextArea` (Box 2) with at least 20 content cells. **Select by keys**: Box 1 `home`, `shift+right` × n; Box 2 `ctrl+home`, `shift+right` × n. **Unfocus**: a click on `#other`.
- **Right-click** (addendum) — `pilot.click(<box>, offset=<cell>, button=3)`: Pilot posts `MouseDown`, `MouseUp` and `Click` with button 3 to the screen and bypasses `App.on_event` (textual `pilot.py:196-250`, `:384-470`). **Right-click (App route)** — `MouseMove` (button 0), `MouseDown` and `MouseUp` (button 3) posted to the App as the driver posts them, back to back with no pause (at least for R-PASTE.26 and R-PASTE.29/2, /4; E3A-11 d); `App.on_event` makes the `Click` (textual `app.py:4060-4117`). Both deliver the same three events to the box (B, pilot4 P12); the matrix, walk and timing cases use the App route. "Right-click on `x`" puts `<cell>` on the character `x`. In the real app at 160×48 with no A2L loaded, Box A is 6 cells wide with 0 content cells (B, pilot4 P16): its cases click at offset (2, 1), and the cases that test where a paste lands use Box 1 / Box 2.

**Clipboard helpers (only after the isolation guard).**
- **Other-program write / read** — a separate system PowerShell process: `Set-Clipboard` with the text on stdin as UTF-8, or `Get-Clipboard -Raw` with UTF-8 output. It stands for "another Windows program".
- **Own read** — the test process detects the end of a copy by `GetClipboardSequenceNumber()` changing (opens nothing), then one read to confirm the text (E3A-11 b).
- **Own write** — the test process writes a `CF_UNICODETEXT` with its own Win32 code, in UTF-16, so a lone surrogate survives (a PowerShell `Set-Clipboard` fed UTF-8 on stdin cannot carry one; E3S-16 c).
- **Held clipboard (t)** — a helper process that opens the Windows clipboard and keeps it open for t seconds (8 s unless the case says otherwise), started and confirmed holding before the key.
- **Held clipboard (until PowerShell start)** — a helper process that opens the Windows clipboard and releases it only after the Process spy records the system PowerShell start, so the rescue is reached without racing the key dispatch, then finds it free (E3A-06).
- **Empty Unicode text** — the test process writes a `CF_UNICODETEXT` of zero characters.
- **X seed / X read** (LinuxX) — `xclip -selection clipboard -i` / `-o` on the private display.

**Route and measurement helpers.**
- **Terminal paste (text)** — `app.post_message(events.Paste(text))`: to the App, as Textual's driver posts it (the App forwards it once to the focused box). Never posted to the box itself: a multi-line box then gets it twice (B, pilot P6 against pilot3).
- **Typed-key time** — 10 warm presses of `a` into the cleared box (2 discarded first), median from the press to the first 5 ms poll of the box's value that holds `a` (pilot2 L1 shape; E3A-11 a).
- **End of a paste / copy** — the clock starts just before the key; it stops at the first 5 ms poll of the box's value that holds the expected text / the `GetClipboardSequenceNumber` change / the notice (E3A-11 a).
- **Tick lateness** — a 50 ms interval timer set on the screen before the key; lateness = actual time − due time of each tick; at least 10 ticks due after the read or write has started (a pass-through marker at `read_os_clipboard` / `write_os_clipboard` entry), in the one-box app (Box 1 / Box 2); a vacuous run fails (E3A-11 c).
- **OSC 52 spy** — a pass-through wrapper on `app._driver.write` that keeps every `ESC ] 52 ; c ; <b64> BEL` and decodes it.
- **Process spy** — a pass-through wrapper on process creation that records each program path and then starts it unchanged.
- **Notices** — the toasts the app shows, read with their text, severity and timeout.
- **Log capture** — a handler on the `s19_app` logger at DEBUG, records kept as (logger, level, message).
- Timing cases are `@pytest.mark.serial_timing` arms; every bound goes through `tests/support/timing.timing_bound` (×2 on CI) and `report_margin` (R-TST-002, R-TST-040/041).

**Payloads.** P1 = `COPY-1 Ñoño Ж 漢字 😀` (one line). P2 = `L1 Ñ€\nL2 漢` (two lines). P1000 = one line of 1,000 characters (`0123456789` × 100). P70k = 70,000 × `x`. `APP-TEXT`, `BEFORE`, `OS-BEFORE`: markers. P-CTRL = `"A\x1b[13DB\x00C\u202e\uD800"` (`A`, ESC, `[13DB`, NUL, `C`, U+202E, a lone surrogate): a single-line box's value after the strip is `A[13DB\x00C` (code points are removed, not whole sequences; the NUL is kept, as it is not an unsafe paste character, E3A-25). P-CTRL-W = P-CTRL without its NUL, for the WinCI arms, written by Own write (a `CF_UNICODETEXT` read ends at the first NUL): `A[13DBC`. P-CTRL-L = `"L1\x1b[2J\nL2"`: a single-line box gets `L1[2J` (the first line taken, then stripped). P-CTRL-M = `"A\x1b[13DB\x00C\tD\r\nE\u202e\uD800"`: a multi-line box's document lines after the strip are `["A[13DB\x00C\tD", "E"]` (the NUL, the TAB and the line end kept); P-CTRL-MW = P-CTRL-M without its NUL, by Own write: `["A[13DBC\tD", "E"]`. P2-ESC = `"L1 \u00d1\u20ac\x1b[2J\nL2 \u6f22"`: lines `["L1 \u00d1\u20ac[2J", "L2 \u6f22"]`. Every strip oracle reads the box's value (`value`; `document.lines`), never the drawn line: the renderer adds its own style sequences, so every drawn line holds ESC (E3S-16).

## Every window: the walk (one round trip per place)

Each walk case: open the place by its own key or control; click the box; Clear; type `W<n>-` + P1 (single-line) or `W<n>-` + P2 (multi-line); Select; `ctrl+c`; check the copy (WinCI: Other-program read equals the text; LinuxH: the app clipboard equals it) — this check is the place's case of R-PASTE.19/2; Clear; `ctrl+v`; the box holds the text again (single-line: the one line).
