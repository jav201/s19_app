## Questions routed to E3, and the lens of the brief

- **E2-1, E2-2, E2-5:** E3S-09, E3S-10 and E3S-08.
- **Process execution.**
  - The system folder: `_system_directory` uses `GetSystemDirectoryW` and reads no `SystemRoot` or `PATH` (`graph-inc1a.md:362`). Correct.
  - The command line: an absolute `argv[0]`, with `shell=False`. CreateProcess searches only for a name without a path, so the application folder (venv `Scripts`), the current folder and `PATH` are all out of play. `list2cmdline` quotes a system folder that has spaces. R-PASTE.16/1's assertion on `argv[0]` is the oracle that covers every search location. /3's decoys cover two of them.
  - Timeouts and kill: E3S-11. Stdout cap: E3S-04. Stderr: E3S-06.
  - Encoding: UTF-8 both ways, and Python writes no BOM. A BOM on PowerShell's stdout would arrive as U+FEFF, and R-PASTE.16/1's exact compare (`PS-READ`) would catch it. Keep that compare exact.
  - Payload: on stdin, never in the command line. Good.
- **Win32 path.**
  - Held clipboard: the retries are bounded (5 × 20 ms). A null from `GlobalLock` gives `None`. Size and terminator: E3S-04.
  - Caps: every route is cut before the box inserts the text — the terminal paste in both classes, Ctrl+V and right-click (OS and fallback), and every copy. The cut comes after the whole OS text is in memory (E3S-04). `#load_path` keeps its refusal of more than 4,096 characters (R-TUI-044.2/5).
- **Pasted content: E3S-01.**
  - File names: project and flow names go through `sanitize_project_name` (alphanumerics, `-` and `_` only; `workspace.py:2133-2136`).
  - Paths: `#load_path` refuses control characters. `#diff_path_a`, `#flow_external_path_input`, `#report_filter_path` and `#operation_config_path` accept NUL and ESC today. E3S-01 covers them.
  - Markup: the box itself parses none (`Text(value)`). Labels and notices are covered by the existing guards. The open sink is the terminal stream, not markup.
- **Copy side.**
  - OSC 52 carries base64 of UTF-8, so no byte of the text reaches the terminal raw. A request is at most 349,528 characters for 65,536 four-byte characters. A lone surrogate gives no request (E3S-01's helper removes it).
  - The app clipboard lives in memory only.
  - Logs: the WARNING texts are fixed, and the DEBUG lines give lengths only (`:654-656`, `:713-715`). A codec-error DEBUG line can name one character; that is acceptable. The notices are constants.
- **Right-click:** E3S-09 and E3S-12. No field submits on a paste. A disabled box gets no paste.
- **CI:**
  - `permissions: contents: read`, `persist-credentials: false`, no secrets and no artifact: correct.
  - The run lines interpolate nothing, so `_script_injections` returns `[]` on the pinned text. There is no `pull_request_target` or `workflow_run`.
  - Pins and forks: E3S-07. Tags: E3S-08.
- **Tests never touch the operator's clipboard:** E3S-02 (scope) and E3S-03 (predicate).
  - Removing Tk removes the product's last X-clipboard code, so on Linux only the test helpers can reach a clipboard, and the X kind of the guard covers them.
  - On the operator's PC, WSLg's display is refused both by that kind (it is not the session's own Xvfb) and by the LinuxH assert that `DISPLAY` is unset.
