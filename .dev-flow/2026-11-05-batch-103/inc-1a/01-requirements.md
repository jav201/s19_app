## User stories

### US-103-01 — copy and paste work in every window, and a paste lands at once (operator story 1)
Copy and paste work in every window. Text copied from any part of the TUI can be pasted into any text field of the TUI and into other Windows programs, and a paste lands at once. (Operator source: story 1 — Workspace, A2L, Load under Windows 11/PowerShell; note of 2026-11-05: "escenarios de copiar texto desde varias partes de la TUI y pegado a las ventanas de texto disponibles en la TUI".)

Inc 1a takes the part of US-103-01 whose copy source is a text box: the paste lands at once by both paste routes, a copy from a text box reaches the OS clipboard and the app clipboard, and every window and dialog that holds a text box does both. Copy from views that are not text boxes (the read-only Patch document, the hex view, the A2L summaries and tag table) is Inc 1b. Under the operator's ruling of 2026-11-06 (Ctrl+C is the terminal's quit key, not the general copy key), a right-click in a text box copies the selection it shows, or pastes when it shows none: a second way to copy and a third paste route beside Ctrl+V and the terminal paste. Ctrl+C keeps copying a selection; with none it is passed on to the app, whose quit confirmation is Inc 1b's.

## Definitions (additions and changes to CTX-PASTE, S7.3; terms and formats only)

- **OS clipboard** (CTX-PASTE, changed). The Windows clipboard: text copied in another Windows program. On other operating systems there is no OS clipboard in the sense of these rows (decision D-2; S7 rows that read or write the OS clipboard meet their `If` rows there).
- **terminal paste** (CTX-PASTE, changed). A paste the terminal sends itself: Ctrl+Shift+V in Windows Terminal, Ctrl+V where the terminal binds Ctrl+V to its own paste (F §1.4 F2: the operator's Windows Terminal 1.24 settings do), and a Shift+right-click in Windows Terminal when the terminal holds no selection of its own (addendum).
- **right-click** (CTX-PASTE, new; addendum). A press and release of the right mouse button (mouse button 3) over a text box, as the terminal reports it to the system. A Shift+right-click in Windows Terminal is the terminal's own and is not a right-click of the system.
- **selection at the press** (CTX-PASTE, new; addendum). The selection a text box shows just before the right button goes down over it. A single-line box without the focus shows none; a multi-line box shows its selection with or without the focus. So the whole-text selection a single-line box makes when the press itself gives it the focus is not part of it (D-9).
- **cursor at the press** (CTX-PASTE, new; addendum). The cursor position a text box holds just before the right button goes down over it; a box without the focus keeps the position it had when it lost the focus, or the one its text was set with.
- **text box** (CTX-PASTE, new). A single-line box or a multi-line box constructed by the system's windows and dialogs (not Textual's own command palette input, a known exception, E3A-08).
- **selection** (CTX-PASTE, new). The text the operator marked in a text box: with shift and the arrow, Home or End keys, with a mouse drag, with ctrl+shift+a (single-line box) or f7 (multi-line box).
- **unsafe paste character** (CTX-PASTE, new; named so at E3 round 2, E3S-22, so that the canon term *control character* of CTX-TEXT keeps its meaning). In a pasted text: a control character of CTX-TEXT (U+0000–U+001F, U+007F–U+009F) other than NUL (U+0000), a lone surrogate (U+D800–U+DFFF) or a bidi control (U+202A–U+202E, U+2066–U+2069), except the box's keep-set: TAB in a single-line box; TAB, LF and CR in a multi-line box. It is the repository's `_CONTROL_SCRUB` set (LLR-116.7) without NUL, which holds neither the surrogates nor the bidi controls, plus those two ranges, minus the keep-set: one definition for these rows, the cases and the graph (`[Data: _UNSAFE_PASTE]`). NUL left the set at E3 round 3 (E3A-25; ruling: strip only what is dangerous to draw, never silently transform what a consumer already refuses): it starts no terminal sequence (R, ECMA-48; not probed on Windows), and the path consumers refuse it loudly (R-LOADDLG.20, R-FB-ADD.5, R-VAR-002.13), so stripping it would turn a refused path into another path.
- **typed-key time** (CTX-PASTE, new). The median, over 10 presses, of the time from the press of the key `a` in a text box to the first 5 ms poll of the box's value that holds `a`, measured in the same running app and the same box as the action it is compared with.
- **end of a paste** (CTX-PASTE, new). The moment the box shows the pasted text, or the paste failure warning shows.
- **end of a copy** (CTX-PASTE, new). The moment the OS clipboard holds the copied text, or the write failure warning shows.
- **responsive** (CTX-PASTE, new). A screen is responsive when every timer of the screen fires at most 100 ms after its due time.
- **write failure warning** (CTX-PASTE, new). The warning notice "Clipboard write failed — copied inside the app only.", shown for 6 seconds.
- **OSC 52 clipboard request** (CTX-PASTE, new). The terminal sequence `ESC ] 5 2 ; c ; <base64 of the UTF-8 bytes of the text> BEL`.
- **system PowerShell** (CTX-PASTE, new). The program `<system folder>\WindowsPowerShell\v1.0\powershell.exe`, where `<system folder>` is the folder Windows reports as its system directory (`C:\Windows\System32` on a default install; F §1.4 F2).
- **isolated clipboard** (test arrangement, new). An OS clipboard that belongs to no person: the Windows clipboard of a GitHub-hosted runner (environment `GITHUB_ACTIONS` = `true`, `RUNNER_ENVIRONMENT` = `github-hosted`, and the logged-on account `runneradmin`, read with `GetUserNameW`), or the X clipboard of a private Xvfb display that the test session started itself.
- **clipboard probe** (test arrangement, new). One nonce written to the OS clipboard by the test process, then read back by a separate system PowerShell `Get-Clipboard -Raw` process; the clipboard is usable when the read equals the nonce.
- **OS clipboard tests** (test arrangement, new). The test cases of `02-test-cases.md` whose preconditions name **WinCI**.
