## Answers to the questions routed to E3

- **Is there a cap on query length, token count or name length?** No, there is none of the three. Two rows are owed: a query cap (E3S-01) and a name cap (E3S-03). A token cap is not needed if step 4 stops growing with the token count (E3S-01 (c)). The longest real names have 26–27 tokens, and a token cap of 16 would refuse them whole.
- **E2-1 (compact index):** accepted for REF (18.1 MiB, 1.80 s, 62.6 ms). It is not a hostile-input bound, as E3S-03 shows. The 64 MiB row holds for REF only, and that is how it reads.
- **E2-3 (three details):**
  - `repr=False` is right: it keeps 50,000 hostile names out of tracebacks and logs.
  - `LabelMatch`'s generated repr uses `repr(name)`, which escapes control characters, so logging a match by repr is safe. Logging `name` with `%s` is not (E3S-04).
  - `eq=False` (identity equality), checking the query type before the limit, and value equality for `LabelMatch` are all fine.
- **E2-5 (code-point classes):** agreed. The A–Z fold keeps every text's length, and that is what keeps the spans inside the name. `İstanbul_MAP` is the one hostile name whose `str.lower()` changes length. Any Unicode fold turns .4/1's negative control RED.
- **E2-7:** rule a `TypeError` (E3S-06).
- **E2 rulings, "E3 checks the slice mapping" (security lens):** the 8 added functions are all private, in the one new file. None does I/O, touches the clipboard, or imports anything beyond `array`, `bisect`, `dataclasses`, `enum` and `typing`. The rest of the mapping is the architect's call.

## Checked and clear

- **No exception reaches the UI for a `str` query and an `int` limit, except a `MemoryError`** (E3S-01).
  - **Inputs tried:** 3,077 hostile queries × 3 limits over 28 hostile names. The names held markup, ESC, NUL, BEL, CR, combining marks, `İ`, `ß`, `ﬁ`, U+FFFD, a lone surrogate, U+10FFFF, CJK, U+202E, U+200B, U+0663, a tab, spaces, a 300-character name, `_` runs, 100 camelCase humps and 64 digits.
  - **Result:** 21,904 entries, 0 exceptions, 0 mismatches with the E1 oracle, and 0 spans that are empty, out of order, touching, or outside `[0, len(name))`.
  - **Other raise paths:** nothing recurses (the trie build and walk use an explicit stack). `_token_range` handles U+10FFFF. A huge `limit` allocates nothing by itself. A non-`str` input gets the pinned `TypeError`.
- **The ranking does not depend on the hash seed.** With PYTHONHASHSEED 0, 1, 4242 and `random`, the sha256 over 1,005 rankings is identical (`bb102d3c…43fe`). The rankings covered REF (QSET + 300 generated queries), the first 50,000 names of case 06, and the hostile set.
  - No Unicode tables are used (D-2, E2-5).
  - Dicts keep insertion order.
  - Sets hold only ints and are always sorted afterwards.
  - `_order_key` is total.
- **Repeated names:** 50,000 identical names become 1 indexed name, built in 0.7 ms.
- **Isolation:** the module does no file, clipboard or network I/O, and no secret appears anywhere. PKI and signing are out of scope (public repo) and are not proposed.
