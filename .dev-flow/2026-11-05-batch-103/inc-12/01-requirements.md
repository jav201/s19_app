## User stories

### US-103-07 (view half) — an A2L file is shown as it is written (operator report, 2026-11-07)

As the operator, I want every address and length that the A2L Explorer's tag table shows to be the value the file declares, painted whole and apart from its neighbours at every terminal width I use. So I never act on an address painted with an adjacent value, or on a shorter hex string cut at the pane edge.

The operator's words: «las direcciones de memoria a veces se reportan incluso con caracteres contiguos como salto de línea… es un riesgo muy alto tener problemas con lectura de a2l» (`../design/operator-report-a2l-reader.md`). The field case (relayed by the orchestrator, not stored here at the operator's request): the A2L Explorer showed a CHARACTERISTIC's address with four extra hex digits appended, and the Region and Limits cells read as one word.

The reader half of US-103-07 (what the file declares) is Inc 11's. This increment owns what the table paints.

3. **Address and Length first and fixed** keep both whole at every width from 80 to 220 columns, unscrolled 40/40 and scrolled fully right 40/40; today's order gives 13/40 and 0/40; first but not fixed gives 40/40 and 0/40 [F A/B/C SUMMARY].
4. **The Tag cell is then cut unmarked.** With Address and Length fixed, the 36-cell capped Tag cell (a 38-cell column) needs more than the width left: at 80 columns the table's visible width is 38 cells and the fixed columns take 25 of them, so 13 are left; at 118, 60 − 25 = 35 [F A N48 W80], [F A N48 W118]. ## Definitions (changes to CTX-A2L-SCREEN; terms only)

- **tag table columns, in order** (CTX-A2L-SCREEN, changed): Address, Length, Tag, Source, Raw, Physical, InMem, Region, Limits, Unit, Bits, Endian, Virt, Func, Access, Dtype (was: Tag, Address, Length, Source, …). Every column keeps its meaning. R-A2L-006.1 cites this list.
- **Address** (CTX-A2L-SCREEN, changed): the address as `0x` and at least 8 uppercase hexadecimal digits; an address above 0xFFFFFFFF (kept by R-VAL-036) takes as many digits as it needs, at most 16, the bound of Inc 11's R-A2L-READ.69 (E3A-07) (was: "`0x` + 8 uppercase hexadecimal digits", which the code and R-VAL-036 already contradict: `0x1C2D3E004026` is painted with 12 digits, R `app.py:20430`).
- **painted whole** (new): a cell is painted whole when the painted line holds its full text within its column's span.
- **width left** (new): the visible width of the tag table (its content region, without its scrollbar) minus the widths of the Address and Length columns, each width with its two padding cells.
- **name width** (new): the width left minus 4 cells: the Tag column's two padding cells, the in-image glyph and the space after it. Written *w*.
- **painted tag name** (new at E3 round 2, E3A-11; like CTX-TEXT's *painted name*): a tag name with each character outside U+0021 … U+007E shown as U+FFFD (R-TUI-042a.6), then cut in the middle as R-TUI-042a.3 and .5 say. The Tag cell shows it.

**Proposed canon note (CTX-TEXT; written into `REQUIREMENTS.md` at batch end, not now; `E3-rulings.md` "Round 2 rulings", E3A-11; placed at E3 round 3, E3A-23: E5 defines *painted tag name* in CTX-TEXT and writes the exception into the safe-text views list itself, as "the A2L Explorer (detail card; table, its Tag cell showing a tag name as its *painted tag name*, R-TUI-042a.3, .5, .6)", in the way S12's Reports view sits there; no canon row changes):** The Tag cell of the A2L Explorer's tag table shows a tag name as its *painted tag name* (R-TUI-042a.3, .5, .6). It is a scoped exception to R-TUI-103a and R-TUI-103.1: a character outside U+0021 … U+007E is shown as U+FFFD, and the middle cut drops characters. The detail card of the A2L Explorer is no exception: every file-derived value there follows R-TUI-103, R-TUI-103.1, R-TUI-103a and R-TUI-103b (R-TUI-042a.7.1, .7.2), and the card shows the tag's full name (R-TUI-042a.8). Why: the Tag cell is a fixed-width cell for A2L identifiers, and the projection keeps the cut O(*w*); a name holding such a character is already a parse error after Inc 11 (R-A2L-READ.4); 0 of 234,654 tracked names (the 35 tracked files) and 0 of 256,568 corpus names change (E3S-01, E3S [N2]).
