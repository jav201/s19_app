## User story

**US-103-04 — “The Patch Editor uses the same parameter selector as the Check Editor, and the selector reports each parameter's true size and format.”** Inc 6 also delivers the planned Patch bulk include and the safety carry-overs that apply to this read/prefill slice.

## Scope and definitions

- **Declared length:** the tag's `length`, a positive non-boolean integer; anything else is missing. Enriched `byte_size` is a decode-unit value and is never a length source. I-2's `Definition.byte_length` is an independent graph oracle, not a fallback that revives a reader refusal.
- **Format:** `text` for an ASCII definition; otherwise the normalized element datatype: `u8/u16/u32/u64`, `s8/s16/s32/s64`, or `f16/f32/f64`, followed by one space and the A2L unit when non-empty. `BYTE/WORD/LONG` use the unsigned labels. Unknown or absent datatype gives `?`. An array's total byte length never widens its element format.
- **Literal text:** a Rich `Text` with no markup parsing; every C0/C1 control character from an A2L/I-2 string becomes U+FFFD before painting. Long values use the existing cell clipping and visible ellipsis.
- **Patch include:** picker-local selection through the same include control, keys and bulk modal as Check. It does not add/edit document entries, change dirty/undo/redo state, or replace `Use parameter`'s single highlighted-row behavior.
- **Population:** a real `set_parameters` repopulation, not the unchanged-signature no-op. With A2L data available, one `describe_definitions(all names, a2l_data)` call supplies datatype/kind; no per-row or per-page describe is permitted.
- **Out of scope:** I-2 encoding, masked staging/re-encoding, definition-editing UI, Inc 7 list filtering/autocomplete, parser/reader changes, app-prefill changes, and physical/raw value display. E3A-07/E3S-08 and E3S-11 therefore remain Inc 8/9 obligations; no masked edit or unbounded I-2 refusal message exists in this slice.
