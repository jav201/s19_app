### Root causes and fixes (`tests/support/b103_a2l_ref.py`)

1. **Forward-reference typedef (R-A2L-READ.42–.45).** `_read_spans` collected typedefs and read spans in one walk, so an `INSTANCE` whose `TYPEDEF_*` is declared later got no length. Fixed by a two-pass `_collect_typedefs(sections)` then `_walk(sections)`; span order unchanged.

2. **`/include` diagnostic (R-A2L-READ.22).** The reference emitted `/include <file> is not read` without the required prefix. Fixed to `f"Line {ln}: /include <file> is not read"` (matches the product's `pending_include_line` text exactly — `Line 5: /include included.a2l is not read` on the tracked file).

3. **Spurious `UNIT unit` errors (R-A2L-READ.29).** The reference detected keywords case-insensitively (`w.upper() in _ARITY`), so the argument `unit` was re-parsed as the `UNIT` keyword, producing 30 false "has 0 of its 1 arguments" / "declared twice" errors on `case_07_stress_smoke/firmware.a2l`. The product detects keywords case-sensitively (`word in _TAG_KEYWORD_ARITY`). Fixed by making all five `_ARITY` membership checks in `_tag_header` and `_keyword_items` case-sensitive — no special-casing of UNIT or the file.

4. **Unresolvable-deposit VALUE typedef over-sizing (R-A2L-READ.43/.45) — surfaced after fix #1.** `_deposit_size` matched broad datatype substrings (`"ULONG"`, `"UWORD"`, …), so `dummy`'s deposit `__ULong_Value` in `update_typedef_test3.a2l` was sized to 4 while the product (correctly) gives no length. Fixed by narrowing the markers to the product's `sizeof_from_deposit` record-layout suffixes (`"__ULONG_Z"`, `"__UWORD_Z"`, `"__FLOAT64_IEEE_Z"`, …), keeping the `_DATATYPE_SIZES.get(u)` fallback.
