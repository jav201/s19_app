## Checked and clear (no finding)

- **The lexer is linear on hostile shapes (model).** Doubling steps measured ≈ 2.0× on: all lines in tier 3, one huge tier-3 line, a string over 200,000 lines (built incrementally), a comment never closed over 400,000 lines, and an error on every line [M3]. The tier-3 rate is about 5 µs per line. The base handles a 20 MB body line in 0.67 s and 300,000 tiny sections in 1.06 s [H11, H12]. Memory grows linearly with the file (`_section_words` keeps (word, line) tuples, about 2× the base on a 20 MB body). Memory is not a row.
- **EOF and encoding shapes.** On the base, an unterminated comment or string at EOF, `//` at EOF with no newline, an escape at EOF, NUL bytes, a Latin-1 byte, a UTF-16 BOM and CR-only line ends all raise nothing [H2–H9]. The design adds the errors for them. A lone surrogate cannot come from disk (`errors="replace"`), and READ.4 prints the code point, not the character.
