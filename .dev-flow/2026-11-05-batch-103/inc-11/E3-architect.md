The core design is right and is the smallest one I can find: a streaming lexer that writes canonical text into the base section shape, so every base line reader inherits the comment, string and line-end fixes and the field rules keep their code; the tag reader moves to words. Measured on the runner it stays inside R-A2L-READ.52 (§3). What blocks:
- **E3A-01 (HIGH).** Corpus class 1 is fixed for MEASUREMENT and CHARACTERISTIC only. ## 2. Answers to the questions routed to E3

### 2.1 Is the reader change the smallest design that fixes every class while keeping the non-defect tags identical?

Yes for the word layer, with three gaps. Alternatives considered:
- (i) A token AST with every reader rewritten over it. It is larger and touches every field rule.
- (ii) E1's CANON pre-pass followed by the base reader unchanged. It needs a second full pass, and the tag reader would still need the header and keyword rules.
- (iii) The graph's design: streaming canonical lines in the base section shape (DE-1, DE-3) plus a word-level tag reader (DE-4). It is (ii) done inline, and it is the smallest.

By class:
- **Corpus classes 2–5 and 7, Latin-1 (CG-5 A), the 47 Inc 2 E3 shapes (RP-C-A … X2, rounds 1–5), the commented copies and the line ends:** mapped to rows and cases (graph table `:100-109`).
- **Class 1 (names):** fixed for tags only (E3A-01, HIGH).
- **Class 6 (lengths):** VAL_BLK is fixed by R-A2L-016 and READ.53; CURVE/MAP go to Inc 3a (CG-4). ARRAY_SIZE is a size class the census oracle does not model (E3A-04).
- **The padding glue:** fixed at the 9-character shape; truncation appears for long names (E3A-03).
- **No regression:** the Issues projection on the 35 tracked files (base reader on E1's CANON, `e3a-issues.txt`) differs from e07fb00 only by V171's `Unclosed /begin sections detected.`, which goes away. Every other A2L code count is equal (no new `A2L_UNRECOGNIZED_BLOCK`, `A2L_DUPLICATE_SYMBOL` or `A2L_BROKEN_REFERENCE`), and REF's diagnostics are `[]` on all 35. That agrees with the 0-error thresholds of READ.4/3, .11/3, .28/3 and .32/4.

### 2.5 F-E2-2 — how R-A2L-READ.50's "header" is read

Read it as the **words on the keyword's line before any child section**, which is the graph's canonical `meta`, and not as the CTX *section header* across lines. Reasons:
- The summary is a structural outline. Its tags block already carries names and addresses.
- The CTX header runs to `/end` for kinds without a keyword list (COMPU_METHOD, RECORD_LAYOUT), so every such line would grow by its coefficients.
- Changing it would alter nearly every summary line of V161, V171 and the corpus. That is a visible change outside the row's purpose (remove comment text) and outside E1-rulings §5.

The wording must then stop using the CTX term, both in READ.50 and in R-A2L-076's `<header>` (E3A-05). With E3A-01, a named section whose `/begin` stands alone also shows its name.

### 2.6 Is the differential oracle independent enough — could a bug common to both pass?

Yes, a common bug could pass, in four places.
1. **The specification.** Both are written from the same Definitions: the keyword and arity list, the header counts 6/7, the number word, the blank set. A wrong definition passes both. The rows' hand-written expected values (166 cases) and READ.49's e07fb00 fixture are the independent oracles; READ.49's fixture is independent of both readers for 234,428 tags.
2. **The 226 defect tags** have REF as their only oracle (E3A-08 (2)).
3. **Graph-only rules** that change output (DE-7) push the REF author toward the reader's code (E3A-06).
4. **Sections** are not compared at all (E3A-08 (1)).

Independent by mechanism, and good:
- The product reads lines through universal newlines; REF normalises the whole text.
- The product's three tiers have no counterpart in REF, so a tier-selection bug shows as a difference.
- CG-6's corpus run against the orchestrator's census lexer (`design/a2l-corpus/census/census.py`) is a third reading, of real files.

With E3A-08's three changes I judge it independent enough.
