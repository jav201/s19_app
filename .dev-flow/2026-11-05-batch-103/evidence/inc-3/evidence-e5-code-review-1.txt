## 2. Design-gap assessment (tasked item)

### FIX forms selected by fixed priority rather than file order — **design-gap, LOW**

- `s19_app/tui/a2l_definition.py:1511-1601` (`_read_fixed_rule`): records the first `FIX_AXIS_PAR` and first `FIX_AXIS_PAR_DIST` in the header, then the `FIX_AXIS_PAR_LIST` child, and selects `par → par_dist → list_numbers` by **fixed priority** (`if par is not None … elif par_dist … elif list_numbers …`).
- The graph `_read_axis` node writes "the first of `FIX_AXIS_PAR o s n`, `FIX_AXIS_PAR_DIST o d n` (header words) and the numbers of the FIX_AXIS_PAR_LIST child **in file order**" — `graph-inc3.md:594`. That wording is ambiguous, but a literal "first … in file order" reading differs from the implementation when two forms co-occur.
- Requirement R-A2L-DEF.98 (`01-requirements.md:190`) pins only the **none** case ("has no FIX_AXIS_PAR, … or FIX_AXIS_PAR_LIST"). The "more than one form" case is **unpinned by any row or case**.

Assessment: LOW. A well-formed AXIS_DESCR has exactly one FIX form (E1 census: 12 tracked PAR_DIST lines, 2 tracked PAR_LISTs, no object with two forms), so no real fixture is affected. The implementation is deterministic and cannot raise or overflow — but it is *not* fail-closed, which diverges from the design doctrine the E3 pass itself applied to the analogous multi-value-MATRIX_DIM case (E3A-10 → R-A2L-DEF.145 refused rather than ignored). This is a spec gap surfacing in the code, not an implementation bug against a pinned contract. **Recommendation (not blocking):** pin the selection rule in CTX/`_read_axis` ("first form in file order", or fixed priority as chosen), or — consistent with fail-closed — refuse a FIX_AXIS carrying more than one form. No code change required to merge.
