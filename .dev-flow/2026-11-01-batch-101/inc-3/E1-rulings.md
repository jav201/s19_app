## 3. Decisions taken at E1 (with reasons)

- **E1-D1 — optimisation, not re-rule.** The profile's largest cost (2 000 `resolve()` calls, 0.65 s of 1.48 s profiled) is not a floor: half are duplicates and none is needed to answer "is this name a file in the project". With gather + isfile the real node measures 0.65–0.74 s (5/5) on a loaded host.
- **E1-D2 — the once-per-name rule lives in the gather, not in its caller.** `app.py` builds `composition_names` as batch + assignments (`app.py:11836`); de-duplicating there would also work, but the gather is the function that owns "check each name" and the isfile change sits in the same loop, so one file holds both and the caller does not change.
- **E1-D3 — duplicate findings collapse.** With the once-per-name rule, a composition name that is missing and appears twice gives one `GATHER-SOURCE-MISSING` finding instead of two. These findings are logged only (`app.py:11860`), never painted; no canon row counts them. Accepted.
- **E1-D4 — the A2L "no longer exists" case is reached only mid-attach.** The A2L attach's request-time guard (`load_a2l_from_path`, `app.py:15202-15217`) already refuses a deleted folder with `A2L NOT loaded: …`, so R-PROJ-002.13's deleted alternative is reached only when the folder goes between the request and the install. The test deletes it from inside the attach worker (a wrapper of the copy step). Checked: the guard reads `validate_project_files`, which raises `FileNotFoundError` on a missing folder.
- **E1-D5 — the refusal comes from the existing read.** With the `mkdir` gone, `validate_project_files(project_dir)` raises `FileNotFoundError` (`project_dir.iterdir()`, `workspace.py:1911`) inside the existing `try` and the existing `except OSError` paints the canon line; a regular file in the folder's place raises `NotADirectoryError`, as today. No new branch, no new text.
- **E1-D6 — the panel paint stamp uses public Textual API only.** The stop stamp is the first publish of the pushed panel screen's `screen_layout_refresh_signal` at which `#result_summary` has a height, subscribed by the app (a running node) from a test wrapper of `push_screen`. Subscribing the screen itself fails (`SignalError: Node must be running`, seen at E1). No product code changes for the stamp; no private Textual method is wrapped by the tests (the E1 script wrapped `_refresh_layout` and `_compositor_refresh` only to diagnose).
- **E1-D8 — the composition check folds `.` and `..` lexically [F5].** Design: `os.path.normpath(resolved_project / name)` and then `is_file()`. `normpath` keeps absolute, drive and UNC names as they are, the same as the base join. On Windows it changes nothing, because the Win32 layer already folds lexically. On POSIX it keeps the base answer for `..` over a missing folder (Python's non-strict `realpath` folded that one lexically too). For `..` after a link it is now judged lexically, as the manifest writer judges it (`_walk_manifest_entry`). The writer refuses a link entry anyway, so no save that names a link can end verified in either form. Rejected alternative: admit the POSIX edge in I-1 and fold nothing. It would leave a composition limb that disagrees with the writer on `..`, to save one function call.
- **E1-D9 — the name key of the once-per-name rule is the exact text [F11].** No case or separator folding before the key. `./x.json` and `x.json` are two checks; both land on the same folded path and give the same answer.
- **E1-D7 — no new test file.** New nodes go into `tests/test_project_gather.py`, `tests/test_b100_workers.py` and `tests/test_b100_project_check.py`, so `tests/test_id_registry.py`'s `EXPECTED_SCANNED_TEST_FILES` needs no re-measure.

## 5. Observations, accepted residuals and backlog rows

- **O-1** — the E1 host was slower than batch-100's (base `4dfb5a1` measured 0.95–1.03 s today against 0.71–0.79 s then). Timing evidence counts only for its host and day; E5 re-measures base and head side by side.
- **O-2** — Save project's worker step runs about 0.1 s slower while the waiter keeps waking the app's loop (`E1-profile.md` §1.4). A test-harness effect on the measured interval, also present in the product while Textual repaints; no row.
- **O-3 — accepted residual: a folder deleted mid-sync is still re-created [F7, S-2].** R-PROJ-002.14 holds when the folder is gone before the sync reads it. If it goes after `validate_project_files` succeeds and before the write, the placement re-creates it: `place_into_workarea` runs `resolved_destination.mkdir(parents=True, exist_ok=True)` (`workspace.py:1183` on `e266395`, `:1200` on origin/main), and the project.json write runs `destination.parent.mkdir(parents=True, exist_ok=True)` (`manifest_writer.py:648`). The re-created folder stays inside the work area, because the destination guard runs first and R-PROJ-CONTAIN.1 holds. The window needs a concurrent delete within microseconds. That code is not this increment's, and the R-PROJ-002.14 tests delete the folder before the trigger. Accepted as residual. The same holds for a folder deleted during a Save project.

Backlog rows for the orchestrator to paste into `.dev-flow/BACKLOG-CODE.md` (exact text; the line numbers are `e266395`'s, with origin/main `f11b3f4`'s in brackets where they differ):

- **▸ (security, S-3, batch-101 Inc 3 E3) An operating-system error at a composition name other than a missing file or a link loop still stops Save project.** `gather_project_artifacts` (`s19_app/tui/services/project_gather_service.py`, composition limb) tests each name with `Path.is_file()`, which swallows only ENOENT, ENOTDIR, EBADF and ELOOP (and Windows errors 21, 123, 1921). Another error — EACCES on a parent folder, a damaged or offline reparse point (WinError 1920, 4392) — leaves the gather and ends the save with R-PROJ-ROLLBACK.18's `… an unexpected error stopped the save. check the folder.`, against the function's documented `Raises: None` (collect-don't-abort, C-5). Same at base. Fix to decide: catch `OSError` around the check and treat the name as not home (common lookup, else `GATHER-SOURCE-MISSING`), with a new `If` row in S11.4.
- **▸ (security, S-4, batch-101 Inc 3 E3; pre-existing) Save project reads through a link in the common patches library.** For a composition name found only in the common library, `_schedule` hands `place_into_workarea` the *resolved* candidate (`unresolved=False`), so the placement's source-side link refusal never sees the link: a symlink `common/boost.json` → a file outside the work area is followed and its bytes are copied into the project as `patches/<target name>` with 0 findings (E3 probe `probe_symsrc.py`, base tree, Windows with symlink privilege). Nothing is written outside the work area (R-PROJ-CONTAIN.1 holds), but the save reads outside it. The active-document limb refuses the same shape with `GATHER-CONTAINMENT`. Fix to decide: refuse a composition source that is a link like the active document (`GATHER-CONTAINMENT`, not copied), by passing the unresolved candidate to the placement; new S11.4 row.
- **▸ (security, S-5, batch-101 Inc 3 E3; pre-existing) Composition names reach the filesystem before any text check.** The composition limb of `gather_project_artifacts` runs no lexical filter before `is_file()`: absolute, drive-relative (`D:x`), UNC and climbing (`../`) names are probed, which is an existence oracle, and a UNC name makes Windows attempt SMB authentication to that host. The base `resolve()` touched the same paths; the manifest writer refuses such names afterwards. Names come from the Save dialog's payload or from a carried manifest the reader already filtered. Fix to decide: run the reader's lexical predicate (`_entry_text`, manifest-keys mode) on each composition name before any filesystem call; it also saves time.
- **▸ (product, D-4, batch-101 Inc 3 E1; orchestrator ruling (a) 2026-11-02) The variant append at the SEC6-5 folder ceiling has under 20 % margin.** Stamped from `load_from_path` to the painted outcome line, the `sec6_5 appended` arm of `tests/test_b100_project_check.py::test_tc_b100_61_sec6_5_distinct_folders_stop_at_the_folder_ceiling` takes 0.59–0.96 s on the Inc 3 E1 Windows host (4/6 runs under 20 %; `2026-11-01-batch-101/evidence/inc-3/appended-poll-vs-stamp.txt`). The sync re-reads the 6 000-entry hostile manifest and `validate_project_files` lists the 3 000-folder project twice (`_sync_loaded_file_to_project` and `_activate_project_file`; `evidence/inc-3/appended-split.txt`). Re-measure base vs head on the LAN host at Inc 3 E5; candidate fix: one folder listing per sync.
