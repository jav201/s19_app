## The F5 change: `Path(os.path.normpath(resolved_project / name)).is_file()`

**No name reaches outside the project.** A True result only skips the name: nothing is read, copied or written for it. A False result falls to `common_patches_dir / Path(name).name`, a bare name that stays inside the library. Every copy still goes through `_gather_copy` → `_check_home_contained` + `place_into_workarea(workarea_root=…)` (`project_gather_service.py:654-668`, unchanged). **Same answer as base, executed on 16 names (Windows, `probe_fold.py`, `probe_unc_nul.py`).** The folded check gives the same boolean as `(rp / name).resolve().is_file()` for each of these: `x.json`, `./x.json`, `missing/../x.json`, `../outside/secret.json` (True in both: skipped, nothing read), `../../work/outside/secret.json`, an absolute path outside, `D:x.json`, `C:x.json`, `\\localhost\…` and `//localhost/…` (UNC: the fold leaves the join unchanged), `x.json/..`, `..`, `""`, `x<y.json` and `loop.json/../x.json`. The answer differs only for `loop.json` (the R-PROJ-GATHER.13 input) and for `a\0b.json` (N-2). On POSIX, Python 3.11/3.12 `realpath` folds `..` lexically after resolving the links before it.
