## What holds (checked, no finding)

- **The waits read the product, bounded by the shared wall-clock wait.** D1/D2 read `app._change_service.document.source_path`, which the product sets in a synchronous handler (`app.py:7142` load, `:4824` paste) before the guard writers run; the test coroutine cannot observe the state between them. D3/D4 read a counter of product calls to the bind step: this is R-TST-030's own "records the state at the product hook", and no product observable exists for a no-op without a product change. Every asserted value is still read from the product. All four go through `settled` → `wait_until` (60 s wall, 0.05 s poll, `pause_first`).
- **The recorder cannot make the no-op arm pass vacuously with the probe as written.** The `fx_bind` hold defers `FlowExecutionPanel.on_button_pressed` at class level (`i15_guard.py`), so `_rebind`, and the instance-level recorder below it, run only 1.5 s later; D3 cannot settle early. Under mutant (early return removed) plus hold, the fixed arm fails at the no-op assertion, which is the right reason (see F5 and F6 for the constraints this depends on).
- **Seams.** `_change_service.document` already has 86 reads in `tests/`, and `source_path` is the canon row's own term. If Inc 6 moves it, the predicate raises `AttributeError`, which `wait_until` propagates at once (loud). If Inc 9 renames `_rebind`, the install fails with `AttributeError`; if Inc 9 re-routes the press, the arm fails after 60 s with `did not settle: TC-B94-27: …` (loud, and it names the cause). Without a product change, there is no narrower seam. A class-level wrap of `on_button_pressed` would sit above the hold and be vacuous; an instance-level wrap of `on_button_pressed` is never dispatched by Textual.
- **No node is renamed.** Two functions change and keep their names, one function is new, and one parameter id `[R-TST-158]` is new. Both modules are unmarked, so they run in the parallel lane (R-TST-157 is feasible).
- **The designed static guard flags nothing outside its two named functions**, so its false-positive rate on the current tree is 0 by construction. Its listed controls (a description changed, a local `range` loop) can turn it RED. F3 and F4 cover what it does not cover.
- **Windows runs (R-TST-156)** fall under the handoff's exception for Windows-only arms (`HANDOFF-2026-11-06.md:38`: LOCALAPPDATA isolated, never the clipboard). E1 §6 shows both conditions were met.
