## User stories

### US-TST-15 — a Windows run reports the product, not the host's clock
As the operator, I want the Patch Editor and Flow Execution arms that check what a press, a value set on a widget or a posted action left to wait until the app has handled it, so that a serial run on the Windows host gives the same verdict as the Linux gate. (TC-331 failed 5 of 16 runs on the Windows host at `c2cba35`; TC-B94-27 failed 2 of 2 Windows runs at `e279c8b`; AT-030c and TC-051's `test_save_back_prompt` failed in the Windows chunk-10 run at `e279c8b`; all four pass on Linux.)

### US-TST-16 — a no-op arm proves the press was handled
As the reviewer of a later increment, I want an arm that asserts that a press changed nothing to prove first that the app handled the press, so that the arm cannot pass when the handler never ran. (TC-B94-27's rebind-to-same arm passes today with its handler held back 1.5 s, `evidence-e1/lin/lin-hold-fxbind-1.txt`.)

## Definitions

- **One-pause read.** A read of app state taken after a press, a value set on a widget or a posted panel action with only fixed `pilot.pause()` calls in between. On the Windows host `pilot.pause()` can return before the press is handled: Textual 8.2.8 ends the pause when `time.process_time()` advances by less than 1 ms over a 20 ms sleep, and on Windows that clock advances in 15.625 ms steps (`evidence-e1/win/clock-probe.txt`: 5 ms of busy work reads 0.0 ms in 14 of 20 samples).
- **Handled press.** For Load and Parse pasted: the app's change document holds the result of the action (the document is replaced and the Edit JSON guard is set in the same synchronous handler: the two branches `s19_app/tui/app.py:4811-4834`; the guard writers `:7191` in the load tail `_patch_editor_load_tail`, which a load runs, and `:4929` at the end of the action handler, which a load and a paste both run; the third writer `:5170` is the history path, which these arms do not use) (E3 F2). For a dropdown pick (AT-030c): the change document's source path names the picked file (`on_patch_editor_panel_change_file_selected`, `app.py:7054`, loads it through `_patch_editor_load`, `:7127`). For Apply: the save-back prompt row `#patch_saveback_row` has lost its `hidden` class (`show_save_prompt`, `s19_app/tui/screens_directionb.py:6465`, called from the apply branch `app.py:4868` only after an apply with ≥ 1 applied entry, R-CHG-003.1; the row is composed hidden, `screens_directionb.py:5114`). For Don't save and Write file: the save-back prompt row has the `hidden` class again; the decision handler hides it first (`app.py:5002`), before the decline return (`:5003-5005`) and before the save (R-CHG-003.2, R-CHG-003.5) (E3 F1). For Bind: the Flow Execution panel's bind step has returned for that press, observed by a recorder the arm wraps around the panel's bind step; the recorder counts a call after the step returns, and every asserted value is read from the product (E3 F5).
- **Shared wait.** `settled(pilot, predicate, description)` of `tests/b97_probes.py`: polls every 0.05 s, bounded at 60 s of wall time, fails with `did not settle: <description>` (Inc 2: R-TST-020, R-TST-021, R-TST-024, wait W3).
- **Windows host.** The operator's Windows PC, interpreter `s19env` (Python 3.11.15, Textual 8.2.8), run serially with `LOCALAPPDATA`, `APPDATA`, `TEMP`, `TMP`, `USERPROFILE` and `HOME` pointed at a fresh scratch folder and the OS clipboard writers replaced by a raising guard (`evidence-e1/probes/i15_guard.py`, `i15-run.sh`).
- **Held-handler probe.** `I15_HOLD=fx_bind|patch_action` of `evidence-e1/probes/i15_guard.py`, and `I15_HOLD=patch_action|change_file|save_back` with the filter `I15_HOLD_ACTION` of `evidence-e3/probes/i15c_guard.py` (E3 F1, F2): the press reaches its unchanged handler 1.5 s later (`set_timer`), the forced slow step of the Post-press rule (`docs/engineering-rules.md:200`). `fx_bind` defers `FlowExecutionPanel.on_button_pressed` for the `fx_bind_*` buttons; `patch_action` defers `S19TuiApp.on_patch_editor_panel_action_requested` (every action, or only the action named by `I15_HOLD_ACTION`, e.g. `parse_paste`, `apply_doc`); `change_file` defers `S19TuiApp.on_patch_editor_panel_change_file_selected`; `save_back` defers `S19TuiApp.on_patch_editor_panel_save_back_decision` (both answers, or only `decline` / `confirm`). It runs from outside the tree and changes no file.
