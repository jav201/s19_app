## User stories

### US-I12-1 — every dialog opens and every action runs from somewhere (F-33, F-34)
As the maintainer, I want every dialog of the app to have a key, a button or a command that opens it, and every action to have a key, a palette command, a button or a caller that runs it, so that the release carries no dialog or action that no operator path reaches and no test keeps one alive.

### US-I12-2 — every widget of the Check Editor is shown in some state (F-35, the Check Editor half)
As the maintainer, I want the Check Editor to hold only widgets that some state of it shows, so that no test proves a behaviour on a widget the operator never sees. (Narrowed at E3, D-5 B: the Flow Builder and Flow Execution half is US-I12b-1 of `../inc-12b/01-requirements.md`.)

### US-I12-3 — Escape closes the Reports dialog (F-51)
As the operator, I want Escape to close the Reports dialog as Close does wherever the focus is inside it, an open dropdown list closing first, so that the Reports dialog answers Escape like the other dialogs.

## Definitions (additions and changes to CTX-DIALOG, CTX-KEYS and CTX-SHELL; terms only)

- **Opener** (CTX-DIALOG, new). A key, a button, a palette command, or a control of another dialog or window, whose use opens a dialog. In the census a construction of the dialog counts as an opener only inside a reached function (*reach*, CTX-KEYS; E3A-02).
- **Dropdown list** (CTX-DIALOG, new). The list of choices that a dropdown shows under itself while it is open.
- **Dialogs today** (CTX-DIALOG, changed): the row `Reports (project '<name>'):` reads `yes` in the column "Esc today", and `report list (the ? chip when the project has no report)` in the column "focus today" (E3 U-6: what the app does now; BL-I12-2 keeps the decision).
- **Action** (CTX-KEYS, new). A named command of the system: what a key, a palette command, a button or a link runs.
- **Reach** (CTX-KEYS, new; corrected at E3, E3A-01, and at E3 round 2, E3A-R2-1). What runs an action from an operator path: the action's exact action string in one of four positions — the action of a key binding, the action of a palette command, a literal argument of `run_action`, the target of an `@click=` link; a binding that the terminal toolkit declares on a toolkit class the action's class derives from, such as `ctrl+x` → cut in a text box; or a call or reference of the action from a reached function (a button reaches an action this way, through its handler). The same text in any other position — a widget id, a comparison, a dictionary key — is not an action string. A **reached function** is an action that has a reach, a handler the toolkit runs by its name (a message handler, `compose`, a watcher, a validator), or a function that a reached function calls or passes on. The words of a message, a docstring or a comment are never a reach.
- **Shown widget** (CTX-SHELL, new). A widget that is displayed, together with every widget that holds it, up to its window.
- **State of a window** (CTX-SHELL, new). An arrangement of a window that the operator reaches through its keys and controls: a tab chosen, a kind chip pressed, a list opened, a notice shown, a lane waiting. A requirement that walks states names them.

The two CTX-SHELL terms are carried with identical text in `../inc-12b/01-requirements.md`; whichever increment merges first folds them into the canon, and the other cites them.
