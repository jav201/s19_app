## Context of use

- **User:** the operator — an engineer who works S19/HEX images with A2L and MAC files, keyboard first.
- **Task:** press `t` to open Reports, read a report or start to fill in the generation fields, then leave and go back to the window they came from (Workspace, or Flow Execution after a chain run: ch18 step 5), without writing a report and without changing the filter.
- **Environment:** a Textual TUI in a terminal (Windows Terminal), reference 118×54. Single-key bindings. `esc` already closes 12 of the app's dialog classes; the find and go-to boxes treat Escape in two stages, but none of them is in a dialog.

## Verdict

**PASS-WITH-NOTES.** The design for F-51 matches the app's dialogs. D-7 A adds a plain screen-level `escape` binding that does what Close does (`dismiss(None)`, posts nothing). That is the idiom of all 12 dialog classes that already answer Escape: Load (`screens.py:373`), Edit change-set JSON (`:762`), bulk add (`:960`), Save project (`:1220`), file chooser (`:1726`), Edit block (`:1924`), the questions (`:2346`), Load result (`:2536`), Legend (`:2702`), Unsaved changes (`screens_directionb.py:4330`), help window (`window_help.py:689`) and Parameter (`a2l_describe.py:57`). None of these bindings is `priority`, and each closes in one stage from its text boxes, including the multi-line editors of Edit change-set JSON and bulk add.

By reading, no focusable place in the Reports dialog takes Escape. `Input`, `ListView` and a closed `Select` bind none. `TextArea` takes Escape only with `tab_behavior="indent"` (`_text_area.py:1830`), and the regions box uses `focus` (B line 33). `CappedTextArea` and `OsClipboardInput` add no key handler. Markdown blocks cannot take focus. The app's `on_key` handles Escape only for the six find and go-to ids. So the binding closes the dialog from all 10 places and on the empty dialog.

The open-dropdown rule (D-8 / R-DLG.15) works the way dropdowns work everywhere: the first Escape closes the list without choosing, the second closes the dialog. The overlay is first in the binding chain (`_select.py:51`), and its Escape only dismisses; it does not apply the highlighted option (`:161`).

After the dialog closes, the focus returns to the widget that had it before `t`. Close and Escape share `dismiss(None)` with no callback, and Textual keeps the main screen's `focused` (`screen.py:1475`; it auto-focuses only when that is `None`). This holds, but no case asserts it (U-2).

The removed hidden widgets take nothing a user can see or reach. Each one is set to `display = False` at compose or mount and never turned back on (grep of every `display` write). No CSS rule shows it. A widget with display off leaves the focus chain, and no binding, palette entry or help line names any of them. The work each one did has a visible owner: the Addendum tab chip, the kind chips with their kind tag, the ribbon, and the `?` help body.

No finding blocks E4. One docs claim must change because of the D-5 B split (U-1).

## Notices (declared, not blocking)

- **N-1 (declared regions):** Escape throws away typed region lines, as Close does and as Escape does in the Edit change-set JSON editor. This matches the rest of the app and is what R-DLG.2 + R-DLG.9 require. A reflex Escape costs more than a mis-click on Close, but guarding against it would need a confirmation dialog (new UI, a prototype round). No change proposed.
- **N-2 (what "shown widget" means):** "Shown widget" is defined, and walked, by the display chain (`b97_probes.is_displayed`). That is a structural read. It catches F-35's kind of defect (display off). It would not catch `visibility: hidden`, a widget of zero size, or one that is always clipped. None of those exists in the tree today (grep: no `visibility: hidden`, no zero `height`/`width`). If "show" is meant as painted, add "region area > 0 after layout" in at least one state.
- **N-3 (painted reads in the acceptance cases):** "Closed" is read off the screen stack. In Textual that decides what is drawn, so it is enough for the row cases. AT-I12-1 should still read the painted frame once: the title `Reports (project 'proj1'):` in `painted_rows` of the screen after `t`, and absent after the last Escape (C-32). Likewise AT-I12-2's "`#issues_hex_pane` paints the address row" and AT-I12-3's "Addendum text starting `## Checks`" should read `painted_rows`, not widget content.
- **N-4 (the D-5 B split):** my reading of the Flow Builder and Flow Execution removals (`#flow_kind`, `#flow_canvas`, `#flow_blocks`, `#flow_help`, `#flow_ext_session`, `#fx_help`: nothing visible or reachable is lost; the kind chip calls `_sync_kind_dependent_visibility` directly, `flow_screens.py:2507`, so the form needs nothing from `#flow_kind`'s `Changed` event) moves with them to Inc 12b.
- **N-5 (focus set directly in cases):** the R-DLG.2 cases set the starting focus with `.focus()`. That is acceptable: the interaction under test is the real `escape` key, every place can be reached by Tab, and AT-I12-1 reaches two of them by Tab. Typed text must be key presses (`pilot.press`), as the pilot did, not a `value =` setter.
