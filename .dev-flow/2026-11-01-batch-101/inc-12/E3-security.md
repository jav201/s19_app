The window-help key tokens don't name them (`window_help.py:1254-1257`). The app loads no keymap file (no `set_keymap`). So no key, palette entry or user file is left naming a removed action.

**The new Escape cannot dismiss a dialog mid-action or skip a confirmation.**
- **Only on the top screen.** A plain screen binding fires only while `ReportViewerScreen` is the active screen. Textual checks the focused widget, its parents, the active screen, then the app. A modal pushed over the dialog (its help window, or any app modal) gets the key instead. The app has no `escape` binding, priority or plain. `S19TuiApp.on_key` acts on Escape only for the six find and go-to boxes (`app.py:10736-10740`).
- **Nothing is in flight.** Generate parses the box, posts `GenerateRequested` to the app queue and dismisses, all in one synchronous handler (`screens.py:3483-3506`). There is no `await` between the post and the dismiss, so an Escape cannot land between them. A dropdown change posts `FilterSelected` the moment it changes (`:3440-3446`). The path box posts only on Enter (`:3470-3476`), and the dialog has no blur handler, so Escape applies nothing typed, as Close does. `_render_report` awaits only a read-only Markdown update. The three app handlers (`app.py:6345`, `:6394`, `:6471`) query no widget of the dialog, so a dismissed dialog is never looked up afterwards.
- **No confirmation to skip.** The dialog has none. Its one outbound action besides Generate is the folder chip, which opens the file manager; R-DLG.2/9 spies on it (0 calls).
- **Inner Escapes keep their meaning.** The help window keeps its own Escape (`window_help.py:689`). The open dropdown's Escape closes the list without changing the value (`_select.py:51`, `:161-163`, `:659-665`), and it runs before the dialog's binding. A priority binding would break that; that is R-DLG.15's negative control, and the right one. The regions box has `tab_behavior` `focus`, so it does not take Escape (`_text_area.py:1829-1834` acts only in `indent` mode).
- **A second Escape is harmless.** Every Escape binding in the product closes, cancels or answers No (`screens.py:2346` `answer(False)`, and the others listed by grep). So a second Escape that reaches the main screen after the dialog closes can at most release a find or go-to box. It never confirms or discards.
- **Unsaved typed input is discarded, as Close does.** Escape drops typed declared regions and a typed filter path (R-DLG.9). The dialog is rebuilt from app state at `t`, and R-DLG.2/3 and /5 pin this. In this app, Escape in the find and go-to boxes releases the focus (LLR-119.3). An operator may press it to leave the regions box and lose the lines typed there. That is lost typing, not lost stored data. It is the UX lens's call (D-7 C was rejected); `ch16-reports.md` could say "Esc closes, as Close, and drops typed regions".
- **The log line is safe.** It is a fixed string and carries no path or typed text.

**D-4 does not affect saved data.** The kind is not stored: each block carries its kind from construction, and `set_blocks` restores blocks, not a kind. The only cost is S-1.

**Tests owned by G-T1 and G-T2.** None of them is a security guard. TC-706's binding census gains the Escape row. TC-B97-08 and -61 change the id count and the "not mounted" check. TC-011's `hasattr` arm goes unused, and its rail candidates keep it able to fail.
