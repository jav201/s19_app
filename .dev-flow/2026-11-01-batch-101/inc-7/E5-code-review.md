## The five checks

1. **Code = graph and requirements.** Every G1–G4 node matches its `func:` line: `_md_text` and `_md_path` are one-line wrappers, `_run_symbol_names` / `_annotate_run`, `_window_rows` builds its own I-5 rows with no cap, `_image_line`, `_header_lines(title)`, the Runs symbols are escaped name by name, provenance paths use `_md_path`, linkage and flow-attribution use `_md_text` with the message limit 500, the census uses `_md_text`, the audit header uses `_md_text`, `_html_header` uses `_esc(_strip_ctl(…))` and `<h1>{_esc(title)}</h1>`, and `_html_run_rows` uses `_strip_ctl`. I-1 composer kwargs and I-4 UI-thread gathering (`mac_path is None` → `None`) match. `(key 7)` is the exact canon text, and key `7` is bound to `show_screen('diff')` (`app.py:2718`). Deviations, all already recorded and accepted: the `_remove_orphan_markdown` helper; the composer catching `BaseException` and re-raising; the `report_*` local names; the exclusive open before `try` (N-1). I found no unrecorded deviation.
2. **Correctness.** Atomic write: `open(part, "x")` happens before the cleanup scope, so a stale `.part` is never touched and `FileExistsError` propagates. `with handle` closes the file before `os.replace` (a Windows requirement). Any failure after the open unlinks only the `.part` this call created. Text-mode newline handling equals base `write_text`. `list_diff_reports` (`*.md`) does not list `*.md.part`. Orphan removal: see CR-3. Inside a closure, `md_written_path` is read at call time, so a Markdown refusal or exception removes nothing (A-3), and `missing_ok=True` covers stubbed generators. Escaping: the only pre-escaping producer (`run_flow` A2B arm) now passes raw values. A grep finds no other `md_safe` / `md_code` producer that feeds the diff generators, and no code parses the report header back (no `- Image A:` reader outside the generator). No double escape. Title: derived from `provenance`, which has a single caller (D-1).
3. **Simplicity, reuse and conformance.** Small and surgical. Reuse: `md_safe` / `md_code` / `_normalise` (private import justified in the docstring, A-1). The docstrings follow the repo's Summary/Args/Returns/Dependencies form. Duplication: CR-4 only.
4. **Tests.** New tests assert exact rows, cells and lines. Examples: the 644 oracle rows per block, `A*512 + "… (truncated)"`, the full `- Image A: A\*b\_\[x\]\.s19 …` line, U+FFFD at the same place in 5 fields of both files, and the exact `(key 7)` reason. The failure-injection tests prove the injection was reached (`hit`), and the differential test compares against `render_hex_view` over 0x00–0xFF. Negatives on file-derived names check both spellings (A-4). Weak spots: CR-5 and CR-6 only.
5. **SR-1 (LLR-155.3 allow-list).** **Consistent with the law's intent; it does not weaken the guard.** LLR-155.3 protects one invariant: a placed file is never replaced or deleted except by the placement claiming a free name. The census already allow-listed both generators for `write_text` onto M-5 collision-counter names ("never an overwrite"). `_write_report` moves the same write behind a staging file. It uses `os.replace` onto the same freshly chosen M-5 name and unlinks only its own `.part`. That is the pattern the census already accepts for `record_recent_source`. The two orphan removals roll back the operation's own placement, made moments earlier in the same failing operation, on report files that B8 reuse never touches. The allow-list entries are narrow: per file and per function, each with a comment citing the requirement. Residual risk: `_write_report` is a general helper whose `os.replace` would overwrite, so a future caller could use it to clobber a name. The census cannot see that. CR-3's `os.link` no-clobber would close it structurally. Records owed by E5 / the orchestrator: list `tests/test_b99_staging.py` among the touched nodes in `E1-slice.md` §4 (integration §3).

## A-6 ruling (explicit)

**Accepted consequence of the approved design. Not a MAJOR for Inc 7.** Reasons:

- (a) The 1.13 GiB HTML file and the ~5.2 GB peak come from the HTML side-by-side pane. That pane was already whole at base (OBS-7-4). At 1 MiB the HTML file is byte-for-byte the same size at base and head, and the peak is the same (1,329 vs 1,327 MiB).
- (b) Inc 7's added work (whole Markdown blocks, whole HTML only-A/B windows) peaks below the HTML phase.
- (c) The failure is loud and leaves no partial file.
- (d) R-CMP-006.7 and G-9 forbid caps on reports.

The resource-exhaustion risk on an ordinary machine is real for two fully different multi-MiB images. It is ranked on the backlog (CR-1), with the streaming write as the smallest fix (−42% peak, measured) and the OBS-7-4 CSS class as the large lever.
