## User stories

### US-BAR-1 — the before/after report names itself and its inputs
As the operator who applied a change document and wrote the patched image, I want the before/after report to be titled as a before/after report and to use the A2L and the MAC I have loaded, so that the file says what it is and its header and Runs table name the artifacts and symbols the patch touched. (F-42: titled "Diff report", `a2l=absent; mac=absent`, Symbols `-` although the A2L is loaded.)

### US-HEXWIN-1 — a written report carries every hex window whole
As the operator reading a written diff or before/after report, I want each hex window written from its first row to its last, so that the bytes of a long run are in the file and the Markdown and HTML copies of one report agree. (F6-1: every window cut at 512 rows; R-CMP-006.7 and batch-09 decision G-9 keep caps on the screen only.)

### US-MDESC-1 — names and paths stay plain text in the Markdown report
As the operator opening a diff report in a Markdown reader, I want image labels, paths and symbol names shown exactly as text, so that a name holding `_`, `*`, `|`, `<`, `[` or a backtick neither formats nor breaks the report, and the Markdown and HTML files of one report show the same characters. (D14-10, R-CMP-004.9.) Consequence admitted [F-E3-8]: in the raw `.md` file nearly every symbol and file name carries backslashes (`CAL\_A`, `img\.s19`), so a plain-text search of the `.md` for `CAL_A` stops matching; the HTML file and any Markdown reader show `CAL_A`. This is the S12 policy (the project report already does it).

## Definitions

- **Diff report, before/after report, hex window, symbols.** S14 CTX-DIFFREPORT and CTX-BEFOREAFTER. The flow-A2B report (S15) is a diff report, Markdown only.
- **Hex window rows.** One row per 16 addresses, from the window's first address (a multiple of 16) up to its end: `0x<address, 8 hex digits>  <16 byte cells>  |<16 ASCII cells>|`; a byte cell is two uppercase hex digits, or two spaces where the image maps no byte; an ASCII cell is the byte's character for 0x20 … 0x7E, else `.` (also for an unmapped byte). (The format `render_hex_view` writes today, `render/hexview.py:273-276`; unchanged. The HTML side-by-side pane of a changed window is outside this format: it shows an unmapped byte's ASCII cell as a space [F-E3-5].)
- **Cap line.** A line `... window limited to <n> rows ...` or `... output truncated at <n> bytes ...` (the screen's hex-view caps, `render/hexview.py:231`, `:244`).
- **Label field.** In either file of a diff report: an image label and a variant id in the header's image lines; each symbol name in the Runs table, the Change-entry linkage table and the Flow change attribution section; each change-document reference in the Flow change attribution section; the filter file name in the `## Report filter applied` block.
- **Path field.** In either file of a diff report: the image path in each header image line (`path=` …), and the original image, saved patched image and change document paths of the `## Before/after provenance` section.
- **Refusal message.** The message of a refusal line in the Flow change attribution section (`FlowRefusal.message`, an issue message of the change document: it can repeat the document's symbol and value text) [S-1].
- **Visible text.** The value after CTX-RPT-TEXT steps 1 and 2: each tab, CR and LF becomes one space, and each character of Unicode category Cc, Cf, Cs, Zl or Zp becomes `�` (U+FFFD). It covers C0, DEL, C1 (e.g. U+0085), the bidi controls (e.g. U+202E), U+2028 and lone surrogates [S-2, F-E3-6]. (Replaces the E1 term "control-stripped value", which removed only U+0000 … U+001F and U+007F.)
- **Report-safe text, path text, field limit.** S12 CTX-RPT-TEXT (both begin with the visible-text steps). Field limits used here: refusal message 500 (an issue message), every other label field 512.
- **Loaded A2L.** The A2L payload the session holds (S2). **Loaded MAC.** The MAC file the loaded image carries; none when no MAC file has been loaded, even though the loaded image then holds an empty MAC record list.
- **Artifact lines.** The two header lines `- Image <A or B> artifacts: summary=<s>; a2l=<status>[ (<covered>/<total>)]; mac=<status>[ (<covered>/<total>)]` (CTX-DIFFREPORT header).

## E5 corrective pass: design-gap fix (C-1)

- **Gap.** The approved design staged each report file under the fixed name `<name>.part` (exclusive create). On Windows the exclusive create follows a dangling symbolic link, so a link planted at that guessable name made the write create the link's target and left the report name as a link (security finding S5-1, LOW, probe P2.3). Proven RED on head `90ea8ae` by `test_r_cmp_005_16_5_planted_link_at_part_name_is_not_followed` (Windows, `evidence/inc-7/e5c-red-c1-windows.txt`).
- **Fix.** The staging name is `<name>.<16 random hex digits>.part` (`secrets.token_hex(8)`), created exclusively in the destination folder; a link cannot be planted at a name nobody can predict. Nothing else in `_write_report` changes (I-6 signature, cleanup scope, `os.replace`).
- **Rows and terms changed.** No `R-*` row text changes: R-CMP-005.16 already says "no temporary file" and its threshold counts files ending `.part`. The CTX-DIFFREPORT `file write` term above, the E3 addendum A-2 / N-1 (a stale `.part` is never touched; it no longer collides, so `FileExistsError` no longer propagates from it), the graph node `_write_report` and I-6, and `E1-slice.md` row 4 are updated. New case rows R-CMP-005.16/4 (N-1, changed) and /5 (the planted link) in `02-test-cases.md`.
