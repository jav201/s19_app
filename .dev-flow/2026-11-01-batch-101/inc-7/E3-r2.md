## 3. Orchestrator point — the private `_normalise` import

**Acceptable; no public alias is needed in Inc 7.** Reasons:
- No public function in `markdown_safety` gives exactly the visible-text steps. `md_code` adds backtick → `�` and `.strip()`, which would change HTML labels and paths that hold a backtick. `md_safe` escapes. So the only alternatives are the private import, a copy of the category set (two definitions that can drift, which is exactly what S-2 was about), or a 5th source file.
- The coupling stays inside one package (`tui/services`), and `markdown_safety` is a stdlib-only leaf module (`markdown_safety.py:3-7`). The import adds no cycle. No test or import guard forbids importing a private name (grep of `tests/`). Tests already import a private name from this module (`tests/test_report_markup_safety.py:185`, `_DROP_CATEGORIES`).
- The risk is a later change to `_normalise` made by someone who believes it has only the two consumers its docstring names ("Used by: md_safe / md_code", `markdown_safety.py:133-134`). That person could, for example, add a `.strip()` or a new category, and the HTML side would follow silently. The S-2 design wants the HTML side to follow, so this risk is about how visible the coupling is, not about safety.

Conditions for E4 (they do not reopen S-2):
1. A-1 as written: the `_strip_ctl` docstring names `markdown_safety._normalise` as its one source and says why no public alias exists (the 4-file cap).
2. Pin the coupling in a test, not only in the docstring: `drs._strip_ctl(v) == markdown_safety._normalise(v)` over the S-2 payloads (U+0085, U+202E, U+0001, U+2028, tab, CR). R-CMP-004.15/1-2 already pin the output. This one assertion also fails when either function changes without the other.
3. Backlog row: when `markdown_safety.py` is next in a slice, add a public `visible_text = _normalise` and update the `_normalise` "Used by" list to include `diff_report_service._strip_ctl`.
