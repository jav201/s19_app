## 3. Design assessment

- **D-1 C (confirm re-run token).** A deletes the only chain-set record of a lane that passed an external step. B merges two runs into one record. C changes one token and one check, so it is the smallest truthful option. Cost: `mode` now names a run kind as well as a dispatch (E3A-07). Dispatch stays safe, because only `parallel` runs in the pool (`:2082`) and any token outside the accepted three still raises. A separate `report_mode=` keyword would keep the two concepts apart at the price of a second parameter. Not worth it for one caller.
- **D-6 (exclusive create).** This is the right primitive, and it matches the house rule that "an entry of any type takes the name". The gap is the post-claim check (E3A-03).
- **D-10 (raise).** Right: `None` keeps its one meaning (nothing to save). The order also stays deterministic: an empty name still returns `None` before the guard runs, so R-FLOW-FILE.3 and R-FB-SAVE.6 hold with a linked home.
- **R-FLOW-FILE.12 at the save, not in `flow_to_dict`.** Right: copy and paste share the serializer (`flow_screens.py:2235`, `:2267`), and the field-by-field round trip (`test_flow_persistence.py:107-115`) calls `flow_to_dict` and `dict_to_flow` directly.
- **D-3 (cut at 64).** Acceptable. Identity is the file stem. Two files can carry the same 64-character `name` (`<C×64>.json` and `<C×64>_<N>.json`), and since only report titles read the field, the effect is cosmetic.
