## Checked and clear (no finding)

- **Save-over.** No flow or chain-set path overwrites. Every save de-duplicates (`_2`, `_3`, … LLR-015.1), and the only other code under `flows/` is a mkdir (`folder_open_service.py:456`) and the Import placement. So the exclusive create fits, and no replace-via-temp + rename is needed. A hard link named like a candidate is skipped by `lexists` and never written.
- **Name spellings.** A stem holds only `isalnum` characters, `-` and `_`. That strips `:` (no alternate data streams), `~` (no 8.3 alias can be typed), trailing dots and spaces, path separators, and every `Cf` character (bidi controls). A case-only clash on Windows (`Tune_B.json` against `tune_b`) is a taken name under `lexists` and gets `_2`; the written `name` is the candidate that was created, so it matches the file on disk. RTL letters (`Lo`) can still reorder how a stem is shown. That is not new with Inc 9, because stems are already painted.
- **Painted names.** Both report titles go through `md_safe` (`flow_execution_service.py:2142`, `flow_report_service.py:425`). The new `Mode` value is a constant. The two refusal statuses are fixed text that carries no path and no markup, so the guard's message (which holds paths) is never painted.
- **Home guard.** `_guarded_destination(flows_dir, self.workarea)` with an unresolved `project_dir` (`_active_project_dir`, LED .50) catches these: a junction or symlink at `flows/`, `flowsets/`, the project folder, or any folder up to `.s19tool`; a link at `.s19tool`; an inside-project link (R-FLOW-FILE.11/2); a path that cannot be resolved. A short-name spelling that does not match `self.workarea` only makes the walk run to the drive root, which can refuse more but never less. `workarea_root=None` with no anchor raises, so the default refuses. On Linux a dangling link at `flows/` is a symlink under `lstat` and is refused. The guard runs before the mkdir, so a refused home creates nothing (D-10).
- **Inc 6 interface.** The Inc 6 diff does not touch `workspace.py`. `_guarded_destination`, `_is_reparse_point` and `_path_traverses_reparse_point` are what base has, and I-5 holds. The handlers do not overlap either (slice §4).
- **Availability note.** `_is_reparse_point` treats every reparse point as a link, cloud-file placeholders included. With the work area at `cwd/.s19tool/workarea` (`app.py:2818-2820`), a sync-client folder would refuse flow saves just as it already refuses the other guarded writes. That is consistent, so it is not a finding; the user guide could say so.
- **F-45.** The confirm re-run's report now states its mode, which makes the report more truthful. The set name in its title goes through `md_safe`, and the report's file name holds no typed text.
