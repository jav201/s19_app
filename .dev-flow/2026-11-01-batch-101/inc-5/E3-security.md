## Rows and tests (security lens)

- The CRC cases use an independent oracle (`zlib.crc32` of the session range bytes) and pin both "hidden → stale, 0 recomputes" and "displayed → recompute after the quiet time". With SEC5-2's /7 added, every outcome of every write site has a case.
- R-CRC-PREVIEW-002.5/6 injects the fault after the engine wrote. That is the right shape for the "hook after `try`/`except`" placement. An exception type outside `(ValueError, KeyError)` propagates and ends the app, so no stale display survives it.
- R-CHKED-026/2's oracle (`Checks: 2 passed, 1 failed`) and the result row with the actual bytes fail on the base path. Good.
- No row is non-EARS, and none names a function or file in its statement.
