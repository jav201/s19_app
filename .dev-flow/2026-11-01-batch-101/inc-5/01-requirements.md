## User stories

### US-CRC-FRESH-2 — the CRC Designer's coverage follows bytes written into the image
As the operator, I want the CRC Designer's coverage CRCs to describe the loaded image as it is after I apply a change document, save a patched image back or save the project, so that I never copy a stale checksum into an image or a release record. (Inc 13 D-4, E3 SEC-3.)

### US-CHK-KEEP-1 — my included parameters survive a Write and a return to the Check Editor
As the operator, I want the parameters I included to stay included after I write the spec and when I come back to the Check Editor, as long as the loaded A2L still lists them. (F-26, D9-12.)

### US-CHK-SPEC-1 — a spec I load back is the spec I wrote
As the operator, I want a spec I pick in the Spec dropdown to come back with its parameters named and included, and with the expected bytes the spec declared, so that Write does not silently re-baseline it and Validate tells me whether the image still matches it. (F-27, D9-11.)

## Definitions

Proposed for the canon (`E1-rulings.md` §2 lists each change). Terms of S13 CTX-DESIGNER and S9 CTX-CHECK-EDITOR are used as the canon and Inc 13 define them.

- **Loaded image changes** (S13 CTX-DESIGNER; **amended** from Inc 13's definition). The session's loaded image (S5 CTX-FILES) is set, replaced or cleared — a load, a project load, an unload — **or the system writes bytes into it in place**: a Patch Editor apply (whether it ends with its `Apply: …` status or with a `Patch Editor: <error>` status), a Patch Editor save-back (the operator confirms *Save patched image as*, whatever its outcome), or a Save project commit that writes the image. Inc 13's sentence "A byte change made in place (the apply of a change document) is not an image change here" is withdrawn. *Stale coverage* and *pending change* keep Inc 13's text and so cover the in-place writes.
- **Fixture image.** Inc 13's: `0x8000`–`0x8007` = `00`…`07`, `0x8010`–`0x8017` = `10`…`17`, `0x8008`–`0x800F` absent; loaded from an S19 file holding those two records. Under the first-shown Ranges `0x00008000-0x00008008, 0x00008010-0x00008018` its oracles are concat `0x9C5BCBBD`, fill `0x2A8A3950`; with `0x8003` = `0xAA` concat `0x08DAAFB7`, fill `0x35D90BC3`; with `0x8003` = `0xBB` concat `0x614BD0E8`, fill `0xE1E79AB1` (each `zlib.crc32` of the 16 range bytes, fill with 8 × `0xFF` between).
- **Field set** (S9 CTX-CHECK-EDITOR). The fields of the Check Editor: the included parameters in inclusion order, then the memory rows in table order.
- **Field loaded from a spec** (S9 CTX-CHECK-EDITOR, new). A field the last spec pick created that has stayed in the field set since. A parameter excluded and included again, and a memory row removed and added again, are fields included in this session.
- **Field included in this session** (S9 CTX-CHECK-EDITOR, new). Any field of the field set that is not a field loaded from a spec.
- **Declared field** (S9 CTX-CHECK-EDITOR, **amended**). A field loaded from a spec, or a field included in this session whose whole range has bytes in the loaded image. (Canon: "A field whose whole range has bytes in the loaded image.")
- **Named parameter of a spec entry** (S9 CTX-CHECK-EDITOR, new). The parameter of the loaded A2L whose name is the entry's symbol, when the loaded A2L lists it with the entry's address and byte count; otherwise the one parameter of the loaded A2L whose address and byte size are the entry's address and byte count, when exactly one has them. An entry has no named parameter when no A2L is loaded, when no parameter or more than one has its address and byte count (and no symbol names one of them), or when an earlier entry of the same spec has the same named parameter. (The entry's symbol is the tag spelling the read records when it resolves the entry through the loaded A2L, canon R-CHG-SYM.9.)
- **Case 08.** Inc 4's: `tools/synth/make_release_case.py`, seed `20260001`, 1.0 MB (`firmware.s19`, `firmware.a2l`, `demo_check.chk.json`). In the pilot the first two measurable parameters in A2L order are `VALUE_0001` (`0x00000000`, 1 byte, `6C`) and `VALUE_0002` (`0x00000014`, 2 bytes, `A0 BE`); `0x00C00FFC`–`0x00C00FFF` holds `FF FF FF FF` and no parameter. Tests take names and addresses from the generated A2L, not from this line.
- **Pilot spec.** The spec Write writes from case 08 with `VALUE_0001` and `VALUE_0002` included and the memory row `0x00C00FFC`, label `SERIAL`, size 4: three `bytes` entries `0x0` `6C`, `0x14` `A0 BE`, `0xC00FFC` `FF FF FF FF` (pilot, `written_entries`).
- **Planted twin A2L.** An A2L written by the test that lists two parameters, `ALPHA` and `BETA`, both at `0x00000014` with 2 bytes, and nothing else at that address.
