Shared terms (`01-requirements.md` Definitions): **fixture image**, **case 08**, **pilot spec**, **planted twin A2L**, **planted moved / renamed / resized A2L** (address *A*), **named parameter**, **still lists**. **Q** = the CRC Designer quiet time, injected with `monkeypatch.setattr(crc_designer_view, "CRC_RECOMPUTE_S", …)` (Inc 13 idiom). **Recompute count** = Inc 13's `designer_recompute_counter` fixture (`tests/support/b101_designer.py`). **Drive** = keys, clicks and dialog fields through Textual's pilot. `Button.press()` on a shipped button or an `Input.value` set is the product route for the output (`full`) but makes the drive partial (`full (output); drive partial`); a message posted to the app, a panel method called directly, or an injected fault makes the case `partial`. **D** = `tests/test_b101_designer_writes.py`, **C** = `tests/test_b101_check_spec_keep.py` (the files the orchestrator split **N** into). **E5 (C-1 … C-10):** the marks were first moved to the coverage audit's values (`E5-coverage-audit.md` §2: 10 cases `partial`); C-2 (`0x0` patched before the R-CHKED-056 pick) and C-3 (the recompute count taken before the trigger) then made 056/1–/3 and 002.5/3, /4, /7, /8 discriminating again, and C-4 added the black-box ATs AT-I5-1 … AT-I5-4; C-6 and C-10 added 6 cases. **Result** is per run: the Check Editor cases ran 3/3 on the final tree (`../evidence/inc-5/e5c-02`, `e5c-03`, `e5c-04`), the designer cases once with 3 fresh apps per node (`e5c-02`); every run is `-q` with node ids from the xdist output; Windows is `not_run` (operator rule).
