# Inc 10a — test cases (ISO/IEC/IEEE 29119-3), E1, E3 correction

One case per coverage item `<requirement id>/<n>` of `01-requirements.md`, written at E1 before any test and corrected at E3; Tests, Coverage and Result filled at E4 integration (`E4-integration-notes.md`; case texts corrected there are marked with their I-Dn) and updated at the E4 rulings (§6 there, round 2 in §7; cases changed or added are marked "(changed at E4, E4-Rn)" / "(added at E4, E4-Rn)"). At E1 every result was `not_run` and **Coverage** `gap` until E4 wrote the test; a planned test was named `planned` with its file. Planned files (new; `tests/test_id_registry.py` `EXPECTED_SCANNED_TEST_FILES` re-measured at integration): **H** = `tests/test_b101_hex_jump.py`, **F** = `tests/test_b101_unload_focus.py`. Moved at E3 with their rows, ids unchanged: R-A2L-048/1–3, R-A2L-049/1, R-SEG-PREV.21/1–2, R-SEG-PREV.22/1 (and file **W**) are in `../inc-10b/02-test-cases.md`.

**Wait rule** (E3 A10-10): every planned test waits on product state through `tests/support/timing.py::wait_until` (the Inc 13 ruling), never a single `pilot.pause()`: the scroll reset lands after a pause (E3 architect P6), the focus landing after a refresh (A10-01), the Save project dialog's close later still. Each negative assertion (no focus in `#screen_split_join`, 0 markers, start kept, 0 files) follows a positive wait in the same test.

**Window-switch rule** (E3 addendum, Inc 12 D-2): every planned test switches windows with the keys (`1`–`9`, `=`, `]`, `0`) or `action_show_screen(<key>)`, never `action_view_main`, `action_view_alt` or `action_view_mac` (removed by Inc 12). No test drives the issue jump (`_jump_to_validation_issue`, `_jump_to_validation_issue_object`): no product route runs it, and Inc 12 removes it. The cases that drove it are withdrawn and kept by id (R-TUI-018.1/5, R-TUI-018.3/1, R-TUI-040.12/2).

Shared terms (`01-requirements.md` Definitions): **case 08**, **fixture three**, **join-fill pick**, **in-place write**, **jump**, **second row**, **view rows**, **first view row**. **MAC below** (test term, E3 A10-03): fixture three plus a MAC file with one valid record at `0x00001000`, outside the image (view rows `0x00001000`, `0x00008000`, `0x00008010`, `0x00008020`). **Drive** = keys, clicks and dialog fields through `run_test(size=(120, 56))` (measured 118 × 54); a go-to is `g`, the text, Tab, Enter (Enter in the box runs nothing today, `E1-rulings.md` §5 N-1). **Second-row check** = the plain text of the view's Static: the first line that starts with `> ` or `  0x` is row 1; the second such line's address = the target row's base. Each expected count is per run; threshold 3/3 runs.
