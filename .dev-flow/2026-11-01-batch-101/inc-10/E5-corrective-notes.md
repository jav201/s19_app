## 2. Decisions taken in this pass

- **E-1 (CR-9).** Read as "accepted as they are": the ruling lists no fix (its other rows say "Accept: <fix>"), so the stale comments of `_step_finalize` and `_rehome_focus_after_load`, the `hexview.py` doctest literal and the thin docstrings of `_note_focus_landing` and `_load_tree_gone` are left. The one CR-9 item another ruling fixes — the `check_action` docstring — is fixed under SE5-3.
- **E-2 (CR-1, sharing with the renderer).** Not shared; graph I-5 does not allow it. I-5 pins `hex_row_bases` and `_hex_view_rows`, and no parameter of `render_hex_view_text`. Its present parameters cannot take the view rows as they are: passed as `row_bases`, `hex_row_bases(view rows, the image's bases_set, MAC set)` re-sorts the list on every render whenever a MAC row lies outside the image, and passed without `bases_set` it builds `set(view rows)` per render — both worse than today. A `view_rows=` parameter is an interface change the graph has not ruled (and Inc 10b relies on I-5). Written in the docstring and the graph node.
- **E-3 (CR-2, behaviour).** "Behaviour unchanged" holds on every reachable path: the painted first row is always one of the view rows (each render sets it to `rows[start]`), and `bisect_left` of a present value is its index. For an address no longer among the view rows the helper gives the next row (bounded by the render's clamp) where the copies gave `0`. The existing 040.8 / 040.11 nodes pass unchanged.
- **E-4 (SE5-1, condition and cost).** The condition is the requirement's own state — `file_type == "mac"` is "a MAC file loaded and no S19 or HEX image" (a primary unload or a MAC-only load) — and applies to a save as only (`walked` is set only then). As the security review states, every S19 / HEX variant of the open project is dropped, not only the unloaded one: after D-7 the session does not know which file was unloaded. A MAC-only load made while a project is open drops them too, by R-WS-LOADED.19's text. No existing test drives a save as from a MAC-only spine (grep of the save tests that load a MAC); the batch-end full suite is the wider check.
- **E-5 (case ids).** QA-3's arms take the ids the audit proposed, R-TUI-040.11/6 … /9. SE5-1's cases are the ruled /19/3 and /19/4. CR-3's case takes the next free id of the rail-key row, R-SHELL-FOCUS.2/8; SE5-5's node, which the ruling did not name, R-SHELL-FOCUS.3/3 — a guard no node can fail is unproven (Inc 9 E5's reason), and the unload's landing is the one SE5-5 names.
