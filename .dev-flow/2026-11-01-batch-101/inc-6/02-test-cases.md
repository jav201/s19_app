# Inc 6 — test cases (ISO/IEC/IEEE 29119-3), E1

One case per coverage item `<requirement id>/<n>` of `01-requirements.md`, written at E1 before any test. Shared terms are that file's Definitions. Abbreviations: **PE** = the Patch Editor shown at 118 × 54 with the fixture image loaded; **proj open** = project `proj` loaded through the app's project load; **L** = the planned file `tests/test_b101_patch_lifecycle.py`. Every planned node is black-box through the shipped controls (keys, buttons, the dropdown's value, the dialogs) and reads painted widgets or written files. **Tests** names the planned node and its planned mark; **Coverage** stays `gap` until E4 writes the node; **Result** is `not_run` for every case.

**Waits (engineering rule 7, `docs/engineering-rules.md:203`; E3A-08).** Every planned node waits through the shared `tests.b97_probes.settled` for a sign that the app handled its press, posted message or set value, also when it asserts that nothing changed; it never reads after fixed pauses alone. The sign of each negative arm is named in its Expected result: a refusal status, a status-log line read with `StatusLog.since(mark)` (rule 5), or a later press's painted effect. **Painted state (E3A-07).** A row that must be hidden or shown is asserted on the painted screen (its label text absent or present); its `hidden` class serves only as the wait predicate, so these cases stay `full`. Cases added or changed at E3 cite the finding or ruling (`E3-rulings.md`).
