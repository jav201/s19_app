## Checked, no finding

- **Node ids:** a decorator above `parametrize` plus a wrapped bound side renames, moves or re-parametrizes no node. The new nodes all live in a new file. Inc 1's four files are not touched.
- **Timing-arm census:** an independent AST census (scratchpad, liberal taint) found the same 31 static arms and the same 37 upper bounds as `E1-slice.md` §3 (5+1+3+16+2+5+1+1+3). The other clock users are deadline loops (`test_b100_workers.py`, `test_b100_reuse.py`, `test_b99_load_project.py`, `support/b100_save_dialog.py`), print-only intervals (`test_report_service.py:692-700`, `test_tc_b100_31_copy_ceiling_2000_files`), or file times (`test_sync_evidence.py`, `test_b100_announce.py:303`). No other clock source (`loop.time`, `timeit`, `datetime`) exists in `tests/`. The unlisted sampled arms in `test_b100_workers.py` (`:2960-2975`, `:3158-3172`) stay out under D-6.
- **`report_margin` semantics:** each arm keeps its own operator. CI scaling is untouched because `timing_bound` is evaluated before the call. The interval is evaluated before the bound, so the record exists before a failing comparison (R-TST-046). Pytest's assertion rewriting calls the function once. In chained (`0.1 <= q <= rm(…)`) and `and` (`timing and timing[0] < rm(…)`) forms, the report is skipped when the left part fails; no upper bound was exceeded then. On CI, a margin is against the doubled bound.
- **CI lanes:** the two steps split the suite (`not serial_timing` / `serial_timing`), so runtime does not double; the cost is one extra collection. The `snapshot` job is untouched, with no `needs`. `-rs` prints the skip reasons R-TST-014 reads: every history arm's skip text holds "unavailable" (`test_b97_flow_builder.py:818,1707`, `test_b97_flow_execution.py:98,230,775,2006`).
- **Shared waits:** the check-first order is kept in the two `wait_for` and the panel waits, and pause-first in `settled` (`b97_probes.py:319-323`). W1–W9 match the base texts. W5 was an `assert` in a module that is not rewritten; it becomes an explicit raise with the same text. `asyncio.sleep` yields to the app's loop under `run_test`, as `_wait_yielding` does. No caller expects a timeout (no `raises` or `except AssertionError` near a call). No caller of `load_project` also wraps `_install_prepared_project`. Only `test_b100_document.py:1072-1074` uses the returned interval. `_install_prepared_project` is looked up on the instance when `call_after_refresh` is scheduled (`s19_app/tui/app.py:13657`), so the instance wrapper is the one called.
- **Module identity:** `timing` is imported only as `tests.support.timing` (4 sites), so `_QC_TM_PENDING` is one list per process.
