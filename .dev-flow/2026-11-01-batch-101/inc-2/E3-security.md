## Confirmations (design level, state `planned` until E4/E5 verify)

- **Triggers and permissions.** The triggers stay `pull_request` and `push` on `main` / `main-tui`, with no `pull_request_target`, `workflow_run` or `workflow_dispatch` added to `tui-ci`. Top-level `permissions: contents: read` is unchanged. No `secrets.*` reference, no new `uses:` action, and no new `pip install` (pytest-xdist is held out by O-2). Fork PRs run with a read-only token and no secrets. `snapshot-regen.yml` is unchanged (manual, read-only).
- **`fetch-depth: 0`.** It clones the full history of a public repository: no new exposure, because everything in history is already public. It applies to the `tui-ci` job only. The history arms run `git show <constant-sha>:<constant-path>` with an argv list and `check=True`, with no shell and no test-derived input.
- **Static guards.** `suite_census.py` is specified as a pure AST census (`timing_arms`, `unreported_upper_bounds`, `newest_line_waits`, `shared_wait_bodies`): it parses source text and never imports or runs a scanned module. E4 keeps it that way (stdlib `ast` / `pathlib` / `tokenize` only, no `importlib`, `exec`, `runpy` or `compile(..., "exec")` that is later run). Planted sources go under `tmp_path`.
- **Writes.** `report_margin` and `qc_tm_drain` work in memory. The hooks write to `TestReport.user_properties` and the terminal only. Junit XML is written only when the operator passes `--junitxml`, and CI does not. `pytester` inner runs write under their own tmp directory. `load_project` sets an instance attribute on the app and removes it in `finally`, so no product file changes. Nothing in the design writes to the repository tree, outside tmp paths, or to the real `%LOCALAPPDATA%\s19_app`. The existing session guard `_recent_store_session_guard` (`tests/conftest.py:60`) and the per-test `_recent_store_isolated` (`:86`) stay in force and cover the new tests. Inner `pytester` runs (in-process or subprocess) inherit the patched `LOCALAPPDATA`.
- **F-2 (callable `failure`).** The callable is evaluated only when the wait raises and builds a string from local test state. I see no security effect, and I confirm the I-1 signature `failure: str | Callable[[], str]`.
