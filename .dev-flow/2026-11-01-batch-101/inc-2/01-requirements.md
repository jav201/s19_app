## User stories

### US-TST-1 — a release gate without false timing failures
As the operator, I want the release gate on the LAN Linux host to run the full suite in about an hour, with the wall-clock timing arms run apart and serially, so that a red gate names a real defect and not the load of eight parallel workers. (Batch-100: 13 timing arms failed under `-n 8` and passed serially.)

### US-TST-2 — CI runs what the local gate runs
As the operator, I want CI to run the same two lanes and every arm that needs the repository history, so that a CI verdict covers what the local gate covers and no arm skips on CI only.

### US-TST-3 — wait and timing rules that a guard enforces
As the author or reviewer of a later increment, I want every shared wait to be bounded by the wall clock and to yield, every timing arm to report its margin, and every status oracle to read all the lines its action painted, so that a thin margin, a clock stopped by a poll or a newest-line oracle is found at the increment gate, not at the batch end.

### US-TST-4 — no unread CI result in the v1.0.0 baseline
As the operator, I want batch-100's deferred CI run recorded against the 5 known failures, so that the release baseline holds no CI result that nobody read.

### US-TST-5 — a version bump keeps the report goldens
As the operator, I want the report goldens to hold no tool version, so that a release version bump (0.1.0 → 1.0.0rc1 broke 7 goldens) needs no golden re-pin. [operator scope item, E3 round 1]

## Definitions

- **Timing arm.** A test whose verdict compares a measured wall-clock interval with a bound. [E3A-2] Static forms — an ordering `assert` (`<`, `<=`, `>`, `>=`) reached from the test (its body, a nested function, a method of its `Test*` class, or a function of the same module it calls, transitively) where one operand: (a) is or holds a subtraction with a clock call or a **clock stamp** on either side — a clock stamp is a name, subscript, attribute or list item bound to a clock call or appended from one (`painted_at[0] - started`, `fakes.preview_times[start] - key_at`, `stamp - start`); (b) is a name or subscript bound, by tuple position or dict key, to such a subtraction or to the matching position of a value returned by a function that returns one (same module, nested, or a test support module); or an item of a list that was `.append`ed such a value (`timing.append(time.perf_counter() - t0)` read as `timing[0]`); or either branch of a conditional expression that is one (`timing[0] if timing else None`) [N-1]; (c) is or contains a `timing_bound(…)` call; (d) is or contains a `report_margin(…)` call. `<clock>` is `time.perf_counter`, `time.monotonic`, `time.time` or their `_ns` forms, under any import alias (`import time as _time`, `from time import perf_counter`), also when the import is local to a function (`load_project`'s `import time`) [N-1]. **Sampled timing arms** (verdict counts samples of a transient state taken over wall time; no static form) are listed by node id: at `b3bf42e` exactly `tests/test_b100_busy.py::test_at_b100_17_worker_load_of_an_8_mib_s19_by_keys`. **Marked set** [E3A-16]: the tests whose own decorator list holds `pytest.mark.serial_timing`; a module- or class-level `pytestmark` that carries `serial_timing` is refused by the guard (one place to read the mark).
- **Upper timing bound.** [E3A-3] The bound side of an ordering comparison in a timing arm whose interval side must stay below it (`interval < b`, `interval <= b`, `b > interval`, the upper half of a chained `a <= interval <= b`), where the interval side is an interval value of forms (a) or (b) of *Timing arm*: a direct subtraction, a stamp difference, or a name or subscript tainted **by tuple position or dict key**, an item of a list `.append`ed an interval, or either branch of a conditional expression that is one [N-1] (a name unpacked from a non-interval position, a key never assigned an interval, and a call such as `len(…)` are not interval values). Any expression on the bound side counts — a literal of any type, a constant, `timing_bound(1.0) * 2`, a call — with no type rule. Lower bounds and comparisons of counts are not upper timing bounds.
- **Parallel lane / serial lane.** Parallel lane: `pytest -n 8 -m "not serial_timing"`. Serial lane: `pytest -m serial_timing` with no `-n`. The release gate is the parallel lane, then the serial lane, on the LAN Linux host.
- **Shared wait helper.** A function of a test support module (`tests/support/*.py`, `tests/b97_probes.py`) that waits for a condition by polling and is called from 2 or more test modules. At `b3bf42e`: `b97_probes.settled`, `b100_load_dialog.wait_for`, `b100_projects.wait_for`, `b100_projects.read_load_result_panel`, `b100_projects.dismiss_load_result_panel` (2 waits), the two waits inside `b100_projects.save_case01_project`, the wait inside `b100_projects.append_variant`: 7 functions, 9 waits.
- **Margin.** `(bound − measured) / bound × 100`, in percent, one decimal. Negative when the measured interval exceeds the bound.
- **Margin report.** One record per upper timing bound: `<label>|<measured>|<bound>|<margin>` with measured and bound in seconds to 3 decimals and margin to 1 decimal.
- **Newest-line wait.** [E3A-6] A call of a function whose name holds `wait`, `settle`, `until` or `poll`, with a predicate lambda that reads the newest status line: the string constant `#log_line_4`; `….log_lines[-1]`; a call of a **newest-line reader**; or `[-1]` applied to a call of an **all-line reader**. A newest-line reader is a function of the same module or of a test support module whose body holds `#log_line_4` or returns `….log_lines[-1]` (e.g. `b97_probes.last_status`). An all-line reader is such a function that builds `#log_line_{…}` with an f-string or returns every `log_lines` item (e.g. `painted_log` in `tests/test_b100_workers.py`). Readers resolve per module (a local name, or a name imported from a support module), never by bare name across the tree.
- **Newest-line baseline.** The count of newest-line waits per test file at `b3bf42e`, as E4's own implemented census measures it there; the dict is generated by that census on the base tree, never typed from a probe count (the E3 probes gave 89 sites in 18 files and, independently, 83 in 15 — neither is a threshold) [R2, E3A-6 note].
- **History arms.** The 6 tests that read a past commit with `git show` and skip when it is unreachable: `test_b97_flow_builder.py::test_tc_b97_19_builder_reach_guard_on_9c7beaf`, `test_b97_flow_builder.py::test_tc_b97_flow_css_shared_rules_byte_equal_and_section_scoped` (`09e44de`), `test_b97_flow_execution.py::test_tc_b97_25_service_reach_guard_on_9c7beaf`, `::test_tc_b97_25_module_constant_in_english`, `::test_tc_b97_25_panel_constants_carry_no_spanish` (`9c7beaf`), `::test_tc_b97_flow_execution_css_section_is_scoped` (`b514b07`, R2-CI).
