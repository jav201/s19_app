## 2. New scope: version-agnostic report goldens (US-TST-5)

The version bump to `1.0.0rc1` broke the goldens that pin `Tool version: 0.1.0`. The coordinator re-pins their bytes on main as a hotfix. Inc 2 makes them independent of the version.

- **Decision.** Each of the 7 report goldens with a version holds the token `<TOOL-VERSION>`. The shared canonicalizer `tests/conftest.py::canonical_report_bytes` replaces the token with `s19_app.version.__version__`, read at call time, so a future bump changes no golden. The golden side changes and the produced side does not. A report that prints any other version still differs, so the version line stays checked; a mask would hide a wrong version. The token style matches the existing `<RUN-ROOT>` token in the same function.
- **Reach.** 5 of the 7 golden tests already compare through `canonical_report_bytes` and need no edit. Two need one line each:
  - `tests/test_report_service.py::test_at288_report_hex_sections_identical_after_move` compared raw bytes. It now compares with `canonical_report_bytes(pinned)`, and its capture branch writes the token in place of the version.
  - `tests/test_report_addendum_bound.py::_golden_documents` decoded the raw golden. It now decodes the canonical form.
- **Coordination.** `tests/test_report_addendum_bound.py` is one of Inc 1's files. Inc 2 edits it only after the rebase onto main (Inc 1 is merged), and only with the orchestrator's go. **Asked here.**
- **Rows:** R-TST-080 (no version in a golden; the 7 goldens hold the token), R-TST-081 (the package version is substituted), R-TST-082 (a wrong version still fails). Cases R-TST-080/1, 081/1, 081/2, 082/1, 082/2 (an E5 mutant run per producer).
