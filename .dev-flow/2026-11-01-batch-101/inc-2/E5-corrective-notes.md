## 5. New finding (not fixed: outside the ruled set)

- **N-1 (census, MINOR).** `_assert_is_arm` (`tests/support/suite_census.py:774`) marks
  as a timing arm any `assert` that holds a `timing_bound` or `report_margin` call, and
  any comparison with an interval operand, whatever the operator. The Definition names
  only ordering asserts (`<`, `<=`, `>`, `>=`).
- **Effect.** The error is on the safe side: the worst case is an extra `serial_timing`
  marker. It showed up when `assert report_margin(…) == 1.0` in the E5S-3 test was taken
  for an arm, and the test now binds the value first.
- **Proposed fix.** Restrict both branches to ordering operators, then re-check the
  real-tree arm set (expected unchanged: 31 static arms plus the planted guard arm).
  That needs its own increment or ruling.
