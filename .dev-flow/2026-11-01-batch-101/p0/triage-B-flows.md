## Groupings

- **F-48 + F-49 — one increment**: both live in the same `run_flow` ExternalStepBlock branch (flow_execution_service.py:1060-1124) and the same ref-resolution seam (`_resolve_manifest_entry`). Introducing an external-output ref binding that the executor resolves to the newest confirmed copy fixes the missing-reference gap (F-48) and the stale-first-copy read (F-49) together.
- **F-45 + F-50 — one design conversation, likely two increments**: both concern the external-step confirm path. F-50 decides where Confirm lives (Builder needs the Flow-Execution confirm handler); F-45 is the report side-effect of the existing confirm re-run (`on_flow_execution_panel_external_step_confirmed` → `run_chain_set` always writes a chain-set report). If the F-50 fix reuses the same handler, F-45's suppression belongs in the same touch point.
- F-28, F-36, F-46 are independent single-site fixes (schema routing, dropdown table, name reset) with no shared root cause; they can ship as three separate S/M increments.
