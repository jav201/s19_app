## Findings

| Id | Severity | Row / node | Finding | Proposed fix |
|---|---|---|---|---|
| S-1 | MEDIUM | R-A2L-036.2, .3, .4; `extract_memory_segments` | The pair rule ("first two adjacent record words, after the name, that are both numbers") does not stop when the record's own base/size pair is broken; it scans on into the offset words. A standard record with a non-literal base or size (a typo `0x1000BAD`, a leading-zero decimal `0400`, which `int(w, 0)` rejects) gets base −1 / size −1 from the `-1 -1` offset placeholders, and with real offsets gets base = the size word, size = the first offset (probe). R-A2L-036.4's intent ("no base") is broken; the −1/−1 row is listed by `_a2l_rows` (`HEX8(-1)` = `0x-0000001`), and the real-offset case is a wrong segment covering wrong memory: wrong Region column, wrong report `mem=`, wrong `a2l(n)` rows, and a Split / Join export of the wrong range. The S1 case (`0x1000 BAD`, no offset words) cannot fail on this. | Anchor the base: the base is the **first** record word after the name that is a number and does not come from a quoted text; if the word after it is not a number, the segment has no base and no size (no further scan). This keeps all 4 fixture shapes and `S3 "" 0x10 DATA 0x20`, and a quoted numeric long identifier still never wins (the helper keeps a `quoted` flag per word). Reword R-A2L-036.2 / .4 accordingly; add cases `S1b "" DATA FLASH INTERN 0x1000 BAD -1 -1 -1 -1 -1` and `S1c "" DATA FLASH INTERN 0xZZ 0x1000 0x400 0x800 -1 -1 -1` → base and size absent. |
| S-2 | MEDIUM | Definitions "Number"; R-A2L-036.2, .3; graph `[I/O: A2L file]`; `_a2l_rows`, `fill_range`, `fmtB` | No plausibility bound on base/size, and the "Number" definition is wrong for the code it pins: `int(w, 0)` also accepts underscores (`0x1_000`), non-ASCII digits (`٣`, `１２`) and hex/octal/binary of unlimited length (the 4 300-digit limit applies to decimal only — the Definitions and graph E2-2(b) claim otherwise). A segment `0x0 0xFFFFFFFF` (or wider, or a negative base) covers every address, so every tag takes that segment's region; picked in Split / Join with intra-gap fill, `fill_range` builds `{addr: … for addr in range(start, end)}` — ~4 G entries → memory exhaustion / hang; a size above ~2^1024 makes `fmtB` (`n / (1 << 20)`) raise `OverflowError` while painting the a2l table. Pre-existing for the standard record shape (the base reader also used `int(w, 0)`), but F-29 makes more shapes produce a base and makes the a2l source reachable on the release demo. | Define Number by a pattern, not by `int(w, 0)`: ASCII only, `[+-]?(0[xX][0-9A-Fa-f]+ \| 0[oO][0-7]+ \| 0[bB][01]+ \| [0-9]+)`, no `_`, at most 16 significant hex digits (decide and state how `0400` reads: decimal 400 or not a number). Add one N-row: "If a segment's base is below 0, its size is 0 or below, or base + size exceeds 2^32, then the system shall give the segment no base and no size" (32-bit = the widest S-record / HEX address the app loads; widen only if a 64-bit loader exists). Cases: `0x0 0x100000001`, `-0x100 0x1000`, `0x0 0x0`, `0x1_000 0x10`, `٣ 0x10` → no base. Backlog (outside this slice): a size cap or confirm before a Split / Join fill export materialises more than N MiB. |
| S-3 | LOW | `_iter_sections`; O-4 | Deep nesting (probe: 3 000 levels) raises `RecursionError` in `parse_a2l_file` (`extract_a2l_tags`) before validation runs, with or without an IF_DATA root; `_a2l_attach_worker` catches it (`except Exception`) as a load failure, so it is contained, not an app crash. The new skip does **not** change the crash point as long as `_iter_sections` passes `inside_if_data` down as an argument (one frame per level). Computing the flag by walking each node's ancestors would add O(depth²) time. | Implement `_iter_sections` with an explicit stack of `(node, inside_if_data)` pairs (same pre-order; no recursion; the flag inherited, never recomputed). Keep O-4 for `extract_a2l_tags` / `extract_memory_segments` in the backlog. Optional E4 case: 1 500 nested sections under IF_DATA → `_iter_sections` returns 1 500 pairs without `RecursionError`. |
| S-4 | LOW | R-VAL-032.3; D-1 | The IF_DATA exemption relies on the parser's nesting, and `build_section_tree` never checks that `/end <NAME>` matches the open block. A file missing `/end IF_DATA` with a stray `/end` elsewhere parses with no structure error and, after Inc 11, raises nothing at all for the blocks that slid into IF_DATA (probe: base 1 warning, target 0). The unbalanced case still raises `A2L_STRUCTURE_ERROR`. No value the app reads depends on these warnings (tags and segments are walked regardless of IF_DATA), so impact is a lost hint, not wrong data. | Accept for Inc 11 and record it beside D-1. Backlog: "If a `/end` names a block other than the open one, raise `A2L_STRUCTURE_ERROR`" (closes the blind spot for every block, not only IF_DATA). |
| S-5 | LOW | R-TUI-042b.5 [OR-2]; `_filtered_validation_issues`; I-5 | `ValidationSeverity` has five members (ERROR, WARNING, INFO, OK, NEUTRAL); `_SEVERITY_RANK` built from the three of `SEVERITY_ORDER` gives `KeyError` for an OK / NEUTRAL issue (probe), and the sort runs on every paint, PgDn and row selection, so one such issue would break the Issues screen. No producer puts OK / NEUTRAL into `_validation_issues` today (grep: those are MAC-row states), so latent. | Rank with `_SEVERITY_RANK.get(issue.severity, len(SEVERITY_ORDER))` (unknown severities last, stable). Add one G2 case: a list holding an OK issue sorts without error and keeps it after INFO. |
| S-6 | LOW | R-A2L-036.2 ff.; `_memory_segment_record_words`; `_strip_a2l_comments` | The helper joins meta and lines and strips comments over the joined text; `_strip_a2l_comments` carries its quote state across the line join, so an unterminated `"` on one line keeps a later `/* 0x10 0x20 */` comment and its words become base/size (probe). Malformed input only. | Strip and split each text with the quote state reset at each line (A2L strings do not span lines), keeping block comments that span lines removed; or reject a record whose texts hold an odd number of unescaped quotes (no base). One robustness case in G1. |
| S-7 | INFO | R-TUI-042b.5 [OR-2] | Cost on very large lists: stable sort of 1 M issues 0.10 s (Linux host); called about three times per Issues action, on top of the existing O(N) copy. A hostile A2L can create ~200 k unknown blocks per second of parse. Acceptable. | None required. If wanted: sort once where `_validation_issues` is assigned (4 sites) and keep the filter order-preserving. |
| S-8 | INFO | R-TUI-042b.1, .2, .4, .6; R-TUI-025.2, .6 (removal of the WARNING → INFO re-labelling) | No real defect is newly hidden by the view change: the re-labelling was display-only (filters already used the true severity, F-03). Newly surfaced, correctly: any former curated name outside IF_DATA (e.g. a top-level `PAGE`) shows as a WARNING. Newly hidden: unknown names inside IF_DATA (D-1, accepted) and S-4. Messages still reach the screen only through `safe_text` (C0/C1 scrub, no markup); with the `[A-Z0-9_]+` regex gone, hostile names take the ordinary WARNING row path, which is the safe one. | Keep the C-17 hostile-name arm in the TC-B94-19 rewrite and make it assert both halves: a name holding `\x1b[31m` and `[red]` / `[/b]` renders as literal text with no control byte in the WARNINGS group. |
| S-9 | INFO | R-A2L-120 … 123; `render_curve_description` | No new injection surface: the added line is a constant, `x_note` is set by code (not file text), and the body `Static` is `markup=False`. Pre-existing, outside this hunk: the modal title `Label(f"Parameter: {title}")` uses Textual's default `markup=True` on the file-derived tag name (a name containing `[/b]` would raise a markup error when the window opens), and the body text is not control-scrubbed. | Backlog: build the title and body through `safe_text`. No change asked of Inc 11. |
| S-10 | INFO | D-9; `RECOGNIZED_A2L_BLOCKS` | The list's breadth has no security effect (an extra name only silences a WARNING; a missing name only adds one). From memory of ASAM MCD-2 MC 1.7, `AR_COMPONENT` (a block inside FUNCTION, new in 1.7) looks missing; not verified against the standard text, which is not at hand. | Check `AR_COMPONENT` against the keyword index when available; otherwise the D-9 accepted risk stands. |
| S-11 | INFO | `_memory_segment_record_words` | The helper tokenises all own lines of a MEMORY_SEGMENT before scanning (the base stopped at the first record line), and `extract_memory_segments` runs up to three times per A2L (`extract_a2l_tags`, the parse log, `_a2l_rows`). Linear in block size; memory grows with a huge hostile block. | Optional: yield words lazily and stop at the base pair; the types only need the words before it. |

No secrets, credentials, external tools, auth or deploy surface are touched by this increment. The export file name of an a2l row stays safe: `sanitize_export_segment` maps the (now record-line) segment name to `[A-Za-z0-9_-]`, so a quoted name like `"..\x"` cannot leave the export folder.

## Verdict

**PASS-WITH-NOTES** — no HIGH finding. S-1 and S-2 are design defects in changed rows (R-A2L-036.2 / .3 / .4 and the "Number" definition) that let a malformed or hostile MEMORY_SEGMENT produce a wrong or unbounded segment; the fixes are inside this increment's slice (`extract_memory_segments`, its helper and rows) and should be folded into `01-requirements.md`, `02-test-cases.md` and the graph before E4. S-3, S-5, S-6 are cheap robustness changes for E4. S-4, S-9, S-11 and the Split / Join fill cap go to the backlog. Evidence states: S-1, S-2, S-3, S-5, S-6 `executed` (probe) / fix `planned`; S-4 `executed`; S-7 `executed`; S-8, S-9, S-11 `n/a — read only`; S-10 `not-run` (standard not available).
