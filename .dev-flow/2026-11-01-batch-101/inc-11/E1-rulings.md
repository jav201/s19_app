## 3. Decisions

- **D-1 — IF_DATA content is not judged (F-02).** The names left after the ASAM list (PAGE, SEGMENT, DAQ, EVENT, PAG, STIM, PROTOCOL_LAYER, TIMESTAMP_SUPPORTED, XCP_ON_CAN, CAN_FD, and in other fixtures CHECKSUM, DAQ_LIST, SOURCE, TP_BLOB, DISTAB_CFG, XCP_ON_* …) occur **only** inside IF_DATA in all 36 A2L files (P). Their grammar comes from the file's A2ML (the interface's own description, e.g. XCP), not from MCD-2 MC. Alternatives: (a) add the XCP names to the list — makes R-VAL-032.2's "ASAM block name" false and misses every other interface (CCP, vendor blocks); (b) keep the view's curated set — D3-12 retires it. Chosen: exempt IF_DATA descendants (R-VAL-032.3). Cost: an unknown name inside IF_DATA is never reported; it cannot change any value the app reads.
- **D-2 — the display triage is removed, not kept dormant (F-02, F-03).** D3-12: "drop the display triage and its note". A dormant curated set would still re-label a top-level `PAGE` WARNING as INFO (F-03 again) against R-VAL-032.1. Removing it touches `app.py` (import line and two count wrappers) → **OR-1**.
- **D-3 — no new row for F-03.** The canon already requires the behaviour (R-TUI-025.6, R-TUI-042b.1, .4); the defect was the triage. Inventing a row would duplicate them.
- **D-4 — F-39: verification arm plus one row, by ruling.** P0 asked for a verification arm only. E1 located the mechanism: per page the order holds; across pages it does not, and after F-02 the faulty demo still shows 3 errors on page 3 after two pages of warnings, against the legend's "Grouped list (order ERROR → WARNING → INFO)" and the guide's "the list starts with 8 errors". Proposed: R-TUI-042b.5, a stable sort by severity rank inside `_filtered_validation_issues` (one expression; every consumer — summary, panel, paging, row selection — reads that list, so they stay consistent). Within one page nothing changes (the panel already groups), so the Issues snapshot is unaffected (its 9 issues fit one page). → **OR-2**. If declined: R-TUI-042b.5 is withdrawn, AT-I11-2 asserts only the clean demo (no INFO group), and the faulty-demo ordering goes to the backlog as a located defect.
- **D-5 — MEMORY_SEGMENT reader (F-29).** Alternatives: (a) Kimi's "parse from the end" (base/size = the two hex words before the `-1` placeholders) — fails when offsets are real addresses or absent (release demo, `Plain`); (b) anchor on the ASAM grammar (PrgType MemType Attr Address Size) — fails on the release demo (`boot CODE FLASH INTERN FLASH …`, an extra word) and on `case_07` (no program type); (c) **first adjacent pair of numbers after the name** for base/size, keyword lookup for the types. Chosen (c): it reads all 4 shapes the fixtures hold and every standard record (a long identifier is quoted, so it can be a number only when written as a quoted number, and then it is not adjacent to another number). The types take the **last** keyword before the base so that a long identifier that happens to be `"CODE"` or `"FLASH"` does not win (R-A2L-036.8, .9 cases `M2`, `M3`). Comments are removed before splitting (the existing `_strip_a2l_comments` / quote-aware splitter), so a `/* 0x10 0x20 */` comment cannot become the base. P: 9 of 9 standard-shape segments keep their base values byte-identical (V161, V171, `memorysegment.a2l`, so TC-682 holds); 8 segments gain a base (`software_a.a2l` 3, release demo 4, `case_07` 1).
- **D-6 — F-21 note once, mixed case unchanged.** When no point has an axis value (the F-21 case, every NO_AXIS_PTS CURVE), one line `x: point index (axis points unavailable)` sits directly above the table header and the rows carry no note. When only some points lack one (a layout whose shape is inconsistent, already flagged by its own note), the per-row suffix stays: there the reader needs to know which rows are indexes. The model (`describe_curve_tag`, `x_note` per point) is unchanged; only the renderer changes. The existing TC-1820 assertion `"index (axis points unavailable)" in rendered` still holds (the new line contains it).
- **D-7 — engine unfreeze (planned at P0).** `validation/rules.py` and `tui/a2l.py` change. Two guards compare them with `main`: `tests/test_engine_unchanged.py::test_tc027_engine_modules_unchanged_vs_main` (TC-027, `_ENGINE_PATHS` holds `s19_app/validation` and `s19_app/tui/a2l.py`) and `tests/test_tui_issues_triage_b94.py::test_tc_b94_18_curated_set_and_engine_freeze` (TC-B94-18 freeze arm). Both turn RED on the branch and GREEN again once the merge puts the new bytes on `main` (re-freeze by merge, as batch-100 Inc 12b). → **OR-3**.
- **D-8 — visible values change as a consequence (A3).** No layout changes. Values that change: the Issues counts and rows (F-02/F-03, intended); the description window text (F-21, intended); the Split / Join `a2l(<n>)` chip and rows (F-29, intended); and, as a consequence of R-A2L-034, the A2L Explorer's Region column and the project report's `mem=<region>` for A2L files of the shapes in D-5 (release demo: 462 tags `unknown` → `flash`; `case_07`: 8 → `flash`; `software_a.a2l`: no tag inside its three segments, unchanged). → **OR-4** (confirm as in scope: it is the canon row R-A2L-034 being met, not a design change).
- **D-9 — the ASAM block-name list.** The 61 names are the `/begin` keywords of ASAM MCD-2 MC 1.7 as the designer knows the standard's keyword index; the standard text was **not** available at E1. Evidence that the list is sufficient: every section outside IF_DATA in all 36 A2L files (34 shipped fixtures, the two release-demo A2Ls) is in it, and so is each of the base's 15 names (P). Evidence that it is not too wide is weaker: a name in the list that the standard does not have would only silence a warning. E3 checks the list against the standard's keyword index if available; otherwise the risk is accepted as stated.
- **D-10 — file budget.** Planned files: `validation/rules.py`, `tui/issues_view.py`, `tui/a2l.py`, plus `tui/app.py` under OR-1 = **4, at the cap**. No test file is in the cap; 3 new test files are proposed (`E1-slice.md` §5), so `tests/test_id_registry.py`'s `EXPECTED_SCANNED_TEST_FILES` is re-measured at integration.
