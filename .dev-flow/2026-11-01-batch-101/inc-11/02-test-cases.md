# Inc 11 — test cases (ISO/IEC/IEEE 29119-3), E1

One case per coverage item `<requirement id>/<n>` of `01-requirements.md`, plus the acceptance cases `AT-I11-<n>` (black-box, through keys and dialogs). Written at E1, before any test; updated at E4 and at the E5 corrective pass. **Coverage** uses the TCP-TRC-4 values: `covered` (the named tests assert the whole expected result on product output), `partial` (part of it, or through injected state or white-box reads; the reason is in the Tests column), `gap`, `conflict`. **Result** uses the TCP-EVD-3 value `verified` with the platform and the transcript (`evidence/inc-11/e5c-*.txt`); no Windows result exists (operator rule: every run on the LAN Linux host 2). In the Tests column, `(full)` / `(partial: …)` says what one test asserts. Test names are E1 proposals in the three new files of `E1-slice.md` §5 — G1 = `tests/test_b101_a2l_blocks_and_segments.py`, G2 = `tests/test_b101_issues_severity_view.py`, G3 = `tests/test_b101_inc11_acceptance.py` — and are fixed at E4. E3 round 1 (`E3-rulings.md`) added 15 cases and the new row R-A2L-036.13. Class: *normal*, or *robustness* for an `If` row. Expected results are the requirement's exact values. Cases marked **[OR-2]** exist only if the orchestrator approves R-TUI-042b.5.
