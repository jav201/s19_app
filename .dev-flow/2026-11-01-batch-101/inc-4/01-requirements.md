## User stories

### US-SYM-1 — documents I open resolve their symbols through the A2L I loaded
As the operator, I want a change or check document that I load, paste, edit as JSON or pick as a check spec to resolve its A2L `symbol` entries against the A2L I have loaded, without the screen stalling on a large A2L, so that the case documents (`demo_patch.changes.json`, `demo_check.chk.json`, `demo_check_fails.chk.json`) work as delivered. (F-01; CODE-CHANGES D8-22.)

### US-SYM-2 — a variant run uses the project's A2L and nothing implicit
As the operator, I want Execute scope over a project's variants to resolve symbol entries against the project's A2L file, and against no other A2L, so that the same document gives the same result in the editor and in a variant run. (T-04, ruling `declarado`.)

### US-SYM-3 — the per-entry JSON edit works on a symbol entry and says plainly when it cannot
As the operator, I want to confirm a per-entry Edit JSON of a symbol entry with the A2L I have loaded, and, when no A2L is loaded, to be told so in words rather than by a finding code alone. (T-12, ruling `sesion`.)

## Definitions (CTX-CHGDOC additions, proposed for the canon)

- **Session read.** A read of a change or check document that the operator starts in the session. It has six alternatives: (1) a Patch Editor file load (the File dropdown pick, the typed-path Load, and the dirty-guard's accept branch, which all run the same load); (2) a Patch Editor paste (Parse paste); (3) a whole-document Edit JSON confirm (its validity pre-check and the paste it posts); (4) a per-entry Edit JSON confirm (R-TUI-058.2; the entry text read as R-CHG-001.44 says); (5) a Check Editor Spec dropdown pick; (6) an A2B Diff check-spec dropdown pick. The project-load reopen of the recorded document (S11 R-PROJ-DOC; `app.py:13893-13941`) and the flow PATCH and CHECK blocks (`flow_execution_service.py:522`, `:803`) are not session reads: they already declare the project's or the flow's A2L and do not change here.
- **Loaded A2L.** The A2L the session holds at the moment of the read (the one the A2L Explorer shows; none after an unload or a project close).
- **The project's A2L file.** The one A2L file the project folder holds (S11 CTX-PROJECT; R-VAR-002.27).
- **The R-CHG-SYM.2 finding.** The finding `CHG-SYMBOL-UNRESOLVED` with the message `entry <i>: the symbol <symbol> cannot be resolved — no A2L context is declared for this change-set — the entry was skipped`.
- **Case 08.** The release demo case generated by `tools/synth/make_release_case.py` (seed `20260001`, 1.0 MB): `firmware.s19`, `firmware.a2l`, `demo_patch.changes.json` (7 entries; entries 2 and 3 carry a `symbol`), `demo_check.chk.json` and `demo_check_fails.chk.json` (3 entries each; entry 2 carries a `symbol`). `<tag 2>`, `<tag 3>` and `<check tag>` are the generated tag names.
