## 1. BLUF

**Verdict: the operator's distrust is justified. A project is a folder of file copies plus a small `project.json`. It never stores session state, and Load project is not a clean restore.** Five HIGH findings:

1. **H-1: Save project saves the file on disk, not the image in memory.** A Patch Editor apply that has not been saved back is silently dropped. The status still reads `Project saved + manifest verified`, and the reloaded image is the original (`p01`).
2. **H-2: Loading a project over another one keeps the previous project's A2L, MAC and Patch Editor entries.** A later save then **writes them into the second project's folder** (`p03`).
3. **H-3: a save-back under the loaded image's own name deletes the image's work copy.** The next Save project raises an uncaught `FileNotFoundError` and **the app exits with code 1** (`p08`, `p02` A). Cause: the save-back staging path `temp/<name>`, the same root as integrity H-3.
4. **H-4: Load project can open the original after a patched image was saved into the project, and says nothing.** A save-back into a project becomes a new non-active variant (`firmware_1.s19`). `project.json` keeps the original active, so Load opens the unpatched image (`p02` A/B).
5. **H-5: Load project ignores every manifest problem.** A corrupt `project.json` loads silently. A corrupt or empty image loads as `Loaded project 'X' -> firmware.s19` with 0 bytes. An image edited on disk after the save is not detected, because no hash is stored (`p04` 2/6/7, `p05`).

**Verified clean:** project data files are full copies, so moving or deleting the original sources after a save does not affect Load (`p04` 1). Load project opens the files **in place** (`<workarea>/<P>/…`) and **does not copy into `temp`** (`p01`). Selecting a variant does not copy anything either (`p07`). A multi-variant project with S19 + HEX variants restores the selected `active_variant` and every variant byte-exact (`p07`). A2L-enriched tags (3) are restored. Flows saved in `<P>/flows/` are listed again after Load (`p06` B). A single-project S19 + MAC + A2L round-trip without a pending patch restores the same file, MAC and A2L (`p01`, the `file`/`mac`/`a2l` keys match apart from their folder).

**Not a regression, by design:** the code has no project-level session model. `project.json` holds only `schema_version`, `active_variant`, `batch`, `assignments`, and optionally `declared_regions` and `gathered` (`manifest_writer.py:336-364`). Everything else a session holds is either a file that happens to sit in the folder or is not kept at all (see §3).

## 3. Inventory: what a project stores vs what a session holds

A project is a **folder** `<parent>/<sanitised name>/`. The parent must lie inside a `.s19tool/workarea` (`copy_into_workarea` containment), and Load sees only `<base>/.s19tool/workarea/*`. The folder holds **byte copies** (`shutil.copy2`, `workspace.py:368`) of the loaded files and a `project.json` (`manifest_writer.py:336-364`) with **relative POSIX paths only**. It records no absolute path, no source path and no hash. Sub-folders are written by other features straight into the active project dir (`flows/`, `flowsets/`, `checks/`, `patches/`, `reports/`, `templates/`, `splits/`).

## 4. Answers to the brief's four questions

1. **Inventory:** see §3. Paths are relative and the files are copies. Session state that is **not** stored: the in-memory patched image, the paste-authored change doc, undo history, the editor's open document (only gathered, not reopened), the source paths, and all UI positions.
2. **Round-trip per artifact:** a clean S19/HEX/MAC/A2L project with no pending edits round-trips byte-exact, and so do multi-variant projects. Five scenarios break it: a pending patch (H-1), a save-back (H-3/H-4), loading over another project (H-2), "save as" (M-3) and A2L-only (M-6). A project saved twice unchanged does not grow. Re-loading same-name sources grows `_<N>` with duplicates (M-1). Moved or deleted **sources** are harmless, while moved, deleted or changed **project files** are reported weakly or not at all (H-5, L-4). Names: spaces and `..` are stripped silently, two names can merge (M-4), unicode works, and long names crash (M-7). Load project opens in place and does **not** copy into `temp`.
3. **Failure honesty:** mostly silent. Five cases report `ok` or say nothing: the lost patch (H-1), leaked A2L/MAC (H-2), the wrong variant (H-4), a corrupt manifest or image (H-5) and "save as" (M-3). One case crashes (H-3, M-7). The only loud case is a missing active variant (L-4), and its wording is misleading.
4. **A project path in Load file:** Load file does not accept projects. A folder gives `Unsupported file type: `, `project.json` gives `Unsupported file type: .json`, and a project's data file is loaded as a loose file into whatever project is open (L-2). Whether Load file *should* route projects is a P1 decision. These findings argue for one Load dialog that lists projects, work-area files and recent sources, which matches the backlog's Load-dialog entry (`BACKLOG-CODE.md:1429`).

## 5. Not checked / limits (stated plainly)

- **The live tree was not probed.** It has uncommitted `app.py` edits by another agent. A diff of `app.py` against HEAD shows no change to the save/load code paths, but that is a code read, not a run.
- **Keystrokes were not exercised.** Handlers were called directly, except `p08`, which uses the real `SaveProjectScreen` dismiss. The `LoadProjectScreen` ListView selection and the `Browse…` tkinter picker were not exercised.
- **Not probed individually:** chain sets, flowsets, check sets, reports, split outputs and templates in project sub-folders (code-read only), the `declared_regions` write → read round-trip, and the `batch`/`assignments` consumers.
- Concurrency was not probed: two app instances on one workarea, or a save while a load worker runs.
- Only Windows (NTFS) was tested. `CON` as a project name was accepted there (`p05`); its behaviour on other systems is unknown.
- The S0-at-`0x0` artefact (integrity H-1) affects every round-trip digest equally, so it cancels out in these comparisons. It was not re-measured here.
- This report does not say which of these the operator actually hit. The most likely candidates for "some artifacts do not load well" are H-2 (wrong A2L/MAC after switching projects), H-1/H-4 (patched work comes back unpatched) and H-3 (crash after a same-name save-back), but that is an inference.
