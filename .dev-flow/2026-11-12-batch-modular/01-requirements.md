## User story

**US-MOD-01 — "As the maintainer, I can have several workers change different domains of the
TUI app in parallel without edit conflicts, and the split itself changes no behaviour."**
`s19_app/tui/app.py` (23,488 lines; `S19TuiApp` 20,475 lines / 374 methods) and
`s19_app/tui/screens_directionb.py` (9,296 lines) become packages of domain modules.

## Definitions

- **Old module**: `s19_app/tui/app.py` or `s19_app/tui/screens_directionb.py` at base.
- **New package**: `s19_app/tui/app/` or `s19_app/tui/screens_directionb/` after the move.
- **Unit**: a top-level function, class, assignment or annotated assignment of an old module
  (an attribute docstring joins the statement before it), or a method or class-body statement of
  `S19TuiApp`. Counts at base: app 126 top units + 374 methods + 44 class-body statements;
  screens_directionb 82 top units (classes moved whole). Imports are not units.
- **Module map**: `design/module-map.json`, generated by `tools/modularize/plan_map.py`.
- **D1 list**: names a test rebinds on an old module object, generated by
  `tools/modularize/test_patch_census.py` into `design/test-patch-census.json`
  (app 37, screens_directionb 1; interfaces.md I-3).
- **Allowed rewrites**: the closed list interfaces.md I-6.
- **Normalised AST**: `ast.dump(include_attributes=False)` after undoing the allowed rewrites
  (spec-verify.md A.4).
- **Mixin**: a plain class `<Name>Mixin` holding moved `S19TuiApp` methods.
- **Core pins**: the members interfaces.md I-5 keeps in `S19TuiApp`'s own body.
- **Source-reading test**: a test that reads the text of an old module, of `S19TuiApp`, or of a
  unit of an old module (hazards.md H-12); **law**: a repository-wide test that censuses source
  or test files (hazards.md H-13).
- **Runner**: the Linux CI runner configuration of `tools/modularize/run_suite.sh` (same Python,
  same `-n` worker count, isolated HOME/XDG/TMP).

Out of scope: the ≤300-line module / ≤40-line function caps (later pass, per module, in
parallel — D2); any behaviour, copy, key or layout change; `REQUIREMENTS.md` product rows
(no product behaviour changes, so the canon fold is the R-MOD rows only).

## Rulings (RU)

- **RU-1 D1 list = 37 + 1, not 39 + 4.** The census text count mixed reads and noise; rebinding
  is what needs the seam. `CHECK_GLYPHS` is only read. (interfaces.md I-3.)
- **RU-2 18 mixins, not ~16.** Domain boundaries; merging two unrelated domains to hit the
  number would put two owners on one file. (interfaces.md I-1.)
- **RU-3 No Code-Wire graph.** No function contract changes; E2 pins the module structure
  instead (E2-module-graph.md).
- **RU-4 Core pins widened** beyond the brief's list (class attributes, BINDINGS, CSS,
  reactives, `compose`/`__init__`/`on_mount`): + zero-argument-`super()` methods, reactive
  watchers, and the two Textual handlers tests rebind on the class (hazards H-3, H-4).
- **RU-5 sdb `map_parts` module.** "One module per panel + shared" left `memory_map` at 2,595
  body lines; the map's sub-widgets and helpers form `map_parts` (1,241), the panel module
  keeps 1,857.
- **RU-6 Cap for this pass** = max(2,200 physical lines, largest whole class + 500): classes are
  not split in this batch, so `PatchEditorPanel` (2,610 lines) alone exceeds any flat cap.
- **RU-7 `deps` holds definitions**, not only re-exports: a package-defined D1 name whose
  body reads another D1 name (`recorded_document_state` reads `os`, `open`) must read the
  patched object; defining it in `deps` keeps those reads native and `deps` a leaf (no cycle).
- **RU-8 `CSS_PATH` rewrite** to `"../styles.tcss"` (Textual resolves it against the class's
  file; the class moves one directory down). Hazard H-6.
- **RU-9 Textual `App` overrides stay in core** (`copy_to_clipboard`, `action_help_quit`,
  `action_quit` added to the pins): the action-reach law gives the `toolkit` reason only on a
  class with a Textual base, and the copy/quit law looks up `S19TuiApp.action_help_quit`.
  Found by the source-reading inventory; hazards H-20.
- **RU-10 Docs paths.** The docs path law (`test_r_doc_ref_1_1_named_paths_exist`) makes
  README.md, PROJECT_RULES.md, CLAUDE.md and docs/architecture.md part of the slice: their
  lines naming the two old files are updated to the new paths (hazards H-12 row 44).
- **RU-11 Pre-existing vacuous test** `test_at_b94_08_variant_machinery_retired` reads
  `s19_app/__init__.py`; fixed as READ-PACKAGE in group 3 (hazards H-23).
