### Import-direction rule (both packages)

- A mixin / panel module imports only from `shared`, `shared_io`, `deps`, `map_parts`
  (sdb `memory_map` only) and modules outside the package. **Never from another mixin or
  panel module.** Methods of one mixin reach another mixin's methods through `self` only.
- `core` imports every mixin (for the class header) and the shared layers.
- `deps` imports only from `shared` and outside the package. `shared` imports nothing from
  the package. `shared_io` imports from `shared` and `deps`.
- `__init__` imports from every module; nothing in the package imports `__init__`
  (no `from . import X` where X is a re-exported name; `from . import deps` is the only
  package-level relative import and it names a submodule).
- The static graph is printed in `module-map.json` `graph` and drawn in `E2-module-graph.md`;
  it is acyclic (checked by `plan_map.py` and by the verifier on the written files).

Difference from the brief's "39 module-alias attrs + 4 string targets": the census in
`census-287b9dc3.json` counted every `alias.X` text match, reads included (`S19TuiApp`,
`SaveProjectPayload`, `MAX_SECTIONS_*` are only read) and regex noise (`py` from `"app.py"`,
`__file__`). The AST census counts rebinding only. Names only read need the re-export (I-2),
not the seam. `CHECK_GLYPHS` (24 sdb hits) is only read (`set(sdb.CHECK_GLYPHS)`), never
rebound — it is NOT in D1.

**`deps.py` contents** (per package):
1. `from __future__ import annotations`;
2. the old import statement of every *imported* D1 name (relative level +1), e.g. `import os`,
   `from datetime import datetime`, `from textual.widgets import Label, ListItem`;
3. imports of what the deps-defined units need from `shared` (`from .shared import …`);
4. the *deps-defined* units, verbatim, in source order: the package-defined D1 names plus every
   top-level def they reference that itself loads a D1 name (app: `_is_link_stat`, which
   `recorded_document_state` calls and which reads `os`). App: `parse_a2l_cached`,
   `_SAVE_FULL_PATH_LIMIT`, `_image_map`, `_file_digest`, `_plan_without_document_key`,
   `_is_link_stat`, `recorded_document_state`. Sdb: `_json_clock`.
5. Nothing binds `open` in `deps`: the only `open(...)` calls of the old module are inside
   `_file_digest` and `recorded_document_state`, which live in `deps`, so a test that sets
   `deps.open` shadows the builtin there exactly as it shadowed it in the old module.

**The rewrite rule (the only body change the mover makes for D1):** in every new module
except `deps.py`, each `ast.Name` node with `id ∈ D1` of its package, `ctx = Load`, that
`symtable` resolves to the module-global scope (not local, parameter, free, nonlocal), and
that is not inside an annotation (argument / return / `AnnAssign.annotation`), becomes
`deps.<id>`. The module gets `from . import deps`. Annotation uses (app: `os` 2, `ListItem` 4)
stay bare and the module imports the name from its original statement. Inside `deps.py`
nothing is rewritten. No other name is ever rewritten to `deps.X`; a non-D1 name homed in
`deps` (`_is_link_stat`) is imported by name.

Counts the verifier checks (base global Loads, annotations excluded) are computed by it from
the base, not typed here.

**Tests:** the retargeter (`design/spec-retarget-tests.md`) rewrites each D1 patch target from
the package root to `.deps`, and every test read `alias.X` with `X ∈ D1` to `alias.deps.X`.
Patches on `S19TuiApp` (37 class-patched names in the census) need no change (I-5).

## I-4 Mixin order and MRO

`class S19TuiApp(ComposeScreensMixin, FlowMixin, SaveCommitMixin, ReportsMixin, PatchMixin,
ChecksDiffMixin, SavePlanMixin, ProjectLoadMixin, FileLoadMixin, LoadedStateMixin,
WorkspaceViewMixin, ProjectsMixin, NavigationMixin, A2lViewMixin, MacViewMixin,
IssuesChecksMixin, HexViewMixin, ShellMixin, App):` (`module-map.json` `app.class_header`).

- Mixins are plain classes (`class XMixin:` — no base, no metaclass, no `__slots__`, no
  docstring, no class attributes).
- `S19TuiApp.__mro__` = `(S19TuiApp, <18 mixins in header order>, App, <App's MRO>)`.
- No attribute name is defined in two of `{S19TuiApp} ∪ mixins` (the old class defined each
  name once; the `_variant_set` property getter+setter is one name and moves as one group,
  getter first). Hence every lookup resolves to the same function as before and zero-argument
  `super()` (kept in core anyway, H-4) reaches the same next class.
- Textual sees through the mixins: bindings, reactives, CSS bases and handler dispatch are
  collected from `cls.__mro__` / `cls.__dict__` per class; mixins are not `DOMNode` and add no
  CSS type name (H-1..H-3).

## I-6 Allowed rewrites (closed list)

1. D1 `Name` → `deps.Name` (I-3).
2. Relative `ImportFrom` level + 1 wherever it occurs (module top or inside a function),
   because every moved line now sits one package deeper (`.x` → `..x`, `..x` → `...x`).
3. `CSS_PATH = "styles.tcss"` → `CSS_PATH = "../styles.tcss"` (one statement, core; H-6).
4. Class headers: `class S19TuiApp(App):` → the I-4 header; methods move under
   `class <Name>Mixin:` at the same indentation.
5. Added lines: module docstrings (one generated line; sdb `__init__` keeps the old docstring),
   `from __future__ import annotations`, generated import statements, `if TYPE_CHECKING:`
   blocks copied from the old module (sdb `LoadedFile`), `from . import deps`.

Anything else is a difference and fails the verifier.

## I-7 Import-cycle rule

- Mixins never name `S19TuiApp` (none does at base; checked by AST). If a moved method needs
  it as a type hint, the mixin imports it under `if TYPE_CHECKING:` only; a runtime reference
  in a mixin is a mover error.
- The deps-defined closure (I-3 item 4) keeps `deps` a leaf above `shared`.
- Each new module must import first in a fresh interpreter (`python -I -c "import <module>"`,
  one process per module) — this catches order-dependent partial-initialisation errors that a
  single `import s19_app.tui.app` hides.
